Send files to the API and save them to a folder or to the database.

## Introduction

When we need to send files to REST API services, we have several ways
to implement this in Netuno.

Usually, files are sent in the HTTP request body structured in
multipart format; this is the most common procedure in the frontend, for example when we fill out a
form and there is a field to choose a file.

Alternatively, we can send the file bytes encoded in Base64 as a value
in a JSON object, when we want a 100% JSON REST API.

## Files

Through `_req.file`, we can pass the field name and thus get the file object
that was sent; see how:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.file("file");
            `
        },
    ]}
/>

That is, `_req` has all the data received in the HTTP request body.

And through the `file` method, it allows obtaining the object representing the file that was
sent.

The obtained value may be `null` if there is no file.

## Base64 in JSON

To upload a file in the JSON sent to the service, we can define a property with the value:

`data:image/png;base64,...`

Where `...` is the sequence of file bytes encoded in Base64.

The file type follows `data`, for example:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Object

If the file is in an internal JSON structure inside the subobject:

```json
{
  "person": {
    "file": "data:image/png;base64,..."
  }
}
```

It can be obtained as follows:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.getValues("person").getFile("avatar");
            `
        },
    ]}
/>

### Array

If the file is in an internal JSON structure inside the array:

```json
{
  "files": [
    "data:image/png;base64,..."
  ]
}
```

It can be obtained as follows:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.getValues("files").getFile(0);
            `
        },
    ]}
/>

## OpenAPI

Netuno supports integration with OpenAPI and uses the OpenAPI definition to validate the HTTP request.

> More about [OpenAPI in Netuno](/docs/academy/server/services/openapi).

With the `file` type, Netuno validates whether the value starts with the file format in JSON, for example:

- `data:image/png;base64,...`

To validate that a file is being received in a JSON object property:

```json title="post.in.json"
{
  "summary": "File Upload",
  "description": "Service that receives a file in the JSON object.",
  "type": "object",
  "properties": {
    "file": {
      "type": "file"
    }
  },
  "required": [
    "file"
  ]
}
```

To validate that a list of files is being received in a JSON array:

```json title="post.in.json"
{
  "summary": "File Uploads",
  "description": "Service that receives a list of files in a JSON array.",
  "properties": {
    "files": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "files"
  ]
}
```

## Saving the File

Usually, when we receive a file in the service, we need to save it, for example:

- **Database**: File related to a record, such as a user.
- **Storage**: Internal application folder used to manage files in general.
- **Folder**: Place the file in any folder on the system.

### Database

In form field management, Netuno supports the `image` and `file` types, as follows:

- **Image**: Image files in general, JPG and PNG.
- **File**: Any type of file.

Imagine that there is an Image field in the Product form; we can save the file sent via upload as
follows:

#### Example using DB Form:

Note the use of `_db.form`:

#### Downloading the File from the Database

To display the stored file, we must create a service that provides the file bytes.

For files saved in the database, as in the example above, the file itself is placed in the application
storage, and only the final file name is stored in the database.

> The application storage is a folder intended to store and organize generic file structures.

Therefore, in the example above, the database files of the `Product` form and the `Image` field are
stored in:

- `storage/database/product/image/*`

> Netuno automatically manages the stored file name to avoid duplicate file names.

To get the file, a service can be created that displays the product image file, for example:

### Storage

We can save a file directly in the application `storage`.

To avoid mixing with database files, we should use the `filesystem` folder, which is
intended to store generic files that are not associated with the database.

To receive the file, this example demonstrates how a file sent in the
`POST` service is stored directly in storage:

<PolyglotCode
    file="services/file/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const file = _req.getFile("file");
                _storage.filesystem("server", "upload").ensurePath();
                file.save(_storage.filesystem("server", "upload", file.name()));
            `
        },
    ]}
/>

The file is stored in the application `storage` folder, in:

- `storage/filesystem/server/upload/*`

> The [Storage](/docs/library/resources/storage) resource is used to get the folder and file path:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // Name of the subfolder in the filesystem.
                    "upload", // Name or path of the internal subfolder.
                    file.name() // Final file name.
                );
            `
        },
    ]}
/>

> See more in the [Storage](/docs/library/resources/storage) documentation.

To download the file, this example demonstrates how the file bytes
can be obtained through the `GET` service:

<PolyglotCode
    file="services/file/get"
    codes={[

            code: `

### Folder

We can save a file directly in any folder on the computer.

There are two resources that are very useful in these cases:

- `_app` - We can get any folder or file in the application.
- `_os` - We can get any folder or file on the computer.

> See the documentation for the respective resources [App](/docs/library/resources/app) and [OS](/docs/library/resources/os);
> both resources have the `folder` and `file` methods, which allow indicating the folder or file path,
> respectively.

`POST` service is stored directly in a folder in the application:

## Conclusion

As can be seen, we can integrate file uploads into REST API services, including integration with
OpenAPI.

We can save the file in the database, inside the application `storage` folder, or in any folder on the
computer.

See the documentation for the resources used in this tutorial that allow manipulating files:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

In the database, we can save images in fields of type `image`, and we can save any type of file in
fields of type `file`; how we save or get files is the same in any case, whether image or
generic file.
