Bestanden naar de API sturen en in een map of in de database opslaan.

## Inleiding

Wanneer we bestanden naar de services van de REST API moeten sturen, hebben we in Netuno verschillende manieren om dit te ontwikkelen.

Meestal worden bestanden in de body van het HTTP-verzoek verzonden, gestructureerd in multipart-formaat; dit is de meest voorkomende procedure in de frontend, bijvoorbeeld wanneer we een formulier invullen met een veld om een bestand te kiezen.

Als alternatief kunnen we de bytes van de bestanden als Base64-gecodeerde waarde in een JSON-object sturen, wanneer we een 100% JSON REST API willen.

## Bestanden

Via `_req.file` kunnen we de veldnaam doorgeven en zo het object van het verzonden bestand verkrijgen, zie hoe:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const mijnBestand = _req.file("bestand");
            `
        },
    ]}
/>

Met andere woorden, `_req` bevat alle gegevens die we in de body van het HTTP-verzoek ontvangen.

En via de methode `file` kunnen we het object verkrijgen dat het verzonden bestand vertegenwoordigt.

De verkregen waarde kan `null` zijn als er geen bestand is.

## Base64 in JSON

Om een bestand te uploaden in de JSON die naar de service wordt gestuurd, kunnen we een eigenschap met de volgende waarde definiëren:

`data:image/png;base64,...`

Waarbij in `...` de reeks bytes van het bestand volgt, gecodeerd in Base64.

Het bestandstype komt na `data`, bijvoorbeeld:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Object

Als het bestand zich in een interne JSON-structuur binnen het subobject bevindt:

```json
{
  "persoon": {
    "bestand": "data:image/png;base64,..."
  }
}
```

## OpenAPI

Netuno ondersteunt integratie met OpenAPI en gebruikt de OpenAPI-definitie om het HTTP-verzoek te valideren.

> Meer over [OpenAPI in Netuno](/docs/academy/server/services/openapi).

Met het type `file` valideert Netuno of de waarde begint met het bestandsformaat in de JSON, bijvoorbeeld:

- `data:image/png;base64,...`

Om te valideren of een bestand in een eigenschap van het JSON-object wordt ontvangen:

```json title="post.in.json"
{
  "summary": "Bestand uploaden",
  "description": "Service die een bestand in het JSON-object ontvangt.",
  "type": "object",
  "properties": {
    "bestand": {
      "type": "file"
    }
  },
  "required": [
    "bestand"
  ]
}
```

Om te valideren of een lijst met bestanden in een array in de JSON wordt ontvangen:

```json title="post.in.json"
{
  "summary": "Bestanden uploaden",
  "description": "Service die een lijst met bestanden in een array in de JSON ontvangt.",
  "properties": {
    "bestanden": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "bestanden"
  ]
}
```

## Het bestand opslaan

Meestal moeten we een bestand dat we in de service ontvangen opslaan, bijvoorbeeld:

- **Database**: Een bestand dat aan een record is gekoppeld, bijvoorbeeld van een gebruiker.
- **Storage**: Interne map van de applicatie die dient om bestanden in het algemeen te beheren.
- **Map**: Het bestand in een willekeurige map van het systeem plaatsen.

### Database

Bij het beheren van formuliervelden ondersteunt Netuno de typen `image` en `file`, namelijk:

- **Image**: Afbeeldingsbestanden in het algemeen, JPG en PNG.
- **File**: Elk type bestand.

#### Bestand downloaden uit de database

Om het opgeslagen bestand te tonen, moeten we een service maken die de bytes van het bestand levert.

Bij bestanden die in de database worden opgeslagen, zoals in het bovenstaande voorbeeld, wordt het bestand zelf in de storage van de applicatie geplaatst en wordt in de database alleen de uiteindelijke bestandsnaam opgeslagen.

> De storage van de applicatie is een map die bedoeld is om generieke bestandsstructuren op te slaan en te organiseren.

Daarom worden in het bovenstaande voorbeeld de databasebestanden van het formulier `Product` en het veld `Afbeelding` opgeslagen in:

- `storage/database/product/afbeelding/*`

> Netuno beheert automatisch de naam van het opgeslagen bestand om dubbele bestandsnamen te voorkomen.

Om het bestand te verkrijgen, kan een service worden gemaakt die het afbeeldingsbestand van het product toont, bijvoorbeeld:

                "afbeelding",

            )

                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storageProductAfbeeldingBestand.inputStream())

    },

### Storage

We kunnen een bestand direct in de `storage` van de applicatie opslaan.

Om ze niet te mengen met databasebestanden, moeten we de map `filesystem` gebruiken, die bedoeld is om generieke bestanden op te slaan die niet aan de database zijn gekoppeld.

Om het bestand te ontvangen, wordt in dit voorbeeld getoond hoe een bestand dat via de `POST`-service wordt verzonden, direct in de storage wordt opgeslagen:

<PolyglotCode
    file="services/bestand/post"
    codes={[
        {
            lang: 'javascript',
            code: `

                bestand.save(_storage.filesystem("server", "upload", bestand.name()));
            `
        },
    ]}
/>

Het bestand wordt opgeslagen in de `storage`-map van de applicatie, in:

- `storage/filesystem/server/upload/*`

> De functie [Storage](/docs/library/resources/storage) wordt gebruikt om het pad van de map en het bestand te verkrijgen:

<PolyglotCode

### Map

We kunnen een bestand direct in een willekeurige map van de computer opslaan.

Er zijn twee functies die in deze gevallen erg nuttig zijn:

- `_app` - We kunnen elke map of elk bestand in de applicatie pakken.
- `_os` - We kunnen elke map of elk bestand op de computer pakken.

> Zie de documentatie van de respectieve functies [App](/docs/library/resources/app) en [OS](/docs/library/resources/os); beide functies hebben de methoden `folder` en `file`, waarmee het pad van respectievelijk de map of het bestand kan worden aangegeven.

Om het bestand te ontvangen, wordt in dit voorbeeld getoond hoe een bestand dat via de `POST`-service wordt verzonden, direct in een map in de applicatie wordt opgeslagen:

## Conclusie

Zoals te zien is, kunnen we het uploaden van bestanden integreren in de services van de REST API, inclusief integratie met OpenAPI.

We kunnen het bestand in de database opslaan, in de `storage`-map van de applicatie of in een willekeurige map op de computer.

Zie de documentatie van de functies die in deze tutorial worden gebruikt en waarmee bestanden kunnen worden beheerd:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

In de database kunnen we afbeeldingen opslaan in velden van het type `image`, en we kunnen elk type bestand opslaan in velden van het type `file`; hoe we bestanden opslaan of verkrijgen is in beide gevallen hetzelfde, of het nu om een afbeelding of een generiek bestand gaat.
