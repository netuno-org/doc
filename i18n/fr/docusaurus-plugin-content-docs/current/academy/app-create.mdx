Ce guide offre un aperçu de la configuration initiale, en abordant le frontend, la base de données et le service API.
Nous allons créer une nouvelle application fullstack de manière rapide et pratique.

## Introduction

Bien que la plateforme soit polyglotte et prenne en charge plusieurs langages de programmation, nous nous concentrerons exclusivement sur l'utilisation de JavaScript dans ce tutoriel. En conséquence, nous créerons une application pratique composée d'un formulaire affiché dans une fenêtre modale (pop-up) avec la fonctionnalité d'exportation de données vers PDF.

#### Prérequis

Avant de commencer, assurez-vous de disposer de :

- La plateforme Netuno préalablement installée sur votre machine. En cas de doute sur cette étape, consultez le guide [Installation de la plateforme](/docs/get-started/installation).

- Un accès au terminal ou à l'invite de commande de l'environnement de développement.

## Créer une nouvelle application

Suivez les instructions ci-dessous pour initialiser votre nouvelle application :

Ouvrez le terminal et naviguez jusqu'au dossier racine où Netuno a été installé.

Exécutez la commande de création de l'application :

```shell
./netuno app
```

### Création avec paramètre

Il est possible de définir le nom de l'application directement lors de l'exécution de la commande, par exemple :

```shell
./netuno app name=mon_application
```

:::info Bonnes pratiques de nommage
Lors de la définition du nom de votre application, évitez d'utiliser des espaces, des accents ou des caractères spéciaux. Préférez l'utilisation de lettres minuscules séparées par des tirets ou des underscores (exemple : **app-ventes** ou **gestion_rh**) pour maintenir la compatibilité avec les URL et les dossiers du système.
:::

## Configuration initiale

L'assistant en ligne de commande posera quelques questions pour configurer votre projet. Indiquez :

- **Nom de l'application** : L'identifiant de votre projet.
- **Type de base de données** : Le système de gestion de base de données qui sera utilisé.
- **Langue** : La langue par défaut de l'interface de votre application.

:::tip Conseils et bonnes pratiques

**Recommandation de base de données pour les débutants**

Pendant le pas-à-pas, lorsqu'il vous sera demandé le type de base de données, nous recommandons de choisir l'option **H2 Database**.

H2 Database est une base de données embarquée déjà intégrée au serveur Netuno. Le grand avantage est qu'elle ne nécessite ni installation ni configuration de serveurs externes (comme PostgreSQL ou MySQL), ce qui rend les développements initiaux et les tests beaucoup plus pratiques et rapides.
:::

### Commande pour démarrer le serveur

Après avoir créé votre nouvelle application, démarrez le serveur de la plateforme Netuno. Cela rendra votre projet accessible dans le navigateur et prêt pour le développement continu.

Exécutez la commande ci-dessous dans votre terminal et attendez l'initialisation.

```shell
./netuno server app=mon_application
```

En passant le paramètre **app=mon_application**, le serveur comprend que ce sera l'application par défaut à exécuter dans cette instance. Une fois le serveur en cours d'exécution, vous pouvez déjà commencer à modifier votre projet.

Tous les fichiers et codes source de votre application sont stockés et organisés dans le dossier `📂 apps/monapp`.

:::info Identifiants d'accès (Backoffice)
Lors de la première connexion à l'interface d'administration **Backoffice** de votre application, le système demandera une authentification. Pour les environnements de développement locaux, utilisez les identifiants par défaut suivants :

**Utilisateur :** dev

**Mot de passe :** dev

*Nous recommandons de modifier ces identifiants lorsque vous déplacez votre application vers un environnement de production.*
:::

### Résumé des étapes

Avec les connaissances initiales de Netuno consolidées, nous appliquerons ces concepts en pratique en créant une fonctionnalité complète, du début à la fin.

L'objectif pratique est d'ajouter deux nouveaux composants interactifs dans l'interface :

* Un bouton chargé de charger et d'afficher le formulaire de clients dans une fenêtre flottante (Modale).
* Un bouton dédié à la génération et à l'exportation de la liste des clients enregistrés dans un fichier PDF.

Pour atteindre ce résultat avec organisation et clarté, nous divisons le développement en une séquence logique d'étapes. Nous suivrons ce plan :

- **Cartographie de l'interface** : Analyser la structure des dossiers de l'application pour localiser où le HTML principal du tableau de bord est défini.

- **Intégration avec React** : Configurer et ajouter la base des deux nouveaux boutons en utilisant le framework React dans le frontend.

- **Logique de la modale** : Construire et programmer le comportement du bouton pour ouvrir correctement le formulaire de clients.

- **Interface d'exportation** : Construire et positionner le bouton qui déclenchera le téléchargement du fichier PDF dans l'interface.

- **Développement du service (API)** : Programmer le backend en créant le service qui effectuera la lecture des données et la génération dynamique du fichier PDF contenant la liste des clients.

Commençons !

## Ajouter des boutons avec React

Dans cette étape, nous allons configurer le fichier principal du panneau **tableau de bord** pour afficher deux nouveaux boutons.

Dans l'architecture d'interface, nous utilisons le concept de **Containers** pour définir des zones étendues du système, qui englobent des fonctionnalités plus importantes et regroupent plusieurs composants plus petits.

- Dans votre éditeur de code, naviguez jusqu'au dossier des containers dans `📂 ui/src/containers`.

- Localisez et ouvrez le fichier principal du tableau de bord : `📂 DashboardContainer/index.jsx`.

- Insérez le code d'importation et de rendu des composants comme dans l'exemple ci-dessous.

```javascript title="ui/src/containers/DashboardContainer/index.jsx"
import { Space } from 'antd';

import BoutonClientModal from '../../components/BoutonClientModal';
import BoutonPDF from '../../components/BoutonPDF';

import "./index.less";

function DashboardContainer() {
    return (
        <div className="mon-tableau-de-bord">
            <Space>
                <BoutonClientModal />
                <BoutonPDF />
            </Space>
        </div>
    );
}

export default DashboardContainer;
```

Notez que ces fichiers de boutons n'existent pas encore physiquement dans votre projet. Comme il s'agit de composants plus petits et réutilisables, nous les créerons dans le dossier des composants dédiés.

:::tip Organisation de l'architecture
Maintenez toujours la séparation entre **Containers** (zones de portée étendue, comme des pages entières ou des tableaux de bord) et **Components** (éléments d'interface isolés, comme des boutons et des modales). Cela rend votre code dans Netuno beaucoup plus propre, facile à maintenir et évolutif.
:::

### Bouton pour formulaire

Accédez au dossier `ui/src/components/` et créez un nouveau dossier appelé `BoutonClientModal`.

Dans le dossier **BoutonClientModal**, créez le fichier principal du composant nommé `index.jsx`.

`📂 ui/src/components/BoutonClientModal/index.jsx`

Ouvrez le fichier et insérez le code ci-dessous :

```javascript title="ui/src/components/BoutonClientModal/index.jsx"
import { Button } from 'antd';

function BoutonClientModal() {
    const onClick = () => {
        netuno.modal.create({
            name: 'client',
            callback: function (modal) {
                let form = modal.find('[netuno-form]');

                form.on('netuno:new', () => {
                    console.log("Création d'un nouveau client.");
                });

                form.on('netuno:save', () => {
                    netuno.modal.hide(modal)
                    console.log("Sauvegarde d'un client.");
                });

                form.on('netuno:delete', () => {
                    netuno.modal.hide(modal)
                    console.log("Suppression d'un client");
                });

                form.on('netuno:back', () => {
                    console.log("Clic sur retour");
                });

                netuno.loadForm(form);
                netuno.modal.show(modal);
            }
        });
    };
    return (
        <div>
            <Button type="primary" onClick={ onClick }>
                Ouvrir le formulaire client
            </Button>
        </div>
    );
}

export default BoutonClientModal;
```

#### Comprendre le code
La magie de ce composant se produit à l'intérieur de la fonction onClick, qui utilise les outils globaux d'interface de Netuno :

- **netuno.modal.create()** : Cette méthode est responsable de l'instanciation de la fenêtre modale à l'écran et de la liaison du formulaire souhaité à celle-ci (dans ce cas, le formulaire appelé client).

- **Événements de formulaire (form.on)** : Le bloc callback nous permet d'« écouter » (listen) les actions de l'utilisateur. Nous pouvons déclencher des actions personnalisées lorsque l'utilisateur crée un enregistrement (netuno:new), enregistre (netuno:save), supprime (netuno:delete) ou clique sur retour (netuno:back).

- **netuno.modal.hide() / show()** : Méthodes utilisées pour masquer la modale après une action réussie ou l'afficher dès que le formulaire est chargé.

:::info Intégration terminée
Maintenant que le composant **BoutonClientModal** a été créé avec succès, l'importation que nous avons faite précédemment dans votre **DashboardContainer** fonctionnera sans erreur, et le bouton devrait déjà être rendu à l'écran !
:::

Dans cette étape, nous créerons le deuxième bouton du tableau de bord : le bouton pour exporter en PDF.

La fonction principale de ce composant dans l'interface est d'agir comme un déclencheur, c'est-à-dire qu'au clic, il effectuera une requête vers un service backend, responsable du traitement des données du système et de la génération du fichier PDF contenant la liste des clients enregistrés.

## Compiler le frontend

Les navigateurs web ne comprennent pas nativement les codes écrits en React, les fichiers `.jsx` ou `.tsx` et les préprocesseurs CSS comme `.less`. Pour que votre interface fonctionne correctement, il est nécessaire de passer par un processus de compilation (build). Ce processus traduit, empaquette et optimise tout votre code en fichiers statiques finaux (JavaScript et CSS standard) que le navigateur peut traiter avec une efficacité maximale.

#### Prérequis

Avant de commencer la compilation, assurez-vous que :

- Vous avez le terminal ou l'invite de commande ouvert dans votre environnement de développement.

- Le gestionnaire de paquets `Bun` est correctement installé sur votre système.

## Exemples de compilation

Netuno met à disposition différentes commandes selon l'étape de votre développement. À partir du dossier racine de Netuno, naviguez jusqu'au dossier `ui` de votre application.

Exécutez les commandes dans le dossier de l'interface de votre application : `📂 apps/monapp/ui`

### Compilation de production

Effectue la compilation complète et optimisée des fichiers. C'est la commande idéale lorsque vous terminez le développement d'un écran ou d'un composant et souhaitez générer les fichiers finaux légers et avec de meilleures performances.

```bash
bun run build
```

### Compilation de développement

La commande **watch** effectue une compilation rapide et surveille le dossier. Chaque fois que vous enregistrez un fichier dans votre éditeur, le terminal exécute automatiquement la compilation.

```bash
bun run watch
```
Indépendamment de la commande utilisée **build** ou **watch**, les modifications n'apparaissent pas instantanément à l'écran de l'utilisateur. Actualisez la page du backoffice dans votre navigateur pour charger les nouveaux fichiers générés.

:::tip Surveillance des erreurs et débogage
Pendant le développement, des erreurs peuvent survenir à deux étapes différentes. Sachez où les chercher :

- **Erreurs de compilation** : Les erreurs de syntaxe dans le code React ou les variables non déclarées seront présentées directement dans votre terminal, où la commande **bun** est en cours d'exécution.

- **Erreurs d'exécution** : Les erreurs qui se produisent pendant l'utilisation de l'application seront présentées dans la console du navigateur. Rappelez-vous toujours d'inspecter la page pour vérifier s'il y a une alerte ou une erreur.
:::

### Compilation intégrée

La fonctionnalité de compilation intégrée permet d'exécuter automatiquement des commandes de terminal en même temps que l'initialisation du serveur. Cela optimise le flux de travail en consolidant tous les logs et surveillances dans un seul terminal central.

Pour activer la compilation intégrée, il est nécessaire de modifier les configurations de développement de votre application :

- Accédez au dossier racine de votre application.

- Ouvrez le fichier de configuration de développement : `_development.json`.

- Localisez le bloc de code relatif à « **commands** ».

- Modifiez la valeur de la propriété « enabled » de **false** à **true**.

- Enregistrez le fichier.

Votre fichier `_development.json` devra avoir une structure similaire à celle-ci :

```json title="config/_development.json"
  ...
  "commands": [{
    "command": "bun run watch",
    "enabled": true,
    "install": "bun install",
    "path": "ui"
  }],
  ...
```

Pour que Netuno lise le fichier mis à jour et applique la nouvelle configuration, il est nécessaire de redémarrer le serveur :

- Allez jusqu'au terminal où le serveur Netuno est en cours d'exécution.

- Arrêtez le processus en appuyant simultanément sur les touches CTRL + C.

- Redémarrez le serveur en indiquant le nom de votre application :

```shell
./netuno server app=monapp
```

:::tip Terminal unique
Après avoir redémarré le serveur, observez les logs dans le terminal. Vous remarquerez que Netuno exécute maintenant automatiquement les commandes de compilation du frontend **bun run watch** en arrière-plan. Désormais, tout fonctionne intégré dans la même fenêtre.
:::

## Service API pour générer un PDF

Dans l'étape précédente, nous avons configuré le bouton **Exporter en PDF** dans le frontend avec l'attribut « **href** » pointant vers l'adresse `services/client/exporte-pdf`. Cependant, si vous cliquez dessus maintenant, rien ne se passera. Cela se produit parce que le service API responsable de la génération du fichier n'existe pas encore.

Tout le développement de l'API se déroule dans le dossier `📂 server`.
Dans cette section, nous créerons le script qui récupère les enregistrements dans la base de données et construit visuellement le document PDF.

- Avoir créé le composant BoutonPDF dans le frontend pointant vers l'URL correcte.
- Avoir le serveur Netuno en cours d'exécution.

- **_header.contentType("pdf")** : Informe au navigateur que la réponse de cette requête n'est pas un texte ou du JSON ordinaire, mais un fichier PDF.

- **_pdf** : C'est la ressource native de Netuno pour la manipulation de PDF. Avec elle, nous définissons la taille de la page (A5), créons des paragraphes, ajustons les tailles de police (setFontSize) et les couleurs (setFontColor).

- **_db.form("client").all()** : Interroge la base de données et retourne tous les enregistrements enregistrés dans le formulaire « client ». La boucle de répétition (for) parcourt chacun de ces clients et extrait l'information du champ « nom » pour l'imprimer dans le document.

- **pdfDocument.close()** : Finalise la construction du document et l'envoie comme réponse.

#### Validation et tests

Il n'est pas nécessaire de cliquer sur le bouton du tableau de bord chaque fois que vous souhaitez tester votre service. Comme il s'agit d'une requête simple (GET), vous pourrez valider l'exécution en accédant directement à l'URL de l'API depuis le navigateur.

Pour cet exemple, accédez à l'adresse suivante :
http://localhost:9000/services/client/exporte-pdf

Si le fichier PDF est généré et affiché à l'écran contenant la liste des clients, le service fonctionne parfaitement ! Par conséquent, le bouton Exporter en PDF dans votre tableau de bord fonctionnera automatiquement.

:::tip Traçage des erreurs dans le backend
Si la page reste blanche ou renvoie un message d'erreur lors de l'accès à l'URL, vérifiez immédiatement le terminal où le serveur Netuno est en cours d'exécution. Contrairement au frontend, dont les erreurs apparaissent dans la console du navigateur, toute erreur d'exécution dans les scripts du dossier server sera affichée en détail dans le terminal du serveur backend.
:::
