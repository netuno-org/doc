## Introduction

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a> est une base de données NoSQL orientée documents. Au lieu de tables et de lignes, les données sont stockées dans des documents au format similaire à JSON, ce qui permet une grande flexibilité dans le modèle de données.

Netuno offre la ressource [_mongo](/docs/library/resources/mongo) pour l'intégration avec MongoDB, avec une abstraction low-code sur le client officiel MongoDB pour Java, disponible pour les différents langages de programmation supportés par Netuno : **JavaScript, Python, Ruby, Kotlin et Groovy**.

> Avant de continuer, il est recommandé de savoir comment créer des services dans Netuno, consultez le tutoriel [REST - Services Web](/docs/academy/server/services/rest).

Un exemple d'implémentation des opérations présentées ici est disponible dans le service d'exemple `mongo.js` qui se trouve à :

## Installation de MongoDB

### Avec Docker

En supposant que vous avez Docker installé, il suffit de télécharger l'image MongoDB et de démarrer un nouveau conteneur :

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

Ainsi, MongoDB est accessible à l'adresse `localhost:27017` sans authentification.

Pour créer l'utilisateur de la base de données conformément à la configuration de l'application, exécutez :

```shell
docker exec -it mongo mongosh produits_db --eval 'db.createUser({ user: "utilisateur_produits", pwd: "12345678", roles: [{ role: "readWrite", db: "produits_db" }] })'
```

### Avec Ubuntu

MongoDB n'est pas inclus dans les dépôts officiels d'Ubuntu, il est donc nécessaire d'ajouter le dépôt officiel avant l'installation :

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

Après l'installation, vous pouvez démarrer le service avec :

```shell
sudo systemctl start mongod
```

### Avec Windows

- <a href="https://www.mongodb.com/try/download/community" target="_blank">Télécharger MongoDB Community Server</a>.

Exécutez l'installateur téléchargé et, à l'étape **Service Configuration**, activez **Install MongoD as a Service** pour que MongoDB démarre automatiquement. MongoDB est accessible à l'adresse `localhost:27017` sans authentification.

> Consultez la [documentation officielle de MongoDB](https://www.mongodb.com/docs/manual/installation/) pour d'autres distributions et versions.

## Configuration de l'application

La configuration des connexions MongoDB se fait dans le fichier de configuration de l'application, selon l'environnement :

- `config/_development.json`

> Voir plus sur les [fichiers de configuration](/docs/academy/explore/configuration) de l'application.

Dans le fichier de configuration, ajoutez le bloc `mongo`, où chaque clé identifie une connexion :

```javascript
{
    ...
    "mongo": {
        "magasin": "mongodb://utilisateur_magasin:12345678@localhost/magasin_db",
        "produits": {
            "username": "utilisateur_produits",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "produits_db"
        }
    },
    ...
}
```

Une connexion peut être définie de deux manières :

- **Comme URL de connexion** — la valeur est simplement une chaîne, par exemple `"mongodb://utilisateur_magasin:12345678@localhost/magasin_db"`.
- **Comme objet de configuration** — avec les champs :
  - `url` — s'il est défini, il est utilisé directement comme URL de connexion, en ignorant les autres champs.
  - `protocol` — le protocole de la connexion, par défaut `mongodb`.
  - `username` et `password` — les identifiants d'accès.
  - `host` — l'adresse du serveur, par défaut `localhost`.
  - `port` — le port de la connexion, par défaut `27017`.
  - `database` — le nom de la base de données, par défaut le nom de la clé de connexion.
  - `params` — paramètres supplémentaires de la connexion ajoutés à l'URL, par exemple `{ "authSource": "admin" }`. Ils ne sont appliqués que lorsque l'URL est construite à partir des champs de l'objet.

> La connexion ne doit pas être la base de données principale de l'application. Contrairement à la configuration `db`, le bloc `mongo` est indépendant et permet plusieurs connexions simultanées.

### Filtres

La factory `_mongo.filters()` propose les principaux opérateurs de requête de MongoDB :

| Opérateur | Description |
|---|---|
| `eq("champ", valeur)` | Égal à la valeur. |
| `ne("champ", valeur)` | Différent de la valeur. |
| `gt("champ", valeur)` | Supérieur à la valeur. |
| `gte("champ", valeur)` | Supérieur ou égal à la valeur. |
| `lt("champ", valeur)` | Inférieur à la valeur. |
| `lte("champ", valeur)` | Inférieur ou égal à la valeur. |
| `in("champ", valeur1, valeur2, ...)` | Égal à l'une des valeurs. |
| `nin("champ", valeur1, valeur2, ...)` | Différent de toutes les valeurs. |
| `and(filtre1, filtre2, ...)` | Correspond à tous les filtres. |
| `or(filtre1, filtre2, ...)` | Correspond à au moins un des filtres. |
| `not(filtre)` | Ne correspond pas au filtre. |
| `regex("champ", "motif")` | Correspond à l'expression régulière. |
| `exists("champ")` | Le champ existe dans le document. |
| `text("recherche")` | Recherche textuelle. |
| `type("champ", "type")` | Le champ est du type spécifié. |
| `mod("champ", diviseur, reste)` | Le reste de la division du champ par le diviseur est égal à la valeur. |
| `where("expression")` | Correspond aux documents qui satisfont une expression JavaScript, par exemple `"this.prix > 100"`. |
| `size("champ", n)` | Le champ de tableau a exactement `n` éléments. |

Les étapes d'agrégation disponibles sont les suivantes :

| Étape | Description |
|---|---|
| `match(filtre)` | Sélectionne uniquement les documents qui correspondent au filtre. |
| `group("$champ", accumulateurs)` | Regroupe les documents par le champ et applique les accumulateurs. |
| `project(projection)` | Ajoute, supprime ou modifie des champs dans les documents. |
| `sort(tri)` | Trie les documents. |
| `limit(n)` | Limite aux `n` premiers documents. |
| `skip(n)` | Saute les `n` premiers documents. |
| `count()` | Compte le nombre de documents. |
| `lookup("collection", "champLocal", "champEtranger", "comme")` | Exécute une jointure avec une autre collection. |

Et les accumulateurs les plus utilisés :

| Accumulateur | Description |
|---|---|
| `sum("champ", "$expression")` | Somme des valeurs. |
| `avg("champ", "$expression")` | Moyenne des valeurs. |
| `min("champ", "$expression")` | Valeur minimale. |
| `max("champ", "$expression")` | Valeur maximale. |
| `first("champ", "$expression")` | Valeur du premier document. |
| `last("champ", "$expression")` | Valeur du dernier document. |
| `top("champ", tri, "$expression")` | Valeur du haut selon le tri. |
| `bottom("champ", tri, "$expression")` | Valeur du bas selon le tri. |

> Dans les accumulateurs, l'expression préfixée par `$` fait référence au champ d'un document d'entrée, par exemple `"$prix"`.

## Conclusion

Avec la ressource `_mongo`, Netuno offre une abstraction low-code et polyglotte sur le client officiel MongoDB pour Java, permettant de travailler avec des documents, filtres, tris, projections, mises à jour, index et agrégations en JavaScript, Python, Ruby, Kotlin et Groovy.

Pour plus de détails sur toutes les méthodes disponibles, consultez la documentation de la ressource [_mongo](/docs/library/resources/mongo) et de la classe [MongoCollection](/docs/library/objects/MongoCollection).
