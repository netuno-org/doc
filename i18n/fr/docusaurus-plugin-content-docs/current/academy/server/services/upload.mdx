Envoyer des fichiers à l'API et les enregistrer dans un dossier ou dans la base de données.

## Introduction

Lorsque nous devons envoyer des fichiers aux services de l'API REST, nous avons plusieurs façons
de réaliser ce développement dans Netuno.

Normalement, les fichiers sont envoyés dans le corps de la requête HTTP structurés au format
multipart, c'est la procédure la plus courante dans le frontend, par exemple lorsque nous remplissons un
formulaire et qu'il y a ce champ pour choisir un fichier.

Alternativement, nous pouvons envoyer les octets des fichiers encodés en Base64 comme valeur
dans un objet JSON, lorsque nous voulons une API REST 100% JSON.

## Fichiers

Grâce à `_req.file`, nous pouvons passer le nom du champ et ainsi obtenir l'objet du fichier
qui a été envoyé, voyez comment :

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const monFichier = _req.file("fichier");
            `
        },
    ]}
/>

C'est-à-dire que `_req` contient toutes les données que nous recevons dans le corps de la requête HTTP.

Et grâce à la méthode `file`, il permet d'obtenir l'objet qui représente le fichier qui a été
envoyé.

La valeur obtenue peut être `null` s'il n'y a aucun fichier.

## Comment faire un Base64 dans le JSON

Pour effectuer l'upload d'un fichier dans le JSON envoyé au service, nous pouvons définir une propriété avec la valeur :

`data:image/png;base64,...`

Où dans les `...` suit la séquence des octets du fichier encodés en Base64.

Le type du fichier va après le `data`, par exemple :

- PNG : `image/png`.
- JPG : `image/jpeg`
- TXT : `text/plain`
- PDF : `application/pdf`
- XLSX : `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Objet

Si le fichier se trouve dans une structure interne du JSON à l'intérieur du sous-objet :

```json
{
  "personne": {
    "fichier": "data:image/png;base64,..."
  }
}
```

Il peut être obtenu de la manière suivante :

<PolyglotCode
    codes={[

### Tableau

Si le fichier se trouve dans une structure interne du JSON à l'intérieur du tableau :

  "fichiers": [
    "data:image/png;base64,..."

## OpenAPI

Netuno prend en charge l'intégration avec OpenAPI et utilise la définition de l'OpenAPI pour valider la requête HTTP.

> Plus d'informations sur [OpenAPI dans Netuno](/docs/academy/server/services/openapi).

Avec le type `file`, Netuno valide si la valeur commence par le format de fichier dans le JSON, par exemple :

- `data:image/png;base64,...`

Pour valider si un fichier est reçu dans une propriété de l'objet JSON :

```json title="post.in.json"
{
  "summary": "Upload de fichier",
  "description": "Service qui reçoit un fichier dans l'objet JSON.",
  "type": "object",
  "properties": {
    "fichier": {
      "type": "file"
    }
  },
  "required": [
    "fichier"
  ]
}
```

Pour valider si une liste de fichiers est reçue dans un tableau JSON :

```json title="post.in.json"
{
  "summary": "Upload de fichiers",
  "description": "Service qui reçoit une liste de fichiers dans un tableau JSON.",
  "properties": {
    "fichiers": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "fichiers"
  ]
}
```

## Enregistrer le fichier

Normalement, lorsque nous recevons un fichier dans le service, nous devons l'enregistrer, par exemple :

- **Base de données** : Fichier lié à un enregistrement, comme celui d'un utilisateur.
- **Storage** : Dossier interne de l'application qui sert à gérer des fichiers en général.
- **Dossier** : Placer le fichier dans un dossier quelconque du système.

### Base de données

Dans la gestion des champs des formulaires, Netuno prend en charge le type `image` et `file`, à savoir :

- **Image** : Fichiers d'image en général, JPG et PNG.
- **File** : Tout type de fichier.

Imaginez que vous avez un champ Image dans le formulaire Produit, nous pouvons enregistrer le fichier envoyé via upload de

#### Téléchargement du fichier depuis la base de données

Pour présenter le fichier stocké, nous devons créer un service qui fournit les octets du fichier.

Étant donné que les fichiers enregistrés dans la base de données, comme dans l'exemple ci-dessus, le fichier lui-même est placé dans le storage de
l'application et dans la base de données seul le nom final du fichier est stocké.

> Le storage de l'application est un dossier destiné à stocker et organiser des structures de fichiers génériques.

Donc, dans l'exemple ci-dessus, les fichiers de base de données du formulaire `Produit` et du champ `Image` sont
stockés dans :

- `storage/database/produit/image/*`

> Netuno gère automatiquement le nom du fichier stocké pour éviter les doublons de noms de fichiers.

Pour obtenir le fichier, un service peut être créé qui présente le fichier image du produit, par exemple :

            # db_produit = _db.get("produit", produit_uid)

            if db_produit.nil?
                _header.status(404)
                _out.json(
                    _val.map()
                        .set("result", false)
                        .set("error", "produit-non-trouve")
                )
                _exec.stop()
            end

            db_produit_image_nom = db_produit.getString("image")

            storage_produit_image_fichier = _storage.database(
                "produit",
                "image",
                db_produit_image_nom
            )

            if storage_produit_image_fichier.extension() == "jpg" || storage_produit_image_fichier.extension() == "jpeg"
                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storage_produit_image_fichier.inputStream())
        `
    },
]}
/>

Remarquez que la ressource `_storage` ([Storage](/docs/library/resources/storage)) est utilisée pour obtenir le fichier :

Dans la base de données, seul le nom du fichier est stocké, et grâce à `_storage.database`, nous pouvons

### Storage

Nous pouvons enregistrer un fichier directement dans le `storage` de l'application.

Pour ne pas mélanger avec les fichiers de base de données, nous devons utiliser le dossier `filesystem`, qui a
pour finalité de stocker des fichiers génériques qui ne sont pas associés dans la base de données.

Pour recevoir le fichier, dans cet exemple il est démontré comment un fichier envoyé dans le service
 `POST` est stocké directement dans le storage :

<PolyglotCode

        {
            lang: 'javascript',
            code: `

        },
    ]}
/>

Le fichier est stocké dans le dossier `storage` de l'application, dans :

### Dossier

Nous pouvons enregistrer un fichier directement dans n'importe quel dossier de l'ordinateur.

- `_app` - Nous pouvons récupérer n'importe quel dossier ou fichier dans l'application.

## Conclusion

Comme on peut le voir, nous pouvons intégrer l'upload de fichiers dans les services de l'API REST, y compris intégré avec
OpenAPI.

Nous pouvons enregistrer le fichier dans la base de données, dans le dossier `storage` de l'application ou dans n'importe quel dossier de
l'ordinateur.

Voir la documentation des ressources utilisées dans ce tutoriel qui permettent de manipuler les fichiers :

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

En base de données, nous pouvons enregistrer des images dans des champs de type `image`, et nous pouvons enregistrer tout type de fichier dans
des champs de type `file`, comment nous enregistrons ou obtenons des fichiers est de la même manière dans tous les cas, qu'il s'agisse d'une image ou d'un
fichier générique.
