## Introduzione

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a> è un database NoSQL orientato ai documenti. Invece di tabelle e righe, i dati vengono memorizzati in documenti in un formato simile a JSON, il che consente una grande flessibilità nel modello dei dati.

Netuno offre la risorsa [_mongo](/docs/library/resources/mongo) per l'integrazione con MongoDB, con un'astrazione low-code sul client ufficiale MongoDB per Java, disponibile per i vari linguaggi di programmazione supportati da Netuno: **JavaScript, Python, Ruby, Kotlin e Groovy**.

> Prima di procedere, si consiglia di sapere come creare servizi in Netuno; vedi il tutorial [REST - Servizi Web](/docs/academy/server/services/rest).

Un esempio di implementazione delle operazioni presentate qui è disponibile nel servizio di esempio `mongo.js` che si trova in:

## Installazione di MongoDB

### Con Docker

Presupponendo che Docker sia installato, è sufficiente scaricare l'immagine di MongoDB e avviare un nuovo container:

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

In questo modo MongoDB è accessibile su `localhost:27017` senza autenticazione.

Per creare l'utente del database in base alla configurazione dell'applicazione, esegui:

```shell
docker exec -it mongo mongosh prodotti_db --eval 'db.createUser({ user: "prodotti_user", pwd: "12345678", roles: [{ role: "readWrite", db: "prodotti_db" }] })'
```

### Con Ubuntu

MongoDB non è incluso nei repository ufficiali di Ubuntu, quindi è necessario aggiungere il repository ufficiale prima dell'installazione:

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

Dopo l'installazione, puoi avviare il servizio con:

```shell
sudo systemctl start mongod
```

### Con Windows

- <a href="https://www.mongodb.com/try/download/community" target="_blank">Scarica MongoDB Community Server</a>.

Esegui l'installer scaricato e, nel passaggio **Service Configuration**, attiva **Install MongoD as a Service** affinché MongoDB si avvii automaticamente. MongoDB è accessibile su `localhost:27017` senza autenticazione.

> Consulta la [documentazione ufficiale di MongoDB](https://www.mongodb.com/docs/manual/installation/) per altre distribuzioni e versioni.

## Configurazione dell'applicazione

La configurazione delle connessioni MongoDB avviene nel file di configurazione dell'applicazione, in base all'ambiente:

- `config/_development.json`

> Vedi di più sui [file di configurazione](/docs/academy/explore/configuration) dell'applicazione.

All'interno del file di configurazione, aggiungi il blocco `mongo`, dove ogni chiave identifica una connessione:

```javascript
{
    ...
    "mongo": {
        "negozio": "mongodb://negozio_user:12345678@localhost/negozio_db",
        "prodotti": {
            "username": "prodotti_user",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "prodotti_db"
        }
    },
    ...
}
```

Una connessione può essere definita in due modi:

- **Come URL di connessione** — il valore è semplicemente una stringa, ad esempio `"mongodb://negozio_user:12345678@localhost/negozio_db"`.
- **Come oggetto di configurazione** — con i campi:
  - `url` — se definito, viene utilizzato direttamente come URL di connessione, ignorando gli altri campi.
  - `protocol` — il protocollo della connessione, per default `mongodb`.
  - `username` e `password` — le credenziali di accesso.
  - `host` — l'indirizzo del server, per default `localhost`.
  - `port` — la porta della connessione, per default `27017`.
  - `database` — il nome del database, per default il nome della chiave di connessione.
  - `params` — parametri aggiuntivi della connessione aggiunti all'URL, ad esempio `{ "authSource": "admin" }`. Vengono applicati solo quando l'URL viene costruita a partire dai campi dell'oggetto.

> La connessione non deve essere il database principale dell'applicazione. A differenza della configurazione `db`, il blocco `mongo` è indipendente e consente più connessioni contemporaneamente.

### Filtri

La factory `_mongo.filters()` offre i principali operatori di query di MongoDB:

| Operatore | Descrizione |
|---|---|
| `eq("campo", valore)` | Uguale al valore. |
| `ne("campo", valore)` | Diverso dal valore. |
| `gt("campo", valore)` | Maggiore del valore. |
| `gte("campo", valore)` | Maggiore o uguale al valore. |
| `lt("campo", valore)` | Minore del valore. |
| `lte("campo", valore)` | Minore o uguale al valore. |
| `in("campo", valore1, valore2, ...)` | Uguale a uno qualsiasi dei valori. |
| `nin("campo", valore1, valore2, ...)` | Diverso da tutti i valori. |
| `and(filtro1, filtro2, ...)` | Corrisponde a tutti i filtri. |
| `or(filtro1, filtro2, ...)` | Corrisponde ad almeno uno dei filtri. |
| `not(filtro)` | Non corrisponde al filtro. |
| `regex("campo", "pattern")` | Corrisponde all'espressione regolare. |
| `exists("campo")` | Il campo esiste nel documento. |
| `text("ricerca")` | Ricerca testuale. |
| `type("campo", "tipo")` | Il campo è del tipo specificato. |
| `mod("campo", divisore, resto)` | Il resto della divisione del campo per il divisore è uguale al valore. |
| `where("espressione")` | Corrisponde ai documenti che soddisfano un'espressione JavaScript, ad esempio `"this.prezzo > 100"`. |
| `size("campo", n)` | Il campo array ha esattamente `n` elementi. |

Le fasi di aggregazione disponibili sono le seguenti:

| Fase | Descrizione |
|---|---|
| `match(filtro)` | Seleziona solo i documenti che corrispondono al filtro. |
| `group("$campo", accumulatori)` | Raggruppa i documenti per il campo e applica gli accumulatori. |
| `project(proiezione)` | Aggiunge, rimuove o modifica campi nei documenti. |
| `sort(ordinamento)` | Ordina i documenti. |
| `limit(n)` | Limita ai primi `n` documenti. |
| `skip(n)` | Salta i primi `n` documenti. |
| `count()` | Conta il numero di documenti. |
| `lookup("collezione", "campoLocale", "campoEstero", "come")` | Esegue un join con un'altra collezione. |

E gli accumulatori più utilizzati:

| Accumulatore | Descrizione |
|---|---|
| `sum("campo", "$espressione")` | Somma dei valori. |
| `avg("campo", "$espressione")` | Media dei valori. |
| `min("campo", "$espressione")` | Valore minimo. |
| `max("campo", "$espressione")` | Valore massimo. |
| `first("campo", "$espressione")` | Valore del primo documento. |
| `last("campo", "$espressione")` | Valore dell'ultimo documento. |
| `top("campo", ordinamento, "$espressione")` | Valore più alto secondo l'ordinamento. |
| `bottom("campo", ordinamento, "$espressione")` | Valore più basso secondo l'ordinamento. |

> Negli accumulatori, l'espressione con prefisso `$` si riferisce al campo di un documento di input, ad esempio `"$prezzo"`.

## Operazioni con opzioni

Le factory `*Options()` della risorsa `_mongo` restituiscono gli oggetti di opzioni predefiniti del driver MongoDB, e puoi concatenare i loro metodi direttamente. Ad esempio, `upsert(true)` inserisce il documento quando il filtro non corrisponde a nessun documento esistente:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const precedente = collezione.findOneAndUpdate(
                    _mongo.filters().eq("nome", "Monitor"),
                    _mongo.updates().set("quantità", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'python',
            code: `
                precedente = collezione.findOneAndUpdate(

                    _mongo.updates().set("quantità", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'ruby',
            code: `

                    _mongo.filters().eq("nome", "Monitor"),

Quando il documento viene inserito, `findOneAndUpdate()` restituisce `null`.

Le factory di opzioni disponibili sono: `insertOneOptions()`, `insertManyOptions()`, `updateOptions()`, `findOneAndUpdateOptions()`, `replaceOptions()`, `findOneAndReplaceOptions()`, `deleteOptions()`, `findOneAndDeleteOptions()`, `countOptions()`, `estimatedDocumentCountOptions()`, `dropCollectionOptions()` e `textSearchOptions()`.

## Conclusione

Con la risorsa `_mongo`, Netuno offre un'astrazione low-code e poliglotta sul client ufficiale MongoDB per Java, consentendo di lavorare con documenti, filtri, ordinamenti, proiezioni, aggiornamenti, indici e aggregazioni in JavaScript, Python, Ruby, Kotlin e Groovy.

Per maggiori dettagli su tutti i metodi disponibili, consulta la documentazione della risorsa [_mongo](/docs/library/resources/mongo) e della classe [MongoCollection](/docs/library/objects/MongoCollection).
