Inviare file all'API e salvarli in una cartella o nel database.

## Introduzione

Quando dobbiamo inviare file ai servizi dell'API REST, abbiamo diversi modi
per realizzare questo sviluppo in Netuno.

Normalmente i file vengono inviati nel corpo della richiesta HTTP strutturati nel formato
multipart; è la procedura più comune nel frontend, ad esempio quando compiliamo un
modulo e c'è quel campo per scegliere un file.

In alternativa possiamo inviare i byte dei file codificati in Base64 come valore
in un oggetto JSON, quando vogliamo un'API REST 100% JSON.

## File

Attraverso `_req.file` possiamo passare il nome del campo e così ottenere l'oggetto del file
che è stato inviato, vedi come:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const mioFile = _req.file("file");
            `
        },
    ]}
/>

Ovvero, `_req` contiene tutti i dati che riceviamo nel corpo della richiesta HTTP.

E tramite il metodo `file` permette di ottenere l'oggetto che rappresenta il file che è stato
inviato.

Il valore ottenuto potrà essere `null` se non c'è nessun file.

## Come Base64 nel JSON

Per eseguire l'upload di un file nel JSON inviato al servizio, possiamo definire una proprietà con il valore:

`data:image/png;base64,...`

Dove nei `...` segue la sequenza dei byte del file codificati in Base64.

Il tipo del file segue `data`, ad esempio:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Oggetto

Se il file si trova in una struttura interna del JSON dentro il sottooggetto:

```json
{
  "persona": {
    "file": "data:image/png;base64,..."
  }
}
```

Può essere ottenuto nel modo seguente:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const mioFile = _req.getValues("persona").getFile("avatar");
            `
        },
    ]}
/>

### Array

Se il file si trova in una struttura interna del JSON dentro l'array:

```json
{
  "file": [
    "data:image/png;base64,..."
  ]
}
```

Può essere ottenuto nel modo seguente:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const mioFile = _req.getValues("file").getFile(0);
            `
        },
    ]}
/>

## OpenAPI

Netuno supporta l'integrazione con OpenAPI e utilizza la definizione OpenAPI per validare la richiesta HTTP.

> Maggiori informazioni su [OpenAPI in Netuno](/docs/academy/server/services/openapi).

Con il tipo `file`, Netuno valida se il valore inizia con il formato file nel JSON, ad esempio:

- `data:image/png;base64,...`

Per validare se si sta ricevendo un file in una proprietà dell'oggetto JSON:

```json title="post.in.json"
{
  "summary": "Upload di File",
  "description": "Servizio che riceve un file nell'oggetto JSON.",
  "type": "object",
  "properties": {
    "file": {
      "type": "file"
    }
  },
  "required": [
    "file"
  ]
}
```

Per validare se si sta ricevendo una lista di file in array nel JSON:

```json title="post.in.json"
{
  "summary": "Upload di File",
  "description": "Servizio che riceve una lista di file in array nel JSON.",
  "properties": {
    "file": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "file"
  ]
}
```

## Salvare il File

Normalmente quando riceviamo un file nel servizio dobbiamo salvarlo, come ad esempio:

- **Database**: File relativo a un record, come quello di un utente.
- **Storage**: Cartella interna dell'applicazione che serve per gestire file in generale.
- **Cartella**: Inserire il file in una cartella qualsiasi del sistema.

### Base di Dati

Nella gestione dei campi dei moduli, Netuno supporta il tipo `image` e `file`, ovvero:

- **Image**: File di immagine in generale, JPG e PNG.
- **File**: Qualsiasi tipo di file.

Immagina di avere un campo Immagine nel modulo Prodotto; possiamo salvare il file inviato via upload nel
modo seguente:

#### Download del File dalla Base di Dati

Per presentare il file memorizzato dobbiamo creare un servizio che fornisce i byte del file.

Nei file salvati nel database, come nell'esempio sopra, il file stesso viene inserito nello storage
dell'applicazione e nel database viene memorizzato solo il nome finale del file.

> Lo storage dell'applicazione è una cartella destinata a memorizzare e organizzare strutture di file generici.

Pertanto, nell'esempio sopra i file del database del modulo `Prodotto` e del campo `Immagine` vengono
memorizzati in:

- `storage/database/prodotto/immagine/*`

> Netuno gestisce automaticamente il nome del file memorizzato per evitare nomi di file ripetuti.

Per ottenere il file, può essere creato un servizio che presenta il file immagine del prodotto, ad esempio:

            # dbProdotto = _db.get("prodotto", prodottoUid)

            if dbProdotto.nil?
                _header.status(404)
                _out.json(
                    _val.map()
                        .set("risultato", false)
                        .set("errore", "prodotto-non-trovato")
                )
                _exec.stop()
            end

            dbProdottoImmagineNome = dbProdotto.getString("immagine")

            storageProdottoImmagineFile = _storage.database(
                "prodotto",
                "immagine",
                dbProdottoImmagineNome
            )

            if storageProdottoImmagineFile.extension() == "jpg" || storageProdottoImmagineFile.extension() == "jpeg"
                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storageProdottoImmagineFile.inputStream())
        `
    },
]}
/>

Nota che la risorsa `_storage` ([Storage](/docs/library/resources/storage)) viene utilizzata per ottenere il file:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.database(
                    "prodotto", // Nome del modulo/tabella.
                    "immagine", // Nome del campo/colonna.
                    dbProdottoImmagineNome // Nome del file.
                );
            `
        },
    ]}
/>

Nel database viene memorizzato solo il nome del file, mentre tramite `_storage.database` possiamo
ottenere il file stesso.

### Storage

Possiamo salvare un file direttamente nello `storage` dell'applicazione.

Per non mescolare con i file del database, dobbiamo utilizzare la cartella `filesystem`, che ha lo
scopo di memorizzare file generici non associati al database.

Per ricevere il file, in questo esempio viene mostrato come un file inviato nel servizio
 `POST` viene memorizzato direttamente nello storage:

<PolyglotCode
    file="services/file/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const file = _req.getFile("file");
                _storage.filesystem("server", "upload").ensurePath();
                file.save(_storage.filesystem("server", "upload", file.name()));
            `
        },
    ]}
/>

Il file viene memorizzato nella cartella `storage` dell'applicazione, in:

- `storage/filesystem/server/upload/*`

> La risorsa [Storage](/docs/library/resources/storage) viene utilizzata per ottenere il percorso della cartella e del file:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // Nome della sottocartella nel filesystem.
                    "upload", // Nome o percorso della sottocartella interna.
                    file.name() // Nome finale del file.
                );
            `
        },
    ]}
/>

> Vedi maggiori informazioni nella documentazione di [Storage](/docs/library/resources/storage).

### Cartella

Possiamo salvare un file direttamente in qualsiasi cartella del computer.

Ci sono due risorse molto utili in questi casi:

- `_app` - Possiamo prendere qualsiasi cartella o file nell'applicazione.
- `_os` - Possiamo prendere qualsiasi cartella o file nel computer.

> Vedi la documentazione delle rispettive risorse [App](/docs/library/resources/app) e [OS](/docs/library/resources/os);
> entrambe le risorse hanno i metodi `folder` e `file`, che permettono di indicare rispettivamente il percorso della cartella o del file.

Per ricevere il file, in questo esempio viene mostrato come un file inviato nel servizio
`POST` viene memorizzato direttamente in una cartella nell'applicazione:

## Conclusione

Come si può vedere, possiamo integrare l'upload di file nei servizi dell'API REST, anche integrato con
OpenAPI.

Possiamo salvare il file nel database, nella cartella `storage` dell'applicazione o in qualsiasi cartella del
computer.

Vedi la documentazione delle risorse utilizzate in questo tutorial che permettono di manipolare i file:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

Nel database possiamo salvare immagini in campi di tipo `image` e possiamo salvare qualsiasi tipo di file in
campi di tipo `file`; il modo in cui salviamo o otteniamo i file è lo stesso in ogni caso, sia che si tratti
di un'immagine sia di un file generico.
