Dieser Leitfaden bietet einen Überblick über die Erstkonfiguration und behandelt Frontend, Datenbank und API-Dienst.
Wir erstellen schnell und praxisnah eine neue Fullstack-Anwendung.

## Einführung

Obwohl die Plattform polyglot ist und mehrere Programmiersprachen unterstützt, konzentrieren wir uns in diesem Tutorial ausschließlich auf die Verwendung von JavaScript. Daher erstellen wir eine praktische Anwendung, die aus einem in einem modalen Fenster (Pop-up) angezeigten Formular mit der Funktion zum Export von Daten nach PDF besteht.

#### Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Die Netuno-Plattform ist bereits auf Ihrem Rechner installiert. Bei Fragen zu diesem Schritt lesen Sie den Leitfaden [Installation der Plattform](/docs/get-started/installation).

- Zugriff auf das Terminal oder die Eingabeaufforderung der Entwicklungsumgebung.

## Eine neue Anwendung erstellen

Befolgen Sie die folgenden Anweisungen, um Ihre neue Anwendung zu initialisieren:

Öffnen Sie das Terminal und navigieren Sie zum Stammordner, in dem Netuno installiert wurde.

Führen Sie den Befehl zum Erstellen der Anwendung aus:

```shell
./netuno app
```

### Erstellung mit Parameter

Sie können den Namen der Anwendung direkt bei der Ausführung des Befehls festlegen, zum Beispiel:

```shell
./netuno app name=meine_anwendung
```

:::info Best Practices für die Benennung
Vermeiden Sie bei der Definition des Namens Ihrer Anwendung Leerzeichen, Akzente oder Sonderzeichen. Bevorzugen Sie Kleinbuchstaben, getrennt durch Bindestriche oder Unterstriche (Beispiel: **app-verkauf** oder **personal_verwaltung**), um die Kompatibilität mit URLs und Systemordnern zu gewährleisten.
:::

## Erstkonfiguration

Der Befehlszeilenassistent stellt einige Fragen zur Konfiguration Ihres Projekts. Geben Sie an:

- **Name der Anwendung**: Die Kennung Ihres Projekts.
- **Datenbanktyp**: Das Datenbankverwaltungssystem, das verwendet wird.
- **Sprache**: Die Standardsprache der Oberfläche Ihrer Anwendung.

:::tip Tipps und Best Practices

**Empfehlung für Datenbanken für Einsteiger**

Während des Assistenten wird nach dem Datenbanktyp gefragt; wir empfehlen die Option **H2 Database**.

H2 Database ist eine eingebettete Datenbank, die bereits in den Netuno-Server integriert ist. Der große Vorteil ist, dass keine Installation oder Konfiguration externer Server (wie PostgreSQL oder MySQL) erforderlich ist, was die ersten Entwicklungen und Tests deutlich praktischer und schneller macht.
:::

### Befehl zum Starten des Servers

Nachdem Sie Ihre neue Anwendung erstellt haben, starten Sie den Server der Netuno-Plattform. Dadurch wird Ihr Projekt im Browser erreichbar und für die kontinuierliche Entwicklung bereit.

Führen Sie den folgenden Befehl in Ihrem Terminal aus und warten Sie auf die Initialisierung.

```shell
./netuno server app=meine_anwendung
```

Durch Übergabe des Parameters **app=meine_anwendung** erkennt der Server, dass dies die Standardanwendung ist, die in dieser Instanz ausgeführt wird. Sobald der Server läuft, können Sie bereits mit der Bearbeitung Ihres Projekts beginnen.

Alle Dateien und Quellcodes Ihrer Anwendung werden im Ordner `📂 apps/meineapp` gespeichert und organisiert.

:::info Zugangsdaten (Backoffice)
Wenn Sie zum ersten Mal auf die Verwaltungsoberfläche **Backoffice** Ihrer Anwendung zugreifen, fordert das System eine Authentifizierung an. Verwenden Sie für lokale Entwicklungsumgebungen die folgenden Standard-Zugangsdaten:

**Benutzer:** dev

**Passwort:** dev

*Wir empfehlen, diese Zugangsdaten zu ändern, bevor Sie Ihre Anwendung in eine Produktionsumgebung verschieben.*
:::

### Zusammenfassung der Schritte

Mit den gefestigten Grundkenntnissen von Netuno wenden wir diese Konzepte in der Praxis an und erstellen eine vollständige Funktionalität von Anfang bis Ende.

Das praktische Ziel ist es, zwei neue interaktive Komponenten zur Oberfläche hinzuzufügen:

* Ein Button, der das Kundenformular in einem schwebenden Fenster (Modal) lädt und anzeigt.
* Ein Button, der die Liste der registrierten Kunden generiert und als PDF-Datei exportiert.

Um dieses Ergebnis organisiert und klar zu erreichen, haben wir die Entwicklung in eine logische Abfolge von Schritten unterteilt. Wir folgen diesem Fahrplan:

- **Oberflächenzuordnung**: Analysieren der Ordnerstruktur der Anwendung, um zu ermitteln, wo das Haupt-HTML des Dashboards definiert ist.

- **React-Integration**: Konfigurieren und Hinzufügen der Basis der beiden neuen Buttons mit dem React-Framework im Frontend.

- **Modal-Logik**: Erstellen und Programmieren des Verhaltens des Buttons, damit das Kundenformular korrekt geöffnet wird.

- **Export-Oberfläche**: Erstellen und Positionieren des Buttons, der den Download der PDF-Datei in der Oberfläche auslöst.

- **Entwicklung des Dienstes (API)**: Programmieren des Backends und Erstellen des Dienstes, der die Daten liest und die PDF-Datei mit der Kundenliste dynamisch generiert.

Legen wir los!

## Buttons mit React hinzufügen

In diesem Schritt konfigurieren wir die Hauptdatei des **Dashboard**-Panels, um zwei neue Buttons anzuzeigen.

In der Oberflächenarchitektur verwenden wir das Konzept der **Container**, um übergreifende Bereiche des Systems zu definieren, die größere Funktionalitäten umfassen und mehrere kleinere Komponenten gruppieren.

- Navigieren Sie in Ihrem Code-Editor zum Container-Ordner unter `📂 ui/src/containers`.

- Suchen Sie die Hauptdatei des Dashboards und öffnen Sie sie: `📂 DashboardContainer/index.jsx`.

- Fügen Sie den Code zum Importieren und Rendern der Komponenten gemäß dem folgenden Beispiel ein.

```javascript title="ui/src/containers/DashboardContainer/index.jsx"
import { Space } from 'antd';

import KundeModalButton from '../../components/KundeModalButton';
import PDFButton from '../../components/PDFButton';

import "./index.less";

function DashboardContainer() {
    return (
        <div className="mein-dashboard">
            <Space>
                <KundeModalButton />
                <PDFButton />
            </Space>
        </div>
    );
}

export default DashboardContainer;
```

Beachten Sie, dass diese Button-Dateien in Ihrem Projekt noch nicht physisch existieren. Da es sich um kleinere und wiederverwendbare Komponenten handelt, erstellen wir sie im Ordner für dedizierte Komponenten.

:::tip Architekturorganisation
Achten Sie stets auf die Trennung zwischen **Containern** (Bereiche mit großem Umfang, wie ganze Seiten oder Dashboards) und **Komponenten** (isolierte Oberflächenelemente wie Buttons und Modals). Dadurch wird Ihr Code in Netuno deutlich sauberer, wartbarer und skalierbarer.
:::

### Button für Formular

Rufen Sie den Ordner `ui/src/components/` auf und erstellen Sie einen neuen Ordner namens `KundeModalButton`.

Erstellen Sie im Ordner **KundeModalButton** die Hauptdatei der Komponente mit dem Namen `index.jsx`.

`📂 ui/src/components/KundeModalButton/index.jsx`

Öffnen Sie die Datei und fügen Sie den folgenden Code ein:

```javascript title="ui/src/components/KundeModalButton/index.jsx"
import { Button } from 'antd';

function KundeModalButton() {
    const onClick = () => {
        netuno.modal.create({
            name: 'kunde',
            callback: function (modal) {
                let form = modal.find('[netuno-form]');

                form.on('netuno:new', () => {
                    console.log('Ein neuer Kunde wird erstellt.');
                });

                form.on('netuno:save', () => {
                    netuno.modal.hide(modal)
                    console.log('Ein Kunde wurde gespeichert.');
                });

                form.on('netuno:delete', () => {
                    netuno.modal.hide(modal)
                    console.log('Ein Kunde wurde entfernt.');
                });

                form.on('netuno:back', () => {
                    console.log('Auf Zurück geklickt');
                });

                netuno.loadForm(form);
                netuno.modal.show(modal);
            }
        });
    };
    return (
        <div>
            <Button type="primary" onClick={ onClick }>
                Kundenformular öffnen
            </Button>
        </div>
    );
}

export default KundeModalButton;
```

#### Den Code verstehen
Die Magie dieser Komponente geschieht innerhalb der Funktion onClick, die die globalen Oberflächenwerkzeuge von Netuno verwendet:

- **netuno.modal.create()**: Diese Methode instanziiert das modale Fenster auf dem Bildschirm und verknüpft das gewünschte Formular damit (in diesem Fall das Formular namens kunde).

- **Formularereignisse (form.on)**: Der callback-Block ermöglicht es uns, die Aktionen des Benutzers zu „lauschen“ (listen). Wir können benutzerdefinierte Aktionen auslösen, wenn der Benutzer einen Datensatz erstellt (netuno:new), speichert (netuno:save), löscht (netuno:delete) oder auf Zurück klickt (netuno:back).

- **netuno.modal.hide() / show()**: Methoden zum Ausblenden des Modals nach einer erfolgreichen Aktion oder zum Anzeigen, sobald das Formular geladen wurde.

:::info Integration abgeschlossen
Nachdem die Komponente **KundeModalButton** erfolgreich erstellt wurde, funktioniert der zuvor in Ihrem **DashboardContainer** vorgenommene Import ohne Fehler, und der Button sollte bereits auf Ihrem Bildschirm gerendert werden!
:::

## Frontend kompilieren

Internetbrowser verstehen von Natur aus keinen in React geschriebenen Code, keine `.jsx`- oder `.tsx`-Dateien und keine CSS-Präprozessoren wie `.less`. Damit Ihre Oberfläche korrekt funktioniert, ist ein Kompilierungsprozess (Build) erforderlich. Dieser Prozess übersetzt, bündelt und optimiert Ihren gesamten Code zu finalen statischen Dateien (Standard-JavaScript und -CSS), die der Browser mit maximaler Effizienz verarbeiten kann.

#### Voraussetzungen

Bevor Sie mit der Kompilierung beginnen, stellen Sie sicher, dass:

- das Terminal oder die Eingabeaufforderung in Ihrer Entwicklungsumgebung geöffnet ist.

- der Paketmanager `Bun` korrekt auf Ihrem System installiert ist.

## Kompilierungsbeispiele

Netuno stellt je nach Entwicklungsphase unterschiedliche Befehle bereit. Navigieren Sie vom Netuno-Stammordner zum Ordner `ui` Ihrer Anwendung.

Führen Sie die Befehle im Oberflächenordner Ihrer Anwendung aus: `📂 apps/meineapp/ui`

### Produktionskompilierung

Führt die vollständige und optimierte Kompilierung der Dateien durch. Dieser Befehl ist ideal, wenn Sie die Entwicklung einer Ansicht oder Komponente abgeschlossen haben und leichte finale Dateien mit besserer Performance erzeugen möchten.

```bash
bun run build
```

### Entwicklungskompilierung

Der Befehl **watch** führt eine schnelle Kompilierung durch und überwacht den Ordner. Immer wenn Sie eine Datei in Ihrem Editor speichern, führt das Terminal die Kompilierung automatisch aus.

```bash
bun run watch
```
Unabhängig davon, ob Sie den Befehl **build** oder **watch** verwenden, erscheinen die Änderungen nicht sofort auf dem Bildschirm des Benutzers. Aktualisieren Sie die Backoffice-Seite in Ihrem Browser, um die neu generierten Dateien zu laden.

:::tip Fehlerüberwachung und Debugging
Während der Entwicklung können Fehler in zwei verschiedenen Phasen auftreten. Achten Sie darauf, wo Sie danach suchen:

- **Kompilierungsfehler**: Syntaxfehler im React-Code oder nicht deklarierte Variablen werden direkt in Ihrem Terminal angezeigt, in dem der Befehl **bun** ausgeführt wird.

- **Laufzeitfehler**: Fehler, die während der Nutzung der Anwendung auftreten, werden in der Browserkonsole angezeigt. Denken Sie immer daran, die Seite zu prüfen, um festzustellen, ob es Warnungen oder Fehler gibt.
:::

### Integrierte Kompilierung

Die integrierte Kompilierung ermöglicht es, Terminalbefehle automatisch zusammen mit dem Start des Servers auszuführen. Dies optimiert den Arbeitsablauf, indem alle Logs und Überwachungen in einem einzigen zentralen Terminal zusammengefasst werden.

Um die integrierte Kompilierung zu aktivieren, müssen Sie die Entwicklungseinstellungen Ihrer Anwendung ändern:

- Rufen Sie den Stammordner Ihrer Anwendung auf.

- Öffnen Sie die Entwicklungskonfigurationsdatei: `_development.json`.

- Suchen Sie den Codeblock für „**commands**“.

- Ändern Sie den Wert der Eigenschaft „enabled“ von **false** auf **true**.

- Speichern Sie die Datei.

Ihre Datei `_development.json` sollte eine Struktur ähnlich der folgenden haben:

```json title="config/_development.json"
  ...
  "commands": [{
    "command": "bun run watch",
    "enabled": true,
    "install": "bun install",
    "path": "ui"
  }],
  ...
```

Damit Netuno die aktualisierte Datei liest und die neue Konfiguration anwendet, muss der Server neu gestartet werden:

- Gehen Sie zum Terminal, in dem der Netuno-Server ausgeführt wird.

- Beenden Sie den Prozess, indem Sie gleichzeitig die Tasten STRG + C drücken.

- Starten Sie den Server erneut und geben Sie den Namen Ihrer Anwendung an:

```shell
./netuno server app=meineapp
```

:::tip Ein einziges Terminal
Beobachten Sie nach dem Neustart des Servers die Logs im Terminal. Ihnen wird auffallen, dass Netuno nun automatisch die Frontend-Kompilierungsbefehle **bun run watch** im Hintergrund ausführt. Ab jetzt funktioniert alles integriert im selben Fenster.
:::

## API-Dienst zum Generieren von PDF

Im vorherigen Schritt haben wir den Button **PDF exportieren** im Frontend mit dem Attribut „**href**“ konfiguriert, das auf die Adresse `services/kunde/exportiere-pdf` verweist. Wenn Sie jedoch jetzt darauf klicken, wird nichts passieren. Das liegt daran, dass der API-Dienst, der die Datei generiert, noch nicht existiert.

Die gesamte API-Entwicklung findet im Ordner `📂 server` statt.

- Die Komponente PDFButton im Frontend erstellt haben, die auf die korrekte URL verweist.

                        _pdf.paragraph(dbKunde.getString("name"))
                            .setFontSize(12)
                            .setFontColor(_pdf.color("#748dae"))
                    )
                }

                pdfDocument.close()
            `
        },
    ]}
/>


#### Den Code verstehen

- **_header.contentType("pdf")**: Teilt dem Browser mit, dass die Antwort dieser Anfrage kein gewöhnlicher Text oder JSON ist, sondern eine PDF-Datei.

- **_pdf**: Ist die native Netuno-Ressource zur Bearbeitung von PDFs. Damit definieren wir die Seitengröße (A5), erstellen Absätze und passen Schriftgrößen (setFontSize) sowie Farben (setFontColor) an.

- **_db.form("kunde").all()**: Fragt die Datenbank ab und gibt alle im Formular „kunde“ gespeicherten Datensätze zurück. Die Wiederholungsschleife (for) durchläuft jeden dieser Kunden und extrahiert die Information des Feldes „name“, um sie im Dokument auszugeben.

- **pdfDocument.close()**: Schließt den Aufbau des Dokuments ab und sendet es als Antwort.

#### Validierung und Tests

Es ist nicht erforderlich, jedes Mal auf den Dashboard-Button zu klicken, wenn Sie Ihren Dienst testen möchten. Da es sich um eine einfache Anfrage (GET) handelt, können Sie die Ausführung validieren, indem Sie die API-URL direkt im Browser aufrufen.

Rufen Sie für dieses Beispiel die folgende Adresse auf:
http://localhost:9000/services/kunde/exportiere-pdf

Wenn die PDF-Datei generiert und auf dem Bildschirm mit der Kundenliste angezeigt wird, funktioniert der Dienst einwandfrei! Folglich funktioniert der Button PDF exportieren in Ihrem Dashboard automatisch.

Wenn die Seite leer bleibt oder beim Aufrufen der URL eine Fehlermeldung zurückgibt, prüfen Sie sofort das Terminal, in dem der Netuno-Server läuft. Anders als im Frontend, dessen Fehler in der Browserkonsole erscheinen, werden Ausführungsfehler in den Skripten des Ordners server ausführlich im Terminal des Backend-Servers angezeigt.
:::
