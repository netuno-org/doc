Dateien an die API senden und in einem Ordner oder in der Datenbank speichern.

## Einführung

Wenn wir Dateien an die Dienste der REST-API senden müssen, gibt es in Netuno mehrere Möglichkeiten, dies zu implementieren.

Normalerweise werden Dateien im Body der HTTP-Anfrage im multipart-Format strukturiert gesendet; dies ist das gängigste Verfahren im Frontend, zum Beispiel wenn wir ein Formular ausfüllen, das ein Feld zur Auswahl einer Datei enthält.

Alternativ können wir die Bytes der Dateien als Base64-kodierten Wert in einem JSON-Objekt senden, wenn wir eine zu 100 % auf JSON basierende REST-API wünschen.

## Dateien

Über `_req.file` können wir den Feldnamen angeben und so das Objekt der gesendeten Datei abrufen; sehen Sie hier:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const meineDatei = _req.file("datei");
            `
        },
    ]}
/>

Das heißt, `_req` enthält alle Daten, die wir im Body der HTTP-Anfrage empfangen.

Und über die Methode `file` lässt sich das Objekt abrufen, das die gesendete Datei repräsentiert.

Der erhaltene Wert kann `null` sein, wenn keine Datei vorhanden ist.

## Als Base64 im JSON

Um eine Datei im an den Dienst gesendeten JSON hochzuladen, können wir eine Eigenschaft mit folgendem Wert definieren:

`data:image/png;base64,...`

Dabei folgt in `...` die Folge der Base64-kodierten Bytes der Datei.

Der Dateityp folgt dabei nach `data`, zum Beispiel:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Objekt

Wenn sich die Datei in einer internen JSON-Struktur innerhalb des Unterobjekts befindet:


## OpenAPI

Netuno unterstützt die Integration mit OpenAPI und verwendet die OpenAPI-Definition zur Validierung der HTTP-Anfrage.

> Mehr über [OpenAPI in Netuno](/docs/academy/server/services/openapi).

Mit dem Typ `file` validiert Netuno, ob der Wert mit dem Dateiformat im JSON beginnt, zum Beispiel:

- `data:image/png;base64,...`

Um zu validieren, ob eine Datei in einer Eigenschaft des JSON-Objekts empfangen wird:

```json title="post.in.json"
{
  "summary": "Datei-Upload",
  "description": "Dienst, der eine Datei im JSON-Objekt empfängt.",
  "type": "object",
  "properties": {
    "datei": {
      "type": "file"
    }
  },
  "required": [
    "datei"
  ]
}
```

Um zu validieren, ob eine Liste von Dateien als Array im JSON empfangen wird:

```json title="post.in.json"
{
  "summary": "Datei-Uploads",
  "description": "Dienst, der eine Liste von Dateien als Array im JSON empfängt.",
  "properties": {
    "dateien": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "dateien"
  ]
}
```

## Die Datei speichern

Normalerweise müssen wir eine im Dienst empfangene Datei speichern, zum Beispiel:

- **Datenbank**: Datei, die zu einem Datensatz gehört, z. B. zu einem Benutzer.
- **Storage**: Interner Ordner der Anwendung, der allgemein zur Verwaltung von Dateien dient.
- **Ordner**: Die Datei in einem beliebigen Ordner des Systems ablegen.

### Datenbank

Bei der Verwaltung der Formularfelder unterstützt Netuno die Typen `image` und `file`, wobei:

- **Image**: Allgemeine Bilddateien, JPG und PNG.
- **File**: Jeder Dateityp.

Angenommen, es gibt ein Bildfeld im Formular Produkt; wir können die per Upload gesendete Datei wie folgt speichern:

#### Download der Datei aus der Datenbank

Um die gespeicherte Datei bereitzustellen, müssen wir einen Dienst erstellen, der die Bytes der Datei liefert.

Bei in der Datenbank gespeicherten Dateien, wie im obigen Beispiel, wird die Datei selbst im Storage der Anwendung abgelegt und in der Datenbank nur der endgültige Dateiname gespeichert.

> Der Storage der Anwendung ist ein Ordner zum Speichern und Organisieren allgemeiner Dateistrukturen.

Daher werden im obigen Beispiel die Datenbankdateien des Formulars `Produkt` und des Feldes `Bild` gespeichert unter:

- `storage/database/produkt/bild/*`

> Netuno verwaltet den Namen der gespeicherten Datei automatisch, um doppelte Dateinamen zu vermeiden.

Um die Datei abzurufen, kann ein Dienst erstellt werden, der die Bilddatei des Produkts bereitstellt, zum Beispiel:

            produktUid = _req.getString("uid")

            # DB Form:
            dbProdukt = _db.form("produkt")
                .where(_db.where("uid").equals(produktUid))
                .first()
            # Alternative mit klassischer DB:
            # dbProdukt = _db.get("produkt", produktUid)

            if dbProdukt.nil?
                _header.status(404)
                _out.json(
                    _val.map()
                        .set("ergebnis", false)
                        .set("fehler", "produkt-nicht-gefunden")
                )
                _exec.stop()
            end

            dbProduktBildName = dbProdukt.getString("bild")

            storageProduktBildDatei = _storage.database(
                "produkt",
                "bild",
                dbProduktBildName
            )

            if storageProduktBildDatei.extension() == "jpg" || storageProduktBildDatei.extension() == "jpeg"
                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storageProduktBildDatei.inputStream())
        `
    },
]}
/>

Beachten Sie, dass die Ressource `_storage` ([Storage](/docs/library/resources/storage)) verwendet wird, um die Datei abzurufen:

In der Datenbank wird nur der Dateiname gespeichert; über `_storage.database` können wir die Datei selbst abrufen.

### Storage

Wir können eine Datei direkt im `storage` der Anwendung speichern.

Um sie nicht mit den Datenbankdateien zu vermischen, sollten wir den Ordner `filesystem` verwenden, der zum Speichern allgemeiner Dateien dient, die nicht mit der Datenbank verknüpft sind.

Um die Datei zu empfangen, wird in diesem Beispiel gezeigt, wie eine im Dienst `POST` gesendete Datei direkt im Storage gespeichert wird:

<PolyglotCode
    file="services/datei/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const datei = _req.getFile("datei");
                _storage.filesystem("server", "upload").ensurePath();
                datei.save(_storage.filesystem("server", "upload", datei.name()));
            `
        },
    ]}
/>

Die Datei wird im Ordner `storage` der Anwendung gespeichert, unter:

- `storage/filesystem/server/upload/*`

> Die Ressource [Storage](/docs/library/resources/storage) wird verwendet, um den Ordner- und Dateipfad abzurufen:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // Name des Unterordners im Filesystem.
                    "upload", // Name oder Pfad des internen Unterordners.
                    datei.name() // Endgültiger Name der Datei.
                );
            `
        },
    ]}
/>

> Weitere Informationen finden Sie in der Dokumentation zu [Storage](/docs/library/resources/storage).

Um die Datei herunterzuladen, wird in diesem Beispiel gezeigt, wie die Bytes der Datei über den Dienst `GET` abgerufen werden können:

### Ordner

Wir können eine Datei direkt in einem beliebigen Ordner des Computers speichern.

Zwei Ressourcen sind in diesen Fällen sehr nützlich:

- `_app` - Wir können jeden Ordner oder jede Datei in der Anwendung abrufen.
- `_os` - Wir können jeden Ordner oder jede Datei auf dem Computer abrufen.

> Siehe die Dokumentation der jeweiligen Ressourcen [App](/docs/library/resources/app) und [OS](/docs/library/resources/os); beide Ressourcen haben die Methoden `folder` und `file`, mit denen der Pfad des Ordners bzw. der Datei angegeben werden kann.

Um die Datei zu empfangen, wird in diesem Beispiel gezeigt, wie eine im Dienst `POST` gesendete Datei direkt in einem Ordner der Anwendung gespeichert wird:

## Fazit

Wie man sehen kann, können wir den Datei-Upload in die Dienste der REST-API integrieren, einschließlich der Integration mit OpenAPI.

Wir können die Datei in der Datenbank, im Ordner `storage` der Anwendung oder in einem beliebigen Ordner des Computers speichern.

Siehe die Dokumentation der in diesem Tutorial verwendeten Ressourcen, mit denen Dateien bearbeitet werden können:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

In der Datenbank können wir Bilder in Feldern vom Typ `image` speichern und jeden Dateityp in Feldern vom Typ `file` speichern; wie wir Dateien speichern oder abrufen, ist in jedem Fall gleich, ob es sich um ein Bild oder eine allgemeine Datei handelt.
