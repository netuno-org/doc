## Wprowadzenie

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a> to dokumentowa baza danych NoSQL. Zamiast tabel i wierszy dane przechowywane są w dokumentach w formacie zbliżonym do JSON, co zapewnia dużą elastyczność modelu danych.

Netuno udostępnia zasób [_mongo](/docs/library/resources/mongo) do integracji z MongoDB, z niskokodową abstrakcją nad oficjalnym klientem MongoDB dla Javy, dostępną dla różnych języków programowania obsługiwanych przez Netuno: **JavaScript, Python, Ruby, Kotlin i Groovy**.

> Przed rozpoczęciem zaleca się zapoznanie z tworzeniem usług w Netuno — zobacz tutorial [REST - Usługi sieciowe](/docs/academy/server/services/rest).

Przykład implementacji przedstawionych tutaj operacji znajduje się w usłudze przykładowej `mongo.js`, zlokalizowanej w:

## Instalacja MongoDB

### Za pomocą Docker

Zakładając, że masz zainstalowany Docker, wystarczy pobrać obraz MongoDB i uruchomić nowy kontener:

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

W ten sposób MongoDB jest dostępny pod adresem `localhost:27017` bez uwierzytelniania.

Aby utworzyć użytkownika bazy danych zgodnie z konfiguracją aplikacji, wykonaj:

```shell
docker exec -it mongo mongosh produkty_db --eval 'db.createUser({ user: "produkty_uzytkownik", pwd: "12345678", roles: [{ role: "readWrite", db: "produkty_db" }] })'
```

### Za pomocą Ubuntu

MongoDB nie jest dostępny w oficjalnych repozytoriach Ubuntu, dlatego przed instalacją trzeba dodać oficjalne repozytorium:

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

Po instalacji możesz uruchomić usługę za pomocą:

```shell
sudo systemctl start mongod
```

### Za pomocą Windows

- <a href="https://www.mongodb.com/try/download/community" target="_blank">Pobierz MongoDB Community Server</a>.

Uruchom pobrany instalator i w kroku **Service Configuration** włącz **Install MongoD as a Service**, aby MongoDB uruchamiał się automatycznie. MongoDB będzie dostępny pod adresem `localhost:27017` bez uwierzytelniania.

> Zapoznaj się z [oficjalną dokumentacją MongoDB](https://www.mongodb.com/docs/manual/installation/), aby poznać inne dystrybucje i wersje.

## Konfiguracja aplikacji

Konfiguracja połączeń MongoDB odbywa się w pliku konfiguracyjnym aplikacji, w zależności od środowiska:

- `config/_development.json`

> Dowiedz się więcej o [plikach konfiguracyjnych](/docs/academy/explore/configuration) aplikacji.

W pliku konfiguracyjnym dodaj blok `mongo`, w którym każdy klucz identyfikuje jedno połączenie:

```javascript
{
    ...
    "mongo": {
        "sklep": "mongodb://sklep_uzytkownik:12345678@localhost/sklep_db",
        "produkty": {
            "username": "produkty_uzytkownik",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "produkty_db"
        }
    },
    ...
}
```

Połączenie można zdefiniować na dwa sposoby:

- **Jako URL połączenia** — wartość jest po prostu ciągiem znaków, na przykład `"mongodb://sklep_uzytkownik:12345678@localhost/sklep_db"`.
- **Jako obiekt konfiguracji** — z polami:
  - `url` — jeśli zdefiniowany, jest używany bezpośrednio jako URL połączenia, z pominięciem pozostałych pól.
  - `protocol` — protokół połączenia, domyślnie `mongodb`.
  - `username` i `password` — dane uwierzytelniające.
  - `host` — adres serwera, domyślnie `localhost`.
  - `port` — port połączenia, domyślnie `27017`.
  - `database` — nazwa bazy danych, domyślnie nazwa klucza połączenia.
  - `params` — dodatkowe parametry połączenia dołączane do URL, na przykład `{ "authSource": "admin" }`. Stosowane są wyłącznie wtedy, gdy URL jest budowany z pól obiektu.

> Połączenie nie musi dotyczyć głównej bazy danych aplikacji. W przeciwieństwie do konfiguracji `db` blok `mongo` jest niezależny i pozwala na wiele równoczesnych połączeń.

### Filtry

Fabryka `_mongo.filters()` udostępnia najważniejsze operatory zapytań MongoDB:

| Operator | Opis |
|---|---|
| `eq("pole", wartosc)` | Równe wartości. |
| `ne("pole", wartosc)` | Różne od wartości. |
| `gt("pole", wartosc)` | Większe niż wartość. |
| `gte("pole", wartosc)` | Większe lub równe wartości. |
| `lt("pole", wartosc)` | Mniejsze niż wartość. |
| `lte("pole", wartosc)` | Mniejsze lub równe wartości. |
| `in("pole", wartosc1, wartosc2, ...)` | Równe którejkolwiek z wartości. |
| `nin("pole", wartosc1, wartosc2, ...)` | Różne od wszystkich wartości. |
| `and(filtr1, filtr2, ...)` | Odpowiada wszystkim filtrom. |
| `or(filtr1, filtr2, ...)` | Odpowiada co najmniej jednemu z filtrów. |
| `not(filtr)` | Nie odpowiada filtrowi. |
| `regex("pole", "wzorzec")` | Odpowiada wyrażeniu regularnemu. |
| `exists("pole")` | Pole istnieje w dokumencie. |
| `text("wyszukiwanie")` | Wyszukiwanie tekstowe. |
| `type("pole", "typ")` | Pole jest określonego typu. |
| `mod("pole", dzielnik, reszta)` | Reszta z dzielenia wartości pola przez dzielnik jest równa podanej wartości. |
| `where("wyrażenie")` | Odpowiada dokumentom spełniającym wyrażenie JavaScript, na przykład `"this.cena > 100"`. |
| `size("pole", n)` | Pole tablicowe ma dokładnie `n` elementów. |

## Agregacje

Do bardziej zaawansowanych analiz służy `aggregate()`, który pozwala wykonać potok agregacji, gdzie każdy etap definiowany jest za pomocą fabryki `_mongo.aggregates()`, a akumulatory za pomocą `_mongo.accumulators()`.

Na przykład, aby pogrupować produkty według kategorii i zsumować cenę w każdej grupie:

    codes={[
        {
            lang: 'javascript',
            code: `

                    _mongo.aggregates().match(
                        _mongo.filters().eq("kategoria", "komputery")
                    ),
                    _mongo.aggregates().group(
                        "$kategoria",
                        _mongo.accumulators().sum("suma", "$cena")
                    ),
                    _mongo.aggregates().sort(
                        _mongo.sorts().descending("suma")
                    )
                ).all()
            `
        },
        {
            lang: 'python',
            code: `

Dostępne etapy agregacji są następujące:

| Etap | Opis |
|---|---|
| `match(filtr)` | Wybiera tylko dokumenty odpowiadające filtrowi. |
| `group("$pole", akumulatory)` | Grupuje dokumenty według pola i stosuje akumulatory. |
| `project(projekcja)` | Dodaje, usuwa lub zmienia pola w dokumentach. |
| `sort(sortowanie)` | Sortuje dokumenty. |
| `limit(n)` | Ogranicza do pierwszych `n` dokumentów. |
| `skip(n)` | Pomija pierwsze `n` dokumentów. |
| `count()` | Zlicza liczbę dokumentów. |
| `lookup("kolekcja", "poleLokalne", "poleObce", "jako")` | Wykonuje złączenie z inną kolekcją. |

A najczęściej używane akumulatory:

| Akumulator | Opis |
|---|---|
| `sum("pole", "$wyrażenie")` | Suma wartości. |
| `avg("pole", "$wyrażenie")` | Średnia wartości. |
| `min("pole", "$wyrażenie")` | Wartość minimalna. |
| `max("pole", "$wyrażenie")` | Wartość maksymalna. |
| `first("pole", "$wyrażenie")` | Wartość pierwszego dokumentu. |
| `last("pole", "$wyrażenie")` | Wartość ostatniego dokumentu. |
| `top("pole", sortowanie, "$wyrażenie")` | Wartość najwyższa według sortowania. |
| `bottom("pole", sortowanie, "$wyrażenie")` | Wartość najniższa według sortowania. |

> W akumulatorach wyrażenie z prefiksem `$` odnosi się do pola dokumentu wejściowego, na przykład `"$cena"`.

## Operacje z opcjami
