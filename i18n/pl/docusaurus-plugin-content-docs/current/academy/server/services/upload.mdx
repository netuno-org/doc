Wysyłanie plików do API i zapisywanie ich w folderze lub w bazie danych.

## Wprowadzenie

Gdy musimy wysyłać pliki do usług API REST, mamy kilka sposobów
na realizację tego zadania w Netuno.

Zwykle pliki są wysyłane w treści żądania HTTP w formacie
multipart; to najczęstszy sposób w frontendzie, na przykład gdy wypełniamy
formularz i znajduje się w nim pole do wyboru pliku.

Alternatywnie możemy wysłać bajty plików zakodowane w Base64 jako wartość
w obiekcie JSON, gdy chcemy mieć API REST w 100% oparte na JSON.

## Pliki

Za pomocą `_req.file` możemy podać nazwę pola i w ten sposób uzyskać obiekt pliku,
który został wysłany. Zobacz jak:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const mojPlik = _req.file("plik");
            `
        },
    ]}
/>

Czyli `_req` zawiera wszystkie dane, które otrzymaliśmy w treści żądania HTTP.

A dzięki metodzie `file` można uzyskać obiekt reprezentujący plik, który został
wysłany.

Otrzymana wartość może być `null`, jeśli nie ma żadnego pliku.

jednolitość i zmniejszyć miejsce zajmowane przez obrazy.

## Base64 w JSON

Aby przesłać plik w JSON wysyłanym do usługi, możemy zdefiniować właściwość o wartości:

`data:image/png;base64,...`

Gdzie w `...` następuje sekwencja bajtów pliku zakodowanych w Base64.

Typ pliku występuje po `data`, na przykład:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Obiekt

Jeśli plik znajduje się w wewnętrznej strukturze JSON w podobiekcie:

```json

}
```

## OpenAPI

Netuno obsługuje integrację z OpenAPI i wykorzystuje definicję OpenAPI do walidacji żądania HTTP.

> Więcej o [OpenAPI w Netuno](/docs/academy/server/services/openapi).

Za pomocą typu `file` Netuno sprawdza, czy wartość zaczyna się od formatu pliku w JSON, na przykład:

- `data:image/png;base64,...`

Aby zweryfikować, czy odbierany jest plik we właściwości obiektu JSON:

```json title="post.in.json"
{
  "summary": "Przesyłanie pliku",
  "description": "Usługa, która otrzymuje plik w obiekcie JSON.",
  "type": "object",
  "properties": {
    "plik": {
      "type": "file"
    }
  },
  "required": [
    "plik"
  ]
}
```

Aby zweryfikować, czy odbierana jest lista plików w tablicy JSON:

```json title="post.in.json"
{
  "summary": "Przesyłanie plików",
  "description": "Usługa, która otrzymuje listę plików w tablicy JSON.",
  "properties": {
    "pliki": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "pliki"
  ]
}
```

## Zapisywanie pliku

Zwykle gdy odbieramy plik w usłudze, musimy go zapisać, na przykład:

- **Baza danych**: plik powiązany z rekordem, np. użytkownika.
- **Storage**: wewnętrzny folder aplikacji służący do ogólnego zarządzania plikami.
- **Folder**: umieszczenie pliku w dowolnym folderze systemu.

### Baza danych

W zarządzaniu polami formularzy Netuno obsługuje typy `image` i `file`, czyli:

- **Image**: ogólnie pliki obrazów, JPG i PNG.
- **File**: dowolny typ pliku.

Załóżmy, że w formularzu Produkt jest pole Obraz; możemy zapisać plik przesłany przez upload w następujący sposób:

#### Pobieranie pliku z bazy danych

Aby wyświetlić przechowywany plik, musimy utworzyć usługę, która dostarcza bajty pliku.

W przypadku plików zapisywanych w bazie danych, jak w powyższym przykładzie, sam plik jest umieszczany w storage
aplikacji, a w bazie danych przechowywana jest tylko końcowa nazwa pliku.

> Storage aplikacji to folder przeznaczony do przechowywania i organizowania struktur ogólnych plików.

Dlatego w powyższym przykładzie pliki bazy danych formularza `Produkt` i pola `Obraz` są
przechowywane w:

- `storage/database/produkt/obraz/*`

> Netuno automatycznie zarządza nazwą przechowywanego pliku, aby uniknąć zduplikowanych nazw plików.

Aby uzyskać plik, można utworzyć usługę, która wyświetla plik obrazu produktu, na przykład:

### Storage

Możemy zapisać plik bezpośrednio w `storage` aplikacji.

Aby nie mieszać ich z plikami bazy danych, powinniśmy użyć folderu `filesystem`, który
służy do przechowywania ogólnych plików niezwiązanych z bazą danych.

Aby odebrać plik, w tym przykładzie pokazano, jak plik przesłany w usłudze
`POST` jest przechowywany bezpośrednio w storage:

<PolyglotCode
    file="services/plik/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const plik = _req.getFile("plik");
                _storage.filesystem("server", "przesylanie").ensurePath();
                plik.save(_storage.filesystem("server", "przesylanie", plik.name()));
            `
        },
    ]}
/>

Plik jest przechowywany w folderze `storage` aplikacji, w:

- `storage/filesystem/server/przesylanie/*`

> Zasób [Storage](/docs/library/resources/storage) służy do uzyskania ścieżki folderu i pliku:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // Nazwa podfolderu w filesystem.
                    "przesylanie", // Nazwa lub ścieżka wewnętrznego podfolderu.
                    plik.name() // Końcowa nazwa pliku.
                );
            `
        },
    ]}
/>

> Zobacz więcej w dokumentacji [Storage](/docs/library/resources/storage).

Aby pobrać plik, w tym przykładzie pokazano, jak bajty pliku

### Folder

Możemy zapisać plik bezpośrednio w dowolnym folderze komputera.

W takich przypadkach bardzo przydatne są dwa zasoby:

- `_app` – możemy pobrać dowolny folder lub plik w aplikacji.
- `_os` – możemy pobrać dowolny folder lub plik na komputerze.

> Zobacz dokumentację odpowiednich zasobów [App](/docs/library/resources/app) i [OS](/docs/library/resources/os);
> oba zasoby mają metody `folder` i `file`, które pozwalają wskazać odpowiednio ścieżkę folderu lub pliku.

Aby odebrać plik, w tym przykładzie pokazano, jak plik przesłany w usłudze

## Podsumowanie

Jak widać, możemy zintegrować przesyłanie plików z usługami API REST, w tym
z OpenAPI.

Możemy zapisać plik w bazie danych, w folderze `storage` aplikacji lub w dowolnym folderze
komputera.

Zobacz dokumentację zasobów użytych w tym samouczku, które pozwalają manipulować plikami:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

W bazie danych możemy zapisywać obrazy w polach typu `image` oraz dowolny typ pliku w
polach typu `file`; sposób zapisywania i uzyskiwania plików jest taki sam w każdym przypadku, zarówno dla obrazu, jak i
pliku ogólnego.
