## Перед началом

Прежде чем продолжить, убедитесь, что у вас есть базовые знания _**JavaScript**_ и основы Netuno, пройдя пошаговое руководство, доступное в [Академии](/docs/academy/overview).

## Введение

Часто возникает необходимость периодически выполнять задачи: время от времени нужно отправлять данные в другую систему, импортировать данные из другой системы, отправлять электронное письмо, проверять записи в базе данных и многое другое...

В Linux/UNIX/Mac существует служба Cron с известным файлом конфигурации `crontab`, а в Windows есть Task Manager (_Диспетчер задач_).

А в Netuno Cron Jobs уже встроен, что помогает избежать внешней настройки.

Такие периодические операции известны как Cron Jobs, или по-русски — запланированные сервисы.

Каждое приложение Netuno может иметь множество Cron Jobs, и Cron Jobs Netuno могут выполнять как внутренние сервисы и URL, так и внешние URL.

> Для получения дополнительной информации см. документацию ресурса [cron](/docs/library/resources/cron).

## Как это работает

Каждое приложение имеет настройку собственных запланированных сервисов (**cron jobs**) с соответствующей конфигурацией выполнения.

Для простоты каждый запланированный сервис — это отдельный **job**, имеющий собственную конфигурацию выполнения: он может выполняться каждую минуту, каждые 5 минут, каждый час, в определённый день и час недели и т. д. ... также у него есть URL, который будет вызван в момент его выполнения.

> Netuno использует библиотеку <a href="http://www.quartz-scheduler.org/" target="_blank">Quartz Scheduler</a> для управления выполнением запланированных сервисов. Настройка правил временного планирования соответствует этой библиотеке.

Таким образом, выполнение каждой задачи проходит через вызов URL (_веб-адреса, ссылки_), который может быть как внешним, так и внутренним для самого приложения. Если это внешняя ссылка, она может принадлежать другому приложению или любому внешнему URL в интернете, сети или на компьютере.

![Схема Cron](/docs/assets/academy/server/cron.svg)

На графике выше показано, что Netuno содержит 2 приложения, в каждом из которых настроено 2 задачи (_запланированных сервиса_), выполняемые в разное время согласно некоторой конфигурации.

Поведение выполнения будет следующим:

- Приложение 1 запускает 2 задачи:
  - Задача 1: выполняет URL внутреннего сервиса самого Приложения 1.
  - Задача 2: выполняет внешний публичный URL.
- Приложение 2 запускает 2 задачи:
  - Задача 3: выполняет URL внутреннего сервиса самого Приложения 2.
  - Задача 4: выполняет URL сервиса Приложения 1.

> Приложения должны размещать сервисы, выполняемые Cron Jobs, в папке:
> - 📂 `server/services/jobs`

Каждый URL выполняется методом HTTP POST. В настройке задачи можно добавить дополнительные параметры, а также секретный ключ, чтобы предотвратить выполнение вне контролируемого контекста.

## Настройка

Настройка запланированных сервисов выполняется в файле конфигурации приложения в соответствии с окружением.

> Настройка никогда не должна начинаться с `*`, это вызовет выполнение каждую секунду, что создаст проблемы с производительностью по принципу снежного кома, если обработка в какой-то момент займёт больше 1 секунды.

Для этого перейдите в разрабатываемом приложении к файлу конфигурации окружения. В этом примере мы будем использовать файл окружения разработки, расположенный по пути:

- 📂 `config/_development.json`

Проверьте, нет ли уже настроек для Cron; если их нет, добавьте в конец файла конфигурации (в формате JSON) параметры настройки:

```
{
    ...
    "cron": {
        "secret": "m3u-S3Gred0",
        "jobs": [
            {
                "name": "moy-job",
                "config": "0 30 12 * * ?",
                "url": "http://moya-app.local.netu.no:9000/services/jobs/moy-job"
            },
            {
                "name": "moy-job",
                "config": "0 0/2 * * * ?",
                "url": "http://moya-app.local.netu.no:9000/services/jobs/moy-drugoy-job",
                "params": {
                    "secret": "m3u-Ou7ro-S3Gred0",
                    "тип": "клиент"
                }
            }
        ]
    },
    ...
}
```

В этой конфигурации первая задача будет выполняться каждый день в 12:30.

А вторая задача будет выполняться каждые 2 минуты.


##### Jobs

Список запланированных сервисов в приложении; поскольку это массив, можно настроить несколько сервисов.

##### Secret

Это параметр ключа безопасности, который защищает сервис: он выполняется только при получении этого параметра с точно совпадающим значением.

Это потому, что `jobs` — публичные сервисы, и чтобы предотвратить их внешнее выполнение, добавлена эта защита.

##### Name

Имя, идентифицирующее сервис внутри системы; может использоваться для управляющих операций, например остановки и возобновления.

##### Config

Настройка выражения временного планирования сервиса, то есть правила его расписания.

> Настройка никогда не должна начинаться с `*`, это вызовет выполнение каждую секунду, что создаст проблемы с производительностью по принципу снежного кома, если обработка в какой-то момент займёт больше 1 секунды.

Ниже приведены поддерживаемые выражения.

##### URL

Адрес, который будет выполняться периодически.

##### Params

Это параметры, передаваемые URL при его выполнении; URL выполняется методом **HTTP POST**, поэтому можно добавлять дополнительные параметры, например _тип_ в примере выше, или даже указать другой секретный ключ.

|ИМЯ ПОЛЯ | ОБЯЗАТЕЛЬНО | ДОПУСТИМЫЕ ЗНАЧЕНИЯ | РАЗРЕШЁННЫЕ СПЕЦИАЛЬНЫЕ СИМВОЛЫ |
| ------- |:------:|:-----------:|--------------|
| Секунды | ДА | 0-59 | , - * / |
| Минуты | ДА | 0-59 | , - * / |
| Часы | ДА | 0-23 | , - * / |

## Сервис

Запланированные сервисы должны быть запрограммированы в папке:

- 📂 `server/services/jobs`

Netuno автоматически выполнит эти сервисы и проверит параметр `secret` на соответствие значению из конфигурации.

> `secret` служит для безопасного выполнения сервиса извне без аутентификации.

Сервис будет выполняться периодически в соответствии с заданной параметризацией.

Чтобы вручную проверить выполнение сервиса, достаточно открыть прямой URL сервиса и передать параметр `secret`.

Например, через GET:

- http://moya-app.local.netu.no:9000/services/job/moy-job?secret=\*\*\*\*\*

Вместо `*****` в конце URL нужно подставить фактическое настроенное значение `secret`.

## Пример

Создайте файл по пути:

- 📂 `server/services/jobs/test.js`

В этот файл сервиса поместите следующий код:
```javascript
_log.info("Тестовая задача!")
_out.print("Ок")
```

В JSON конфигурации вашего приложения настройте параметризацию следующим образом:

```json
{
    ...
    "cron": {
        "secret": "m3u-S3Gred0",
        "jobs": [
            {
                "name": "test",
                "config": "0/30 * * * * ?",
                "url": "/services/jobs/test"
            }
        ]
    },
    ...
}
```

При запуске сервера Netuno в терминале начнёт появляться сообщение `Тестовая задача!` каждые 30 секунд.

Если открыть в браузере URL:

- http://localhost:9000/services/jobs/test?secret=m3u-S3Gred0

Он вернёт только `Ок`, а в терминале появится сообщение `Тестовая задача!`.

> В окружении `development` проверка `secret` не действует, поэтому можно выполнять без передачи `secret`, и это будет работать, но в другом окружении, например в production, она уже учитывается.

## Много задач

Когда требуется создать много запланированных задач, следует увеличить количество потоков, используемых для параллельного выполнения различных запланированных задач.

Эта настройка выполняется в файле `config.js`, находящемся в корне Netuno, путём добавления строки из примера:

```javascript
config.cronThreadCount = 10
```

> По умолчанию эта настройка допускает только 3 потока.
> 
> Следует учитывать, что количество потоков нужно увеличивать в соответствии с числом ядер CPU.

Использование слишком малого числа потоков для выполнения множества параллельных расписаний может привести к остановке выполнения запланированных задач.

Поэтому если задачи через некоторое время зависают, вероятно, выполняется слишком много задач параллельно; тогда необходимо увеличить количество потоков.

## Программно

Netuno позволяет настраивать и управлять Cron Jobs программно.

Это означает, что через код можно управлять всем.

### Создать новую задачу

Чтобы создать новую задачу, мы создаём её расписание с помощью [`_cron.schedule`](/docs/library/resources/cron#schedule).

[`_cron.schedule`](/docs/library/resources/cron#schedule) принимает следующие параметры:

1. Ключ идентификации задачи: `key`.
2. Настройка времени расписания для выполнения.
3. Адрес сервиса, который должен выполняться, то есть `URL`.
4. Дополнительные параметры, передаваемые при вызове сервиса.

```javascript
_cron.schedule(
    'moya-zadacha',
    '0 0/60 * * * ?',
    `/services/jobs/tovar-obnovlenie`,
    _val.map()
        .set('id', 123)
)
```

Если нужно автоматически создавать задачи при инициализации приложения, этот автоматизм можно закодировать в файле:

- `server/core/_init.js`

Этот файл выполняется каждый раз при инициализации приложения сервером Netuno.

### Удалить задачу

Чтобы удалить определённую задачу, используем [`_cron.remove(key)`](/docs/library/resources/cron#remove).

где `key` — ключ идентификации задачи.

См. пример:

```javascript
_cron.remove('moya-zadacha')
```

### Список задач

С помощью [`_cron.schedules()`](/docs/library/resources/cron#schedules) можно вывести список всех настроенных задач.

Пример вывода списка всех запланированных задач:

```javascript
const spisok = _cron.schedules()
_out.println('<table>')
_out.println('<tr>')
_out.println(`  <td>Ключ</td>`)
_out.println(`  <td>URL</td>`)
_out.println(`  <td>Параметры</td>`)
_out.println(`  <td>Описание</td>`)
_out.println(`  <td>Последнее выполнение</td>`)
_out.println(`  <td>Следующее выполнение</td>`)
_out.println(`  <td>Приоритет</td>`)
_out.println('</tr>')
for (const zadanie of spisok) {
        _out.println('<tr>')
        _out.println(`  <td>${zadanie.getString('key')}</td>`)
        _out.println(`  <td>${zadanie.getString('url')}</td>`)
        _out.println(`  <td>${zadanie.getValues('params').toJSON()}</td>`)
        _out.println(`  <td>${zadanie.get('detail').getDescription()}</td>`)
        _out.println(`  <td>${zadanie.get('trigger').getPreviousFireTime()}</td>`)
        _out.println(`  <td>${zadanie.get('trigger').getNextFireTime()}</td>`)
        _out.println(`  <td>${zadanie.get('trigger').getPriority()}</td>`)
        _out.println('</tr>')
}
_out.println('</table>')
```

### Приостановить задачи

С помощью [`_cron.pause(key)`](/docs/library/resources/cron#pause) можно приостановить выполнение определённой задачи.

Пример приостановки всех запланированных задач:

```javascript
const spisok = _cron.schedules()
_out.println('<table>')
_out.println('<tr>')
_out.println(`  <td>Ключ</td>`)
_out.println(`  <td>Остановлено</td>`)
_out.println('</tr>')
for (const zadanie of spisok) {
    _out.println('<tr>')
    _out.println(`  <td>${zadanie.getString('key')}</td>`)
    _out.println(`  <td>${_cron.pause(zadanie.getString('key'))}</td>`)
    _out.println('</tr>')
}
_out.println('</table>')
```

> Обратите внимание на использование `_cron.pause` в примере выше.

### Возобновить задачи

С помощью [`_cron.resume(key)`](/docs/library/resources/cron#resume) можно возобновить выполнение определённой задачи.

Пример возобновления всех запланированных задач с отображением времени их выполнения:

```javascript
const spisok = _cron.schedules()
_out.println('<table>')
_out.println('<tr>')
_out.println(`  <td>Ключ</td>`)
_out.println(`  <td>Возобновлено</td>`)
_out.println(`  <td>Следующее выполнение</td>`)
_out.println('</tr>')
for (const zadanie of spisok) {
    _out.println('<tr>')
    _out.println(`  <td>${zadanie.getString('key')}</td>`)
    _out.println(`  <td>${_cron.resume(zadanie.getString('key'))}</td>`)
    _out.println(`  <td>${zadanie.get('trigger').getNextFireTime()}</td>`)
    _out.println('</tr>')
}
_out.println('</table>')
```

> Обратите внимание на использование `_cron.resume` в примере выше.
