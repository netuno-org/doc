Отправка файлов в API и сохранение в папку или базу данных.

## Введение

Когда нужно отправлять файлы в сервисы REST API, в Netuno есть несколько способов
реализовать это.

Обычно файлы отправляются в теле HTTP-запроса в формате
multipart — это наиболее распространённый подход во фронтенде, например когда заполняют
форму и в ней есть поле для выбора файла.

В качестве альтернативы можно отправлять байты файлов, закодированные в Base64, как значение
в объекте JSON, если нужен REST API, полностью работающий с JSON.

## Файлы

Через `_req.file` можно передать имя поля и таким образом получить объект файла,
который был отправлен. Смотрите:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const moiFayl = _req.file("fayl");
            `
        },
    ]}
/>

То есть `_req` содержит все данные, полученные в теле HTTP-запроса.

А через метод `file` можно получить объект, представляющий отправленный
файл.

Полученное значение может быть `null`, если файла нет.

## Как Base64 в JSON

Чтобы загрузить файл в JSON, отправляемый в сервис, можно задать свойство со значением:

`data:image/png;base64,...`

Где в `...` идёт последовательность байтов файла, закодированных в Base64.

Тип файла указывается после `data`, например:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Объект

Если файл находится во внутренней структуре JSON внутри подобъекта:

```json
{
  "chelovek": {
    "fayl": "data:image/png;base64,..."
  }
}
```

Его можно получить так:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const moiFayl = _req.getValues("chelovek").getFile("avatar");
            `
        },
    ]}
/>

### Массив

Если файл находится во внутренней структуре JSON внутри массива:

```json
{
  "fayly": [
    "data:image/png;base64,..."
  ]
}
```

Его можно получить так:

## OpenAPI

Netuno поддерживает интеграцию с OpenAPI и использует определение OpenAPI для проверки HTTP-запроса.

> Подробнее об [OpenAPI в Netuno](/docs/academy/server/services/openapi).

С типом `file` Netuno проверяет, начинается ли значение с формата файла в JSON, например:

- `data:image/png;base64,...`

Чтобы проверить, что в свойстве объекта JSON принимается файл:

```json title="post.in.json"
{
  "summary": "Загрузка файла",
  "description": "Сервис, который принимает файл в объекте JSON.",
  "type": "object",
  "properties": {
    "fayl": {
      "type": "file"
    }
  },
  "required": [
    "fayl"
  ]
}
```

Чтобы проверить, что в JSON принимается список файлов в массиве:

```json title="post.in.json"
{
  "summary": "Загрузка файлов",
  "description": "Сервис, который принимает список файлов в массиве JSON.",
  "properties": {
    "fayly": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "fayly"
  ]
}
```

## Сохранение файла

Обычно, когда сервис получает файл, его нужно сохранить, например:

- **База данных**: файл, связанный с записью, например с пользователем.
- **Storage**: внутренняя папка приложения, предназначенная для управления файлами в целом.
- **Папка**: поместить файл в любую папку системы.

### База данных

При управлении полями форм Netuno поддерживает типы `image` и `file`, а именно:

- **Image**: файлы изображений в целом, JPG и PNG.
- **File**: любой тип файла.

Представьте, что в форме `Produkt` есть поле изображения; сохранить файл, загруженный
через загрузку, можно так:

#### Скачивание файла из базы данных

Чтобы отдать сохранённый файл, нужно создать сервис, который возвращает байты файла.

При этом файлы, сохранённые в базе данных, как в примере выше, сам файл помещается в storage
приложения, а в базе данных хранится только итоговое имя файла.

> Storage приложения — это папка, предназначенная для хранения и организации структур общих файлов.

Таким образом, в примере выше файлы базы данных формы `Produkt` и поля `Izobrazhenie` хранятся в:

- `storage/database/produkt/izobrazhenie/*`

> Netuno автоматически управляет именем сохраняемого файла, чтобы избежать повторяющихся имён файлов.

Чтобы получить файл, можно создать сервис, который отдаёт файл изображения продукта, например:

<PolyglotCode

### Storage

Можно сохранить файл напрямую в `storage` приложения.

Чтобы не смешивать с файлами базы данных, следует использовать папку `filesystem`,
предназначенную для хранения общих файлов, не связанных с базой данных.

Чтобы принять файл, в этом примере показано, как файл, отправленный в сервис
`POST`, сохраняется напрямую в storage:

<PolyglotCode
    file="services/fayl/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const fayl = _req.getFile("fayl");
                _storage.filesystem("server", "zagruzka").ensurePath();
                fayl.save(_storage.filesystem("server", "zagruzka", fayl.name()));
            `
        },
    ]}
/>

Файл сохраняется в папке `storage` приложения по пути:

- `storage/filesystem/server/zagruzka/*`

> Ресурс [Storage](/docs/library/resources/storage) используется для получения пути к папке и файлу:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // Имя подпапки в filesystem.
                    "zagruzka", // Имя или путь внутренней подпапки.
                    fayl.name() // Итоговое имя файла.
                );
            `
        },
    ]}
/>

> Подробнее см. в документации [Storage](/docs/library/resources/storage).

Чтобы скачать файл, в этом примере показано, как получить байты файла

### Папка

Можно сохранить файл напрямую в любую папку компьютера.

В таких случаях очень полезны два ресурса:

- `_app` — можно получить любую папку или файл в приложении.
- `_os` — можно получить любую папку или файл на компьютере.

> См. документацию соответствующих ресурсов [App](/docs/library/resources/app) и [OS](/docs/library/resources/os);
> оба ресурса имеют методы `folder` и `file`, которые позволяют указать путь к папке или файлу
> соответственно.

## Заключение

Как видно, можно интегрировать загрузку файлов в сервисы REST API, в том числе
с OpenAPI.

Можно сохранять файл в базе данных, в папке `storage` приложения или в любой папке
компьютера.

См. документацию ресурсов, использованных в этом руководстве и позволяющих
работать с файлами:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

В базе данных можно сохранять изображения в поля типа `image` и любые типы файлов
в поля типа `file`; способ сохранения и получения файлов одинаков в любом случае —
будь то изображение или обычный файл.
