## Введение

NodeJS и NPM лежат в основе экосистемы разработки фронтенда.

Несмотря на их полезность, их производительность оставляет желать лучшего.

Поэтому мы рекомендуем использовать Bun, чтобы получить значительные и ощутимые преимущества благодаря лёгкой и быстрой адаптации с сохранением совместимости.

В Netuno Bun используется всё чаще, и вот причины...

## Bun

Bun сопоставим с NodeJS, но значительно мощнее, современнее, интуитивнее и супербыстрый.

Производительность Bun не вызывает сомнений: кто переходит с выполнения на NodeJS на Bun, сразу замечает преимущество.

Поскольку фронтенд-проекты обычно запускаются не сразу, с Bun запуск происходит мгновенно.

Кроме того, фронтенд-зависимости обычно занимают много места: папка `📂 node_modules` легко может достигать сотен мегабайт или даже гигабайт.

Bun также решает проблему лишнего места, вызванного дублированием копий зависимостей в нескольких проектах.

Он создаёт центральное хранилище зависимостей, общее для всех проектов, и при установке настраивает связанные папки.

Так он резко сокращает объём места, занимаемого зависимостями.

> Среди множества других преимуществ также выделяются удобство использования и улучшенный, интуитивный и в целом более развитый вывод.

Поскольку преимущества производительности имеют первостепенное значение для гибкой разработки, мы рекомендуем его использовать.

Чтобы установить Bun, выполните шаги по ссылке:

- [**Установка Bun**](https://bun.sh/docs/installation)

### Использование в проектах

Чтобы использовать Bun в проектах, убедитесь, что если вы уже используете NPM, Yarn или другой менеджер, то необходимо удалить папку `📂 node_modules`.

В каталоге с файлом `package.json` выполните команду установки зависимостей:

- `bun install`

Теперь достаточно выполнить действия из `scripts`, настроенные в `package.json`, например:

- `bun run dev`

А для сборки:

- `bun run build`

Использовать Bun очень похоже на NPM, Yarn, PNPM и т. д., только он гораздо быстрее и в целом лучше. Кроме того, при развёртывании в тестовых и производственных средах он позволяет достичь высокой производительности: развёртывание завершается быстро и в целом эффективнее.

### Встроенные команды в Netuno

Со стороны Netuno это обеспечено централизацией терминала, где все команды проекта выполняются вместе в одном процессе и терминале Netuno.

- [Подробнее о централизованном терминале.](/docs/academy/explore/centralized-terminal)

Если вы уже интегрировали и используете выполнение команд NPM, необходимо перейти на Bun.

Измените на Bun в настройке `commands` приложения Netuno в `📂 config/_development.json`, например:

```json title="config/_development.json"
{
    ...
    "commands": [
        ...
        {
            "path": "website",
            "command": "bun run dev",
            "install": "bun install",
            "enabled": true
        }
    ]
    ...
}
```

## Заключение

Больше не страдайте из-за нехватки места, вызванной множеством копий зависимостей в папках `📂 node_modules`, которые занимают гигабайты.

И не ждите так долго, пока ваш проект наконец установит зависимости, запустится или соберётся.

Ничто не мешает использовать Bun, потому что он обеспечивает совместимость с NodeJS и NPM — это буквально два в одном.

В проектах с Netuno мы используем и переводим всё на **Bun**, следите за этой тенденцией.
