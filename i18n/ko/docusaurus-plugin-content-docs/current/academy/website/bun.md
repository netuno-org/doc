## 소개

NodeJS와 NPM은 프런트엔드 개발 생태계를 정의하는 기반입니다.

유용성에도 불구하고 각각의 성능은 매우 아쉬운 수준입니다.

따라서 빠른 적응의 용이함과 호환성 유지를 바탕으로 크고 체감 가능한 이점을 얻기 위해 Bun 사용을 권장합니다.

Netuno에서는 점점 더 Bun을 사용하고 있습니다. 그 이유를 살펴보세요...

## Bun

Bun은 NodeJS와 동등하지만 훨씬 강력하고 현대적이며 직관적이고 매우 빠릅니다.

Bun의 성능은 의심할 여지가 없습니다. NodeJS 실행에서 Bun으로 전환한 사람은 그 이점을 즉시 느낄 수 있습니다.

프런트엔드 프로젝트는 보통 시작하는 데 시간이 걸리지만, Bun에서는 초기화가 즉시 이루어집니다.

또한 프런트엔드 의존성은 보통 많은 공간을 차지하며, `📂 node_modules` 폴더는 쉽게 수백 메가바이트 또는 기가바이트에 이를 수 있습니다.

Bun은 여러 프로젝트에 걸친 의존성 복제로 인한 공간 낭비 문제도 해결합니다.

모든 프로젝트가 공유하는 중앙 의존성 저장소를 만들고, 설치 시 링크된 폴더를 구성합니다.

따라서 의존성이 차지하는 공간 소비를 크게 줄입니다.

> 다양한 다른 이점들 중에서도 사용성과 더욱 향상되고 직관적이며 전반적으로 더 발전된 출력이 특히 돋보입니다.

성능상의 이점은 민첩한 개발에 매우 중요하므로 사용을 권장합니다.

Bun을 설치하려면 다음 단계를 따르세요:

- [**Bun 설치**](https://bun.sh/docs/installation)

### 프로젝트에서의 사용

프로젝트에서 Bun을 사용하려면 이미 NPM, Yarn 또는 다른 도구를 사용 중인 경우 `📂 node_modules` 폴더를 제거해야 합니다.

`package.json` 파일이 있는 위치에서 의존성 설치 명령을 실행해야 합니다:

- `bun install`

이제 `package.json`에 구성된 `scripts` 작업을 실행하면 됩니다. 예를 들어:

- `bun run dev`

그리고 컴파일하려면:

- `bun run build`

Bun 사용은 NPM, Yarn, PNPM 등과 매우 유사하지만, 훨씬 빠르고 전반적으로 더 좋습니다. 또한 테스트 및 운영 환경으로의 배포에서도 높은 성능을 얻고 배포를 빠르게 완료할 수 있으며 전반적으로 더 효율적입니다.

### Netuno에 통합된 명령어

Netuno 측에서는 터미널 중앙 집중화를 통해 프로젝트의 모든 명령이 Netuno의 동일한 프로세스와 터미널에서 함께 실행됩니다.

- [중앙 집중식 터미널에 대해 더 알아보기.](/docs/academy/explore/centralized-terminal)

NPM 명령 실행을 통합하여 사용 중인 경우 Bun으로 변경해야 합니다.

Netuno 애플리케이션의 `📂 config/_development.json`에서 `commands` 구성의 Bun으로 변경하세요. 예를 들어:

```json title="config/_development.json"
{
    ...
    "commands": [
        ...
        {
            "path": "웹사이트",
            "command": "bun run dev",
            "install": "bun install",
            "enabled": true
        }
    ]
    ...
}
```

## 결론

`📂 node_modules` 폴더 안에 여러 의존성 복제본이 기가바이트를 낭비하는 공간 부족 문제로 더 이상 고통받지 마세요.

그리고 프로젝트가 마침내 의존성을 설치하고 시작하거나 컴파일할 때까지 그렇게 오래 기다리지도 마세요.

Bun 사용을 막을 이유는 없습니다. NodeJS 및 NPM과의 호환성을 보장하며, 말 그대로 둘을 하나로 합친 것입니다.

Netuno가 적용된 프로젝트에서는 Bun을 사용하고 모든 것을 **Bun**으로 마이그레이션하고 있습니다. 이 흐름을 따라가세요.
