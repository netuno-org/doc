Netuno에는 로우코드 방식으로 REST API를 만들기 위한 자체 프레임워크가 있으며, JWT(JSON Web Token)와 OpenAPI 3.0을 지원합니다.

Netuno에서 웹 서비스 개발을 위한 프레임워크는 매우 유연하여 모든 유형의 개발을 수행할 수 있습니다.

이 프레임워크는 이미 로우코드 개발을 위한 많은 기능을 제공하여 메일 전송, 다른 REST API 소비, 다른 데이터베이스와의 통합, PDF 및 Excel 파일 생성, SMS 전송, 데이터베이스 데이터 조작 등과 같은 가장 일반적인 요구 사항을 구현하는 데 필요한 많은 코드 라인을 절약합니다.

그리고 Netuno 프레임워크에 솔루션이 없는 경우에는 기존 Java, Kotlin 또는 JavaScript 라이브러리를 쉽게 통합하여 맞춤형 리소스를 개발하고 Netuno 프레임워크와 통합할 수 있습니다.

## JWT - JSON Web Token

[JWT.io](https://jwt.io/)는 JSON 객체를 통해 세션 컨텍스트의 데이터를 클라이언트로 전달하기 위한 표준 명세입니다.

따라서 서버는 로그인한 사용자의 민감한 데이터를 세션에 저장할 필요가 없으며, 대신 클라이언트로 전달되는 토큰이 되고 이후 각 요청마다 이 토큰을 반환해야 합니다.

이 토큰에는 유효 기간 제한과 새로운 인증을 요구하지 않고 새 토큰을 생성할 수 있게 하는 프로세스 등 몇 가지 보안 제어가 적용됩니다.

Netuno는 JWT 지원을 통합하고 있으며 간단하고 쉽게 사용할 수 있고, Netuno의 기본 사용자 및 인증과도 통합되어 작동합니다.

## OpenAPI 3.0

Swagger v1 및 v2는 이미 오래전부터 웹 서비스 정의 개발과 클라이언트 코드 생성을 위한 표준이 되었으며, 그 성공 이후

이에 따라 Swagger는 정의를 개방하고 [OpenAPI 3](https://www.openapis.org/)가 되었습니다.

이는 API 문서화 방식과 API를 소비할 클라이언트 생성 방식의 표준을 정의하는 기반으로 계속 사용되고 있습니다.

Netuno는 이미 OpenAPI 3.0과의 모든 통합을 제공하며, OpenAPI 정의와 [JSON Schema](https://json-schema.org/) 검증을 함께 사용합니다.

즉, Netuno는 웹 서비스의 입력과 출력도 검증할 수 있으며, 수신하고 반환되는 JSON의 스키마 검증을 통해 다음과 같이 처리합니다:

- `입력`: 웹 서비스 호출이 구조와 검증을 충족하지 않으면 거부됩니다
- `출력`: 정의된 구조와 검증을 충족하지 않는 데이터를 반환하면 웹 서비스가 규정을 준수하지 않는다는 경고가 생성됩니다.

따라서 Netuno는 수신 데이터 검증을 위해 코드에 많은 `if`문을 작성할 필요를 줄여 줄 뿐만 아니라, 웹 서비스가 생성하는 결과에 대한 검증까지 보장하여 _단위 테스트_를 수행합니다.

또한 Netuno가 생성한 OpenAPI 구조는 [Swagger 편집기](https://editor.swagger.io/)와 함께 사용하여 테스트 인터페이스, 문서 및 다른 기술의 API 클라이언트용 코드를 생성할 수 있습니다.

## 기본

Netuno는 또한 복잡한 절차 없이 웹 서비스와 인증 생성을 지원합니다. 즉, JWT 또는 OpenAPI 사용이 필수는 아니지만 기본 권장 사항입니다.

API 생성을 신속하게 진행하기 위해 또는 서버 간 통신이 관련된 상황에서는 최대한 단순화하여 시간을 절약하는 경우가 많습니다.

> Netuno는 [HTTP 인증](https://developer.mozilla.org/pt-BR/docs/Web/HTTP/Authentication)을 수행할 수 있습니다.
