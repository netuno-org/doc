API로 파일을 전송하고 폴더나 데이터베이스에 저장합니다.

## 소개

API REST 서비스로 파일을 전송해야 할 때 Netuno에서는 이 개발을 수행하는 여러 가지 방법이 있습니다.

일반적으로 파일은 multipart 형식으로 구조화된 HTTP 요청 본문으로 전송되며, 이는 프런트엔드에서 가장 흔한 절차입니다. 예를 들어 양식을 작성할 때 파일을 선택하는 필드가 있는 경우입니다.

대안으로, 100% JSON인 API REST를 원할 때 파일 바이트를 Base64로 인코딩하여 JSON 객체의 값으로 전송할 수 있습니다.

## 파일

`_req.file`을 통해 필드 이름을 전달하여 전송된 파일 객체를 얻을 수 있습니다. 다음과 같습니다:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const 내파일 = _req.file("파일");
            `
        },
    ]}
/>

즉, `_req`에는 HTTP 요청 본문에서 받은 모든 데이터가 있습니다.

그리고 `file` 메서드를 통해 전송된 파일을 나타내는 객체를 얻을 수 있습니다.

파일이 없으면 얻은 값은 `null`일 수 있습니다.

## JSON에서 Base64 사용

서비스로 전송되는 JSON에서 파일을 업로드하려면 다음과 같은 값을 가진 속성을 정의할 수 있습니다:

`data:image/png;base64,...`

여기서 `...`에는 Base64로 인코딩된 파일 바이트 시퀀스가 이어집니다.

파일 유형은 `data` 뒤에 오며, 예를 들면 다음과 같습니다:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### 객체

파일이 하위 객체 내부의 JSON 내부 구조에 있는 경우:

```json
{
  "사람": {
    "파일": "data:image/png;base64,..."
  }
}
```

다음과 같이 얻을 수 있습니다:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const 내파일 = _req.getValues("사람").getFile("아바타");
            `
        },
    ]}
/>

### 배열

파일이 배열 내부의 JSON 내부 구조에 있는 경우:

```json
{
  "파일들": [
    "data:image/png;base64,..."
  ]
}
```

다음과 같이 얻을 수 있습니다:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const 내파일 = _req.getValues("파일들").getFile(0);
            `
        },
    ]}
/>

## OpenAPI

Netuno는 OpenAPI와의 통합을 지원하며 OpenAPI 정의를 사용하여 HTTP 요청을 검증합니다.

> [Netuno의 OpenAPI](/docs/academy/server/services/openapi)에 대해 더 알아보십시오.

`file` 유형을 사용하면 Netuno는 값이 JSON의 파일 형식으로 시작하는지 검증합니다. 예를 들면 다음과 같습니다:

- `data:image/png;base64,...`

JSON 객체의 속성에서 파일을 수신하는지 검증하려면:

```json title="post.in.json"
{
  "summary": "파일 업로드",
  "description": "JSON 객체에서 파일을 수신하는 서비스.",
  "type": "object",
  "properties": {
    "파일": {
      "type": "file"
    }
  },
  "required": [
    "파일"
  ]
}
```

JSON 배열에서 파일 목록을 수신하는지 검증하려면:

```json title="post.in.json"
{
  "summary": "파일 업로드",
  "description": "JSON 배열에서 파일 목록을 수신하는 서비스.",
  "properties": {
    "파일들": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "파일들"
  ]
}
```

## 파일 저장

일반적으로 서비스에서 파일을 받으면 이를 저장해야 합니다. 예를 들면 다음과 같습니다:

- **데이터베이스**: 사용자와 같은 레코드에 관련된 파일.
- **스토리지**: 일반적으로 파일을 관리하는 애플리케이션 내부 폴더.
- **폴더**: 시스템의 임의 폴더에 파일을 넣습니다.

### 데이터베이스

양식 필드 관리에서 Netuno는 `image` 및 `file` 유형을 지원합니다:

- **Image**: 일반적인 이미지 파일, JPG 및 PNG.
- **File**: 모든 유형의 파일.

상품 양식에 이미지 필드가 있다고 가정하면, 업로드로 전송된 파일을 다음과 같이 저장할 수 있습니다:

#### DB Form을 사용하는 예:

`_db.form` 사용에 주목하십시오:

                        _val.map()
                            .set("이미지", 상품이미지)
                    )
                )

                if db결과 == 1:

                        _val.map()
                            .set("결과", True)

                else:
                    _header.status(404)
                    _out.json(

                            .set("결과", False)
                            .set("오류", "uid-상품-없음")
                    )
            `
        },
        {
            lang: 'ruby',
            code: `

                  _header.status = 400
                  _out.json(
                    _val.map()
                      .set("결과", false)

#### 데이터베이스에서 파일 다운로드

저장된 파일을 표시하려면 파일 바이트를 제공하는 서비스를 만들어야 합니다.

위 예처럼 데이터베이스에 저장된 파일의 경우, 파일 자체는 애플리케이션의 스토리지에 저장되고 데이터베이스에는 최종 파일 이름만 저장됩니다.

> 애플리케이션의 스토리지는 일반 파일 구조를 저장하고 구성하기 위한 폴더입니다.

따라서 위 예에서 `상품` 양식과 `이미지` 필드의 데이터베이스 파일은 다음에 저장됩니다:

- `storage/database/상품/이미지/*`

> Netuno는 파일 이름 중복을 피하기 위해 저장된 파일 이름을 자동으로 관리합니다.

파일을 얻으려면 예를 들어 상품 이미지 파일을 표시하는 서비스를 만들 수 있습니다:

### 스토리지

애플리케이션의 `storage`에 파일을 직접 저장할 수 있습니다.

데이터베이스 파일과 섞지 않기 위해, 데이터베이스에 연결되지 않은 일반 파일을 저장하는 것을 목적으로 하는 `filesystem` 폴더를 사용해야 합니다.

파일을 받기 위해, 이 예에서는 `POST` 서비스로 전송된 파일이 스토리지에 직접 저장되는 방법을 보여줍니다:

<PolyglotCode
    file="services/파일/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const 파일 = _req.getFile("파일");
                _storage.filesystem("서버", "업로드").ensurePath();
                파일.save(_storage.filesystem("서버", "업로드", 파일.name()));
            `
        },
    ]}
/>

파일은 애플리케이션의 `storage` 폴더에 다음 위치로 저장됩니다:

- `storage/filesystem/서버/업로드/*`

> [Storage](/docs/library/resources/storage) 리소스는 폴더 및 파일 경로를 얻는 데 사용됩니다:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "서버", // filesystem 내 하위 폴더 이름.
                    "업로드", // 내부 하위 폴더 이름 또는 경로.
                    파일.name() // 최종 파일 이름.
                );
            `
        },
    ]}
/>

> [Storage](/docs/library/resources/storage) 문서에서 더 알아보십시오.

파일을 다운로드하기 위해, 이 예에서는 `GET` 서비스를 통해 파일 바이트를 얻는 방법을 보여줍니다:

### 폴더

컴퓨터의 임의 폴더에 파일을 직접 저장할 수 있습니다.

이러한 경우 매우 유용한 두 가지 리소스가 있습니다:

- `_app` - 애플리케이션의 모든 폴더나 파일을 가져올 수 있습니다.
- `_os` - 컴퓨터의 모든 폴더나 파일을 가져올 수 있습니다.

> 각각의 리소스 [App](/docs/library/resources/app) 및 [OS](/docs/library/resources/os) 문서를 참조하십시오. 두 리소스 모두 `folder` 및 `file` 메서드가 있으며, 이를 통해 각각 폴더 또는 파일 경로를 지정할 수 있습니다.

파일을 받기 위해, 이 예에서는 `POST` 서비스로 전송된 파일이 애플리케이션의 폴더에 직접 저장되는 방법을 보여줍니다:

## 결론

살펴본 것처럼 API REST 서비스에 파일 업로드를 통합할 수 있으며, OpenAPI와도 통합할 수 있습니다.

파일을 데이터베이스, 애플리케이션의 `storage` 폴더 또는 컴퓨터의 임의 폴더에 저장할 수 있습니다.

파일을 조작할 수 있도록 이 튜토리얼에서 사용한 리소스 문서를 참조하십시오:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

데이터베이스에서는 `image` 유형 필드에 이미지를 저장할 수 있고, `file` 유형 필드에 모든 유형의 파일을 저장할 수 있습니다. 파일을 저장하거나 얻는 방법은 이미지든 일반 파일이든 모든 경우에 동일합니다.
