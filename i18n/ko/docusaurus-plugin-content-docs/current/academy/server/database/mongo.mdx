## 소개

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a>는 문서 지향 NoSQL 데이터베이스입니다. 테이블과 행 대신 데이터는 JSON과 유사한 형식의 문서에 저장되므로 데이터 모델에 큰 유연성을 제공합니다.

Netuno는 MongoDB와의 통합을 위해 [_mongo](/docs/library/resources/mongo) 리소스를 제공합니다. 이 리소스는 Java용 공식 MongoDB 클라이언트 위에 로우코드 추상화를 제공하며, Netuno가 지원하는 다양한 프로그래밍 언어에서 사용할 수 있습니다: **JavaScript, Python, Ruby, Kotlin, Groovy**.

> 시작하기 전에 Netuno에서 서비스를 만드는 방법을 아는 것이 좋습니다. [REST - 웹 서비스](/docs/academy/server/services/rest) 튜토리얼을 참고하세요.

여기에 제시된 작업의 구현 예시는 다음 위치에 있는 예제 서비스 `mongo.js`에서 확인할 수 있습니다:

## MongoDB 설치

### Docker 사용

Docker가 설치되어 있다고 가정하면, MongoDB 이미지를 다운로드하고 새 컨테이너를 시작하기만 하면 됩니다:

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

이렇게 하면 MongoDB가 인증 없이 `localhost:27017`에서 접근 가능합니다.

애플리케이션 설정에 맞게 데이터베이스 사용자를 생성하려면 다음을 실행하세요:

```shell
docker exec -it mongo mongosh 상품_db --eval 'db.createUser({ user: "상품_사용자", pwd: "12345678", roles: [{ role: "readWrite", db: "상품_db" }] })'
```

### Ubuntu 사용

MongoDB는 Ubuntu 공식 저장소에 포함되어 있지 않으므로 설치 전에 공식 저장소를 추가해야 합니다:

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

설치 후 다음 명령으로 서비스를 시작할 수 있습니다:

```shell
sudo systemctl start mongod
```

### Windows 사용

- <a href="https://www.mongodb.com/try/download/community" target="_blank">MongoDB Community Server 다운로드</a>.

다운로드한 설치 프로그램을 실행하고 **Service Configuration** 단계에서 **Install MongoD as a Service**를 활성화하여 MongoDB가 자동으로 시작되도록 하세요. MongoDB는 인증 없이 `localhost:27017`에서 접근 가능합니다.

> 다른 배포판과 버전은 [MongoDB 공식 문서](https://www.mongodb.com/docs/manual/installation/)를 참고하세요.

## 애플리케이션 설정

MongoDB 연결 설정은 환경에 따라 애플리케이션 설정 파일에서 구성합니다:

- `config/_development.json`

> 애플리케이션의 [설정 파일](/docs/academy/explore/configuration)에 대해 더 알아보세요.

설정 파일 안에 `mongo` 블록을 추가하고, 각 키가 하나의 연결을 식별하도록 합니다:

```javascript
{
    ...
    "mongo": {
        "매장": "mongodb://매장_사용자:12345678@localhost/매장_db",
        "상품": {
            "username": "상품_사용자",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "상품_db"
        }
    },
    ...
}
```

연결은 두 가지 방식으로 정의할 수 있습니다:

- **연결 URL** — 값은 단순한 문자열입니다. 예: `"mongodb://매장_사용자:12345678@localhost/매장_db"`.
- **설정 객체** — 다음 필드를 사용합니다:
  - `url` — 정의된 경우 연결 URL로 직접 사용되며 다른 필드는 무시됩니다.
  - `protocol` — 연결 프로토콜, 기본값 `mongodb`.
  - `username`과 `password` — 접근 자격 증명.
  - `host` — 서버 주소, 기본값 `localhost`.
  - `port` — 연결 포트, 기본값 `27017`.
  - `database` — 데이터베이스 이름, 기본값은 연결 키의 이름.
  - `params` — URL에 추가되는 연결 매개변수, 예: `{ "authSource": "admin" }`. 객체 필드로 URL을 구성할 때만 적용됩니다.

> 연결이 애플리케이션의 주 데이터베이스일 필요는 없습니다. `db` 설정과 달리 `mongo` 블록은 독립적이며 여러 연결을 동시에 허용합니다.

### 필터

`_mongo.filters()` 팩토리는 MongoDB의 주요 쿼리 연산자를 제공합니다:

| 연산자 | 설명 |
|---|---|
| `eq("필드", 값)` | 값과 같습니다. |
| `ne("필드", 값)` | 값과 다릅니다. |
| `gt("필드", 값)` | 값보다 큽니다. |
| `gte("필드", 값)` | 값보다 크거나 같습니다. |
| `lt("필드", 값)` | 값보다 작습니다. |
| `lte("필드", 값)` | 값보다 작거나 같습니다. |
| `in("필드", 값1, 값2, ...)` | 값 중 하나와 같습니다. |
| `nin("필드", 값1, 값2, ...)` | 모든 값과 다릅니다. |
| `and(필터1, 필터2, ...)` | 모든 필터와 일치합니다. |
| `or(필터1, 필터2, ...)` | 필터 중 하나 이상과 일치합니다. |
| `not(필터)` | 필터와 일치하지 않습니다. |
| `regex("필드", "패턴")` | 정규 표현식과 일치합니다. |
| `exists("필드")` | 문서에 해당 필드가 존재합니다. |
| `text("검색")` | 텍스트 검색입니다. |
| `type("필드", "유형")` | 필드가 지정된 유형입니다. |
| `mod("필드", 제수, 나머지)` | 필드를 제수로 나눈 나머지가 지정된 값과 같습니다. |
| `where("표현식")` | JavaScript 표현식을 만족하는 문서와 일치합니다. 예: `"this.가격 > 100"`. |
| `size("필드", n)` | 배열 필드에 정확히 `n`개의 요소가 있습니다. |

## 집계

더 고급 분석을 위해 `aggregate()`로 집계 파이프라인을 실행할 수 있으며, 각 단계는 `_mongo.aggregates()` 팩토리로, 누적기는 `_mongo.accumulators()`로 정의합니다.

예를 들어 제품을 카테고리별로 그룹화하고 각 그룹의 가격을 합산하려면:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const 문서들 = 컬렉션.aggregate(
                    _mongo.aggregates().match(
                        _mongo.filters().eq("카테고리", "컴퓨터")
                    ),
                    _mongo.aggregates().group(
                        "$카테고리",
                        _mongo.accumulators().sum("합계", "$가격")
                    ),
                    _mongo.aggregates().sort(
                        _mongo.sorts().descending("합계")
                    )
                ).all()
            `
        },
        {
            lang: 'python',
            code: `

                        "$카테고리",
                        _mongo.accumulators().sum("합계", "$가격")
                    ),
                    _mongo.aggregates().sort(
                        _mongo.sorts().descending("합계")
                    )
                ).all()
            `
        },
        {
            lang: 'ruby',
            code: `
                문서들 = 컬렉션.aggregate(
                    _mongo.aggregates().match(
                        _mongo.filters().eq("카테고리", "컴퓨터")
                    ),
                    _mongo.aggregates().group(
                        "$카테고리",

                    )

사용 가능한 집계 단계는 다음과 같습니다:

| 단계 | 설명 |
|---|---|
| `match(필터)` | 필터와 일치하는 문서만 선택합니다. |
| `group("$필드", 누적기)` | 필드를 기준으로 문서를 그룹화하고 누적기를 적용합니다. |
| `project(프로젝션)` | 문서의 필드를 추가, 제거 또는 변경합니다. |
| `sort(정렬)` | 문서를 정렬합니다. |
| `limit(n)` | 처음 `n`개 문서로 제한합니다. |
| `skip(n)` | 처음 `n`개 문서를 건너뜁니다. |
| `count()` | 문서 수를 셉니다. |
| `lookup("컬렉션", "로컬필드", "외래필드", "별칭")` | 다른 컬렉션과 조인을 수행합니다. |

그리고 가장 많이 사용되는 누적기는 다음과 같습니다:

| 누적기 | 설명 |
|---|---|
| `sum("필드", "$표현식")` | 값의 합계입니다. |
| `avg("필드", "$표현식")` | 값의 평균입니다. |
| `min("필드", "$표현식")` | 최솟값입니다. |
| `max("필드", "$표현식")` | 최댓값입니다. |
| `first("필드", "$표현식")` | 첫 번째 문서의 값입니다. |
| `last("필드", "$표현식")` | 마지막 문서의 값입니다. |
| `top("필드", 정렬, "$표현식")` | 정렬에 따른 상위 값입니다. |
| `bottom("필드", 정렬, "$표현식")` | 정렬에 따른 하위 값입니다. |

> 누적기에서 `$` 접두사가 붙은 표현식은 입력 문서의 필드를 참조합니다. 예: `"$가격"`.

## 옵션을 사용하는 작업

`_mongo` 리소스의 `*Options()` 팩토리는 MongoDB 드라이버의 기본 옵션 객체를 반환하며, 해당 메서드를 직접 체이닝할 수 있습니다. 예를 들어 `upsert(true)`는 필터와 일치하는 기존 문서가 없을 때 문서를 삽입합니다:

                    _mongo.filters().eq("이름", "모니터"),
                    _mongo.updates().set("수량", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'python',
            code: `
                이전문서 = 컬렉션.findOneAndUpdate(
                    _mongo.filters().eq("이름", "모니터"),
                    _mongo.updates().set("수량", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'ruby',
            code: `
                이전문서 = 컬렉션.findOneAndUpdate(
                    _mongo.filters().eq("이름", "모니터"),
                    _mongo.updates().set("수량", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'kotlin',
            code: `
                val 이전문서 = 컬렉션.findOneAndUpdate(
                    _mongo.filters().eq("이름", "모니터"),
                    _mongo.updates().set("수량", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },

            lang: 'groovy',
            code: `
                def 이전문서 = 컬렉션.findOneAndUpdate(
                    _mongo.filters().eq("이름", "모니터"),

사용 가능한 옵션 팩토리는 다음과 같습니다: `insertOneOptions()`, `insertManyOptions()`, `updateOptions()`, `findOneAndUpdateOptions()`, `replaceOptions()`, `findOneAndReplaceOptions()`, `deleteOptions()`, `findOneAndDeleteOptions()`, `countOptions()`, `estimatedDocumentCountOptions()`, `dropCollectionOptions()`, `textSearchOptions()`.
