Netuno를 사용하면 여러 명령과 프로세스의 데이터 출력(로그)을 단일 터미널 창, 즉 기본 서버가 실행 중인 동일한 창으로 통합할 수 있습니다.

여러 기술을 동시에 다루는 것이 일반적인 현대 개발 흐름에서 Netuno는 로그 오케스트레이터 역할을 하며, ReactJS, Angular, Vue 및 기타 모든 프런트엔드 프로세스처럼 자동으로 병렬 시작되도록 구성된 여러 명령을 포함할 수 있습니다.

> 어떤 프로세스든 시작할 수 있으며, 명령만 정의하면 됩니다. 예를 들어 다른 기술로 개발된 보조 REST API 서버도 통합할 수 있습니다.


## 구성

외부 프로세스를 통합하려면 애플리케이션의 환경 구성 파일을 편집해야 합니다. 이 가이드에서는 개발 환경을 예로 사용합니다.

### 파일 위치

애플리케이션 폴더로 이동하여 다음 파일을 찾으세요:

- 📂 `config/_development.json`

### 구성 구조


구성은 객체 배열로 이루어진 "commands" 키를 통해 수행됩니다. 이를 통해 여러 서비스를 병렬로 실행할 수 있습니다.

파일을 열고 `"commands"` 키가 이미 있는지 확인하세요. 없다면 JSON 형식을 준수하여 파일 끝에 아래 구성을 추가하세요:

```json
{
    ...
    "commands": [
        {
            "path": "ui",
            "command": "bun run watch",
            "enabled": true
        },
        {
            "env": [ "PORT=21030", "WDS_SOCKET_PORT=21030" ],
            "path": "웹사이트",
            "install": "bun install",
            "command": "bun run dev",
            "enabled": true
        }
    ],
    ...
}
```

> **참고:** 위 예시에서는 "ui" 폴더용 명령과 "웹사이트" 폴더용 명령을 구성했으며, 둘 다 bun 패키지 관리자를 사용합니다.

### 매개변수 참조

**사용자 인터페이스(UI):** 애플리케이션의 `ui` 디렉터리 안에서 `bun run watch`를 실행합니다.

**웹사이트:** `웹사이트` 폴더 안에서 `bun run dev`를 실행합니다.

### env

프로세스를 실행하는 데 필요한 환경 변수를 정의합니다. 여러 변수를 동시에 정의할 수 있습니다.

### path

명령이 실행될 폴더 경로를 애플리케이션 루트 기준으로 정의합니다.

### install

Netuno에는 패키지 의존성 관리를 위한 내장 스마트 기능이 있습니다:

- **자동 감지:** 명령이 `npm`, `bun`, `pnpm` 또는 `yarn`으로 시작하면 Netuno가 `node_modules` 폴더가 있는지 확인합니다.

- **스마트 실행:** 폴더가 없으면 해당 설치 명령(예: `bun install`)이 기본 프로세스를 시작하기 전에 자동으로 실행됩니다.

- **사용자 지정:** `install` 매개변수를 수동으로 정의하면 기본 감지 대신 사용자 지정 구성이 사용됩니다.

### command

실행할 기본 명령입니다. 모든 데이터 출력(`output`)이 Netuno와 통합됩니다.

### enabled

애플리케이션과 함께 명령을 자동으로 시작할지(true) 여부(false)를 정의합니다.

## 결론

Netuno에서 명령을 중앙 집중화하면 작업 흐름이 크게 단순해집니다.
통합된 가시성을 통해 병렬 프로세스의 모든 정보를 단일 터미널에 모아 실시간 모니터링이 쉬워집니다.

안전한 종료 기능 덕분에 Netuno 서버 실행을 중지하면 구성된 모든 보조 프로세스도 자동으로 종료되어 "백그라운드" 프로세스나 포트 충돌을 방지합니다.
