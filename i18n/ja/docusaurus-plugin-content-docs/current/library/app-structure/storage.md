コードまたはデータベースに統合されたファイル。

## 一般的なストレージ

`📂 storage` フォルダは、アプリケーションの処理に役立つ一般的なファイルを安全に保存するためのものです。

## フォルダ構造

`📂 storage` フォルダには次の構造があります。

<pre class="doc-structure__tree">
<span>./<b>storage</b>/</span>
&nbsp;<span>├─ ./<b>database</b>/</span>
&nbsp;<span>└─ ./<b>filesystem</b>/</span>
&nbsp;    <span>├─ ./<b>private</b>/</span>
&nbsp;    <span>├─ ./<b>public</b>/</span>
&nbsp;    <span>└─ ./<b>server</b>/</span>
</pre>

## データベース

`📂 database` フォルダは、データベースに関連するファイルや画像を保存するために使用されます。

ファイルをデータベースに直接保存することは実用的ではありません。バックアップやデータ同期に悪影響を及ぼし、一般に多くのファイルが占める容量によってデータベースのサイズが大幅に増加するためです。

そのため、ファイルや画像のアップロード項目を持つデータフォームでは、最終的なファイルはここに整理して保存され、データベースの項目には最終的なファイル名だけが保存されます。

データ構造にファイルが含まれる場合、アプリケーション全体のバックアップを行うには、データベースのバックアップに加えてこのフォルダのバックアップも必要です。

## 一般的なファイルシステム

`📂 filesystem` フォルダでは、アプリケーションに役立つ一般的なファイルをアクセス制限付きで整理できます。

アプリケーションのコードで直接役立つファイルはすべてここに保存する必要があります。

制限は次のように分かれています。

### プライベート

`📂 private` フォルダは、アプリケーションで認証されたユーザーだけが読み取りまたは書き込みのためにアクセスできます。

### パブリック

`📂 public` フォルダは外部アクセスに役立ちます。

### サーバー

`📂 server` フォルダは、アプリケーションの内部コードからの読み取りと書き込みのみを許可します。

したがって、内部または外部のどのユーザーもその内容にアクセスできません。

その内容はコードを通じてのみアクセス可能です。
