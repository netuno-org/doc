## はじめに

NodeJSとNPMは、フロントエンド開発のエコシステムを定義する基盤です。

その有用性にもかかわらず、それぞれのパフォーマンスは非常に物足りないものです。

そのため、迅速な適応の容易さと互換性を維持しながら、有意義で実感できるメリットを得るためにBunの使用を推奨します。

NetunoではますますBunが使用されています。その理由を見てみましょう...

## Bun

BunはNodeJSと同等ですが、はるかにパワーアップされ、現代的で直感的、そして超高速です。

Bunのパフォーマンスは疑いの余地がありません。NodeJSの実行からBunに移行した人は、そのメリットにすぐに気づきます。

フロントエンドプロジェクトは起動に時間がかかることがよくありますが、Bunでは起動は即座です。

また、フロントエンドの依存関係は多くのスペースを占めることが多く、`📂 node_modules`フォルダは簡単に数百メガバイト、あるいはギガバイトに達することがあります。

Bunは、複数のプロジェクトによる依存関係のコピーの複製で無駄になるスペースの問題も解決します。

すべてのプロジェクトで共有される依存関係の中央リポジトリを作成し、インストール時にリンクされたフォルダを設定します。

これにより、依存関係が占めるスペースの消費を大幅に削減します。

> その他多くの利点の中でも、使いやすさと、洗練され直感的で全体的により進化した出力が際立っています。

パフォーマンス上の利点はアジャイル開発にとって極めて重要であるため、その使用を推奨します。

Bunをインストールするには、次の手順に従ってください：

- [**Bunのインストール**](https://bun.sh/docs/installation)

### プロジェクトでの使用

プロジェクトでBunを使用するには、すでにNPM、Yarn、またはその他を使用している場合は、`📂 node_modules`フォルダを削除する必要があることを確認してください。

`package.json`ファイルがある場所で、依存関係をインストールするコマンドを実行する必要があります：

- `bun install`

あとは、`package.json`で設定された`scripts`のアクションを実行するだけです。例えば：

- `bun run dev`

コンパイルするには：

- `bun run build`

Bunの使用はNPM、Yarn、PNPMなどと非常によく似ていますが、全体的にはるかに高速で優れています。さらに、テスト環境や本番環境へのデプロイでも、高いパフォーマンスを得ながらデプロイを迅速に完了でき、全体的により効率的です。

### Netunoに統合されたコマンド

Netuno側ではターミナルの集中化により、プロジェクトのすべてのコマンドがNetunoの同じプロセスとターミナルで一緒に実行されます。

- [集中化ターミナルの詳細。](/docs/academy/explore/centralized-terminal)

NPMのコマンド実行を統合して使用している場合は、Bunに変更する必要があります。

Netunoアプリケーションの`📂 config/_development.json`にある`commands`設定でBunに変更します。例えば：

```json title="config/_development.json"
{
    ...
    "commands": [
        ...
        {
            "path": "website",
            "command": "bun run dev",
            "install": "bun install",
            "enabled": true
        }
    ]
    ...
}
```

## まとめ

もう`📂 node_modules`フォルダ内の複数の依存関係のレプリカでギガバイトを無駄にし、スペース不足に悩まないでください。

また、プロジェクトが依存関係をインストールし、起動し、コンパイルするまで長く待つ必要もありません。

Bunの使用を妨げるものは何もありません。NodeJSとNPMとの互換性を保証し、文字通り2つを1つにしたものです。

Netunoのプロジェクトでは、私たちは**Bun**を使用し、すべてを**Bun**に移行しています。このトレンドに追随してください。
