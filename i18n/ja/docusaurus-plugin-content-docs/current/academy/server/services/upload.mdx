APIにファイルを送信し、フォルダまたはデータベースに保存します。

## はじめに

REST APIのサービスにファイルを送信する必要がある場合、Netunoではこの開発を行うためのさまざまな方法があります。

通常、ファイルはmultipart形式で構造化されたHTTPリクエストのボディで送信されます。これはフロントエンドで最も一般的な手順であり、たとえばフォームに記入してファイルを選択するフィールドがある場合などです。

あるいは、100% JSONのREST APIを実現したい場合、Base64でエンコードされたファイルのバイトをJSONオブジェクトの値として送信することもできます。

## ファイル

`_req.file`を通じてフィールド名を渡すことで、送信されたファイルのオブジェクトを取得できます。次のようにします：

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.file("file");
            `
        },
    ]}
/>

つまり、`_req`にはHTTPリクエストのボディで受け取ったすべてのデータが含まれています。

そして`file`メソッドを通じて、送信されたファイルを表すオブジェクトを取得できます。

ファイルが存在しない場合、取得される値は`null`になる可能性があります。

## 画像

画像を受け取る場合、統一性を確保し、画像が占めるスペースを削減するために、サイズを変更する必要がしばしばあります。

## JSONでのBase64

サービスに送信するJSONでファイルをアップロードするには、値を持つプロパティを以下のように定義できます：

`data:image/png;base64,...`

`...`にはBase64でエンコードされたファイルのバイト列が続きます。

ファイルの種類は`data`の後に続きます。たとえば：

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### オブジェクト

ファイルがJSONのサブオブジェクト内の内部構造にある場合：

```json
{
  "person": {
    "file": "data:image/png;base64,..."
  }
}
```

次のようにして取得できます：

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.getValues("person").getFile("avatar");
            `
        },
    ]}
/>

### 配列

ファイルがJSONの配列内の内部構造にある場合：

```json
{
  "files": [
    "data:image/png;base64,..."
  ]
}
```

次のようにして取得できます：

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const myFile = _req.getValues("files").getFile(0);
            `
        },
    ]}
/>

## OpenAPI

NetunoはOpenAPIとの統合をサポートしており、OpenAPIの定義を使用してHTTPリクエストを検証します。

> Netunoでの[OpenAPI](/docs/academy/server/services/openapi)の詳細についてはこちらをご覧ください。

`file`タイプを使用すると、Netunoは値がJSONのファイル形式で始まるかどうかを検証します。たとえば：

- `data:image/png;base64,...`

JSONオブジェクトのプロパティでファイルを受信していることを検証するには：

```json title="post.in.json"
{
  "summary": "ファイルのアップロード",
  "description": "JSONオブジェクトでファイルを受信するサービス。",
  "type": "object",
  "properties": {
    "file": {
      "type": "file"
    }
  },
  "required": [
    "file"
  ]
}
```

JSONの配列でファイルのリストを受信していることを検証するには：

```json title="post.in.json"
{
  "summary": "複数ファイルのアップロード",
  "description": "JSONの配列でファイルのリストを受信するサービス。",
  "properties": {
    "files": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "files"
  ]
}
```

## ファイルの保存

通常、サービスでファイルを受信したら、それを保存する必要があります。たとえば：

- **データベース**：ユーザーなどのレコードに関連するファイル。
- **ストレージ**：アプリケーションの内部フォルダで、一般的なファイルの管理に使用されます。
- **フォルダ**：システムの任意のフォルダにファイルを配置します。

### データベース

フォームのフィールド管理において、Netunoは`image`タイプと`file`タイプをサポートしています：

- **Image**：一般的な画像ファイル（JPGとPNG）。
- **File**：あらゆる種類のファイル。

商品フォームに画像フィールドがあり、アップロードで送信されたファイルを次のように保存できるとします：

#### データベースからファイルをダウンロード

保存されたファイルを表示するには、ファイルのバイトを提供するサービスを作成する必要があります。

上記の例のようにデータベースに保存されるファイルの場合、ファイル自体はアプリケーションのストレージに配置され、データベースには最終的なファイル名のみが保存されます。

> アプリケーションのストレージは、汎用的なファイル構造を保存および整理するためのフォルダです。

したがって、上記の例では、`商品`フォームと`画像`フィールドのデータベースファイルは以下に保存されます：

- `storage/database/product/image/*`

> Netunoは、ファイル名の重複を避けるために、保存されるファイルの名前を自動的に管理します。

ファイルを取得するには、たとえば商品の画像ファイルを表示するサービスを作成できます：

            # クラシックDBを使った代替：
            # dbProduct = _db.get("product", productUid)

            if dbProduct.nil?
                _header.status(404)
                _out.json(
                    _val.map()
                        .set("result", false)
                        .set("error", "product-not-found")
                )
                _exec.stop()
            end

            dbProductImageName = dbProduct.getString("image")

            storageProductImageFile = _storage.database(
                "product",
                "image",
                dbProductImageName
            )

            if storageProductImageFile.extension() == "jpg" || storageProductImageFile.extension() == "jpeg"
                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storageProductImageFile.inputStream())
        `
    },
]}
/>

ファイルを取得するために`_storage`リソース（[Storage](/docs/library/resources/storage)）が使用されていることに注目してください：

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.database(
                    "product", // フォーム/テーブル名。
                    "image", // フィールド/列名。
                    dbProductImageName // ファイル名。
                );
            `
        },
    ]}
/>

データベースにはファイル名のみが保存されており、`_storage.database`を通じてファイル自体を取得できます。

### ストレージ

アプリケーションの`storage`に直接ファイルを保存できます。

データベースのファイルと混在させないために、`filesystem`フォルダを使用する必要があります。これは、データベースに関連付けられていない汎用的なファイルを保存するためのものです。

ファイルを受信するために、この例では`POST`サービスで送信されたファイルがストレージに直接保存される方法を示します：

<PolyglotCode
    file="services/file/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const file = _req.getFile("file");
                _storage.filesystem("server", "upload").ensurePath();
                file.save(_storage.filesystem("server", "upload", file.name()));
            `
        },
    ]}
/>

ファイルはアプリケーションの`storage`フォルダ内の以下に保存されます：

- `storage/filesystem/server/upload/*`

> [Storage](/docs/library/resources/storage)リソースは、フォルダとファイルのパスを取得するために使用されます：

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "server", // filesystem内のサブフォルダ名。
                    "upload", // 内部サブフォルダの名前またはパス。
                    file.name() // ファイルの最終的な名前。
                );
            `
        },
    ]}
/>

> 詳細については[Storage](/docs/library/resources/storage)のドキュメントをご覧ください。

ファイルをダウンロードするために、この例では`GET`サービスを通じてファイルのバイトを取得する方法を示します：

### フォルダ

コンピュータの任意のフォルダに直接ファイルを保存できます。

このような場合に非常に便利な2つのリソースがあります：

- `_app` - アプリケーション内の任意のフォルダまたはファイルを取得できます。
- `_os` - コンピュータ内の任意のフォルダまたはファイルを取得できます。

> それぞれのリソース[App](/docs/library/resources/app)と[OS](/docs/library/resources/os)のドキュメントをご覧ください。どちらのリソースにも`folder`と`file`メソッドがあり、それぞれフォルダまたはファイルのパスを指定できます。

ファイルを受信するために、この例では`POST`サービスで送信されたファイルがアプリケーション内のフォルダに直接保存される方法を示します：

<PolyglotCode
    file="services/file/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const file = _req.getFile("file");
                const folder = _app.folder("temp");
                if (folder.exists() == false) {
                    folder.mkdir();
                }
                file.save(_app.file(\`temp/\${file.name()}\`));
            `
        },
        {
            lang: 'python',
            code: `
                file = _req.getFile("file")
                folder = _app.folder("temp")
                if folder.exists() == False:
                    folder.mkdir()

                file.save(_app.file(f"temp/{file.name()}"))
            `
        },
        {
            lang: 'ruby',
            code: `
                file = _req.getFile("file")
                folder = _app.folder("temp")
                if folder.exists() == false
                    folder.mkdir()
                end
                file.save(_app.file("temp/#{file.name()}"))
            `
        },
        {
            lang: 'kotlin',
            code: `

                val folder = _app.folder("temp")
                if (folder.exists() == false) {
                    folder.mkdir()
                }
                file.save(_app.file("temp/\${file.name()}"))
            `
        },
        {
            lang: 'groovy',
            code: `
                final file = _req.getFile("file")
                final folder = _app.folder("temp")
                if (folder.exists() == false) {
                    folder.mkdir()
                }
                file.save(_app.file("temp/\${file.name()}"))
            `
        },
    ]}
/>

上記のコードはアプリケーション内に`temp`フォルダを作成し、受信したファイルをそのフォルダ内に保存します。

## まとめ

ご覧のように、REST APIのサービスにファイルのアップロードを統合でき、OpenAPIとも統合できます。

ファイルはデータベースに、アプリケーションの`storage`フォルダ内に、またはコンピュータの任意のフォルダに保存できます。

このチュートリアルで使用された、ファイルを操作できるリソースのドキュメントをご覧ください：

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

データベースでは、`image`タイプのフィールドに画像を保存でき、`file`タイプのフィールドにあらゆる種類のファイルを保存できます。画像でも汎用ファイルでも、ファイルの保存や取得の方法はどの場合も同じです。
