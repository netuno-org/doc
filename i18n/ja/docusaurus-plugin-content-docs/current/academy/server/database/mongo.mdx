## はじめに

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a> はドキュメント指向の NoSQL データベースです。テーブルや行の代わりに、JSON に似た形式のドキュメントにデータを保存するため、データモデルに大きな柔軟性を持たせることができます。

Netuno は MongoDB との統合のために [_mongo](/docs/library/resources/mongo) リソースを提供しており、MongoDB 公式 Java クライアントに対するローコード抽象化として、Netuno がサポートする各種プログラミング言語で利用できます: **JavaScript、Python、Ruby、Kotlin、Groovy**。

> 先に進む前に、Netuno でサービスを作成する方法を理解しておくことをおすすめします。チュートリアル [REST - Web サービス](/docs/academy/server/services/rest) を参照してください。

ここで紹介する操作の実装例は、次の場所にあるサンプルサービス `mongo.js` で利用できます:

    `apps/demo/server/services/samples/javascript/mongo`
]} />

## MongoDB のインストール

### Docker を使用する

Docker がインストールされていると仮定して、MongoDB イメージをダウンロードし、新しいコンテナを起動するだけです:

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

これにより、MongoDB は認証なしで `localhost:27017` からアクセスできるようになります。

アプリケーションの設定に合わせてデータベースユーザーを作成するには、次を実行します:

```shell
docker exec -it mongo mongosh products_db --eval 'db.createUser({ user: "products_user", pwd: "12345678", roles: [{ role: "readWrite", db: "products_db" }] })'
```

### Ubuntu を使用する

MongoDB は Ubuntu の公式リポジトリに含まれていないため、インストール前に公式リポジトリを追加する必要があります:

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

インストール後、次のコマンドでサービスを開始できます:

```shell
sudo systemctl start mongod
```

### Windows を使用する

- <a href="https://www.mongodb.com/try/download/community" target="_blank">MongoDB Community Server をダウンロード</a>。

ダウンロードしたインストーラーを実行し、**Service Configuration** の手順で **Install MongoD as a Service** を有効にすると、MongoDB が自動的に起動します。MongoDB は認証なしで `localhost:27017` からアクセスできます。

> その他のディストリビューションやバージョンについては、[MongoDB 公式ドキュメント](https://www.mongodb.com/docs/manual/installation/) を参照してください。

## アプリケーションの設定

MongoDB 接続の設定は、環境に応じてアプリケーションの設定ファイルで行います:

- `config/_development.json`

> アプリケーションの[設定ファイル](/docs/academy/explore/configuration)について詳しくはこちらをご覧ください。

設定ファイル内に `mongo` ブロックを追加し、各キーが接続を識別します:

```javascript
{
    ...
    "mongo": {
        "store": "mongodb://store_user:12345678@localhost/store_db",
        "products": {
            "username": "products_user",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "products_db"
        }
    },
    ...
}
```

接続は次の 2 つの方法で定義できます:

- **接続 URL として** — 値は単なる文字列です。例: `"mongodb://store_user:12345678@localhost/store_db"`。
- **設定オブジェクトとして** — 次のフィールドを持ちます:
  - `url` — 定義されている場合、他のフィールドを無視して接続 URL として直接使用されます。
  - `protocol` — 接続プロトコル。デフォルトは `mongodb`。
  - `username` と `password` — アクセス資格情報。
  - `host` — サーバーアドレス。デフォルトは `localhost`。
  - `port` — 接続ポート。デフォルトは `27017`。
  - `database` — データベース名。デフォルトは接続キーの名前。
  - `params` — URL に追加される接続の追加パラメータ。例: `{ "authSource": "admin" }`。URL がオブジェクトのフィールドから構築される場合にのみ適用されます。

> 接続はアプリケーションのメインデータベースである必要はありません。`db` 設定とは異なり、`mongo` ブロックは独立しており、複数の接続を同時に扱えます。

### フィルタ

`_mongo.filters()` ファクトリは、MongoDB の主要なクエリ演算子を提供します:

| 演算子 | 説明 |
|---|---|
| `eq("フィールド", 値)` | 値と等しい。 |
| `ne("フィールド", 値)` | 値と等しくない。 |
| `gt("フィールド", 値)` | 値より大きい。 |
| `gte("フィールド", 値)` | 値以上。 |
| `lt("フィールド", 値)` | 値より小さい。 |
| `lte("フィールド", 値)` | 値以下。 |
| `in("フィールド", 値1, 値2, ...)` | いずれかの値と等しい。 |
| `nin("フィールド", 値1, 値2, ...)` | すべての値と等しくない。 |
| `and(フィルタ1, フィルタ2, ...)` | すべてのフィルタに一致する。 |
| `or(フィルタ1, フィルタ2, ...)` | 少なくとも 1 つのフィルタに一致する。 |
| `not(フィルタ)` | フィルタに一致しない。 |
| `regex("フィールド", "パターン")` | 正規表現に一致する。 |
| `exists("フィールド")` | ドキュメントにフィールドが存在する。 |
| `text("検索")` | テキスト検索。 |
| `type("フィールド", "型")` | フィールドが指定された型である。 |
| `mod("フィールド", 除数, 余り)` | フィールドを除数で割った余りが値と等しい。 |
| `where("式")` | JavaScript 式を満たすドキュメントに一致する。例: `"this.price > 100"`。 |
| `size("フィールド", n)` | 配列フィールドの要素数が正確に `n` である。 |

`_mongo.updates()` ファクトリは、更新演算子を提供します:

| 演算子 | 説明 |

| `push("フィールド", 値)` | 配列に値を追加する。 |
| `combine(更新1, 更新2, ...)` | 複数の更新を 1 つに結合する。 |

## 集計

より高度な分析には、`aggregate()` で集計パイプラインを実行できます。各ステージは `_mongo.aggregates()` ファクトリで定義し、アキュムレータは `_mongo.accumulators()` で定義します。

                        "$category",
                        _mongo.accumulators().sum("total", "$price")
                    ),
                    _mongo.aggregates().sort(
                        _mongo.sorts().descending("total")
                    )
                ).all()
            `
        },
        {

利用可能な集計ステージは次のとおりです:

| ステージ | 説明 |
|---|---|

| `group("$フィールド", アキュムレータ)` | フィールドでドキュメントをグループ化し、アキュムレータを適用する。 |
| `project(射影)` | ドキュメントのフィールドを追加、削除、変更する。 |
| `sort(並べ替え)` | ドキュメントを並べ替える。 |
| `limit(n)` | 最初の `n` ドキュメントに制限する。 |
| `skip(n)` | 最初の `n` ドキュメントをスキップする。 |
| `count()` | ドキュメント数をカウントする。 |
| `lookup("コレクション", "ローカルフィールド", "外部フィールド", "as")` | 別のコレクションとの結合を実行する。 |

よく使用されるアキュムレータ:

| アキュムレータ | 説明 |
|---|---|
| `sum("フィールド", "$式")` | 値の合計。 |
| `avg("フィールド", "$式")` | 値の平均。 |
| `min("フィールド", "$式")` | 最小値。 |
| `max("フィールド", "$式")` | 最大値。 |
| `first("フィールド", "$式")` | 最初のドキュメントの値。 |
| `last("フィールド", "$式")` | 最後のドキュメントの値。 |
| `top("フィールド", 並べ替え, "$式")` | 並べ替えに従った先頭の値。 |
| `bottom("フィールド", 並べ替え, "$式")` | 並べ替えに従った末尾の値。 |

> アキュムレータでは、`$` 接頭辞付きの式は入力ドキュメントのフィールドを参照します。例: `"$price"`。

## オプション付き操作

`_mongo` リソースの `*Options()` ファクトリは、MongoDB ドライバーの標準オプションオブジェクトを返し、そのメソッドを直接チェーンできます。たとえば、`upsert(true)` はフィルタに一致する既存ドキュメントがない場合にドキュメントを挿入します:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const old = collection.findOneAndUpdate(
                    _mongo.filters().eq("name", "モニター"),
                    _mongo.updates().set("quantity", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'python',
            code: `
                old = collection.findOneAndUpdate(
                    _mongo.filters().eq("name", "モニター"),
                    _mongo.updates().set("quantity", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'ruby',
            code: `
                old = collection.findOneAndUpdate(
                    _mongo.filters().eq("name", "モニター"),
                    _mongo.updates().set("quantity", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'kotlin',
            code: `
                val old = collection.findOneAndUpdate(
                    _mongo.filters().eq("name", "モニター"),
                    _mongo.updates().set("quantity", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'groovy',
            code: `
                def old = collection.findOneAndUpdate(
                    _mongo.filters().eq("name", "モニター"),

                    _mongo.findOneAndUpdateOptions().upsert(true)

    ]}

ドキュメントが挿入された場合、`findOneAndUpdate()` は `null` を返します。

利用可能なオプションファクトリは次のとおりです: `insertOneOptions()`、`insertManyOptions()`、`updateOptions()`、`findOneAndUpdateOptions()`、`replaceOptions()`、`findOneAndReplaceOptions()`、`deleteOptions()`、`findOneAndDeleteOptions()`、`countOptions()`、`estimatedDocumentCountOptions()`、`dropCollectionOptions()`、`textSearchOptions()`。

## まとめ

`_mongo` リソースにより、Netuno は MongoDB 公式 Java クライアントに対するローコードで多言語対応の抽象化を提供し、JavaScript、Python、Ruby、Kotlin、Groovy でドキュメント、フィルタ、並べ替え、射影、更新、インデックス、集計を扱えるようにします。

利用可能なすべてのメソッドの詳細については、[_mongo](/docs/library/resources/mongo) リソースおよび [MongoCollection](/docs/library/objects/MongoCollection) クラスのドキュメントを参照してください。
