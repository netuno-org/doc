一般的にどのような業種でも、ExcelファイルやGoogle Spreadsheets、LibreOffice、OpenOfficeなどのスプレッドシートが広く使われています。これらは情報の整理、分析、さらには他のスプレッドシートとの連携といったニーズを簡単に解決できるため、幅広く利用されています。

したがって、情報構造が比較的小さく、複雑さがそれほど大きくない場合、Excelなどは問題をうまく解決します。

時間の経過とともにファイルは増え続け、情報があちこちに散らばったファイルがどんどん増えていく傾向があります。

![Excelファイルの画像](/docs/assets/business/excel-danger.jpg "Excelファイル")

問題は、そのExcelファイルが他のいくつものファイルとともに巨大な怪物のようになり、管理が難しくなる場合です。さらに複数の人が関わると、さまざまな問題が発生し、情報が限界まで脆弱になって、ついには維持できなくなります。

そこでは、ユーザープロファイルやグループを管理し、データを検証しながらより適切に構造化して管理し、グラフや表を含む複雑なレポートとしてデータをエクスポートし、より複雑な検索を行い、他のシステムと連携するなど、より堅牢なアプリケーションを作成する必要が出てきます。

> 主なジレンマは、Excelは比較的安価である一方、管理アプリケーションの開発はあまりにも高コストだということです。

Netunoを使えば、**少ない労力**で、すべての情報を管理するアプリケーションをすばやく作成でき、散らばって管理が複雑なExcelファイルを完全に置き換えられます。

## データベーステーブルとしてのスプレッドシート

データベースはとても複雑だとは考えないでください。複雑ではなく、Excelのスプレッドシートとよく似ていることがわかります。

> データベースのテーブルは、スプレッドシートと同じものです。

たとえば、Excelのスプレッドシートを見てみましょう：

|   	|    A    	|      B     	|       C       	|      D      	|
|:-:	|:-------:	|:----------:	|:-------------:	|:-----------:	|
| **1** 	| 製品 	| 数量 	| 単価 	| 合計金額 	|
| **2** 	|  フォーク  	|     10     	|      3,00     	|    30,00    	|
| **3** 	|  グラス  	|      5     	|      4,00     	|    20,00    	|
| **4** 	|  ナイフ  	|      8     	|      2,00     	|    16,00    	|
| **5** 	|         	|            	|  **合計金額**  	|    **66,00**    	|

この情報をデータベースに保存するには、**製品**の情報を保存するテーブルを作成する必要があります。

テーブルは以下の例のように構成され、次のデータを含みます：

<table>
    <thead>
        <tr>
            <th colspan="3">製品</th>
        </tr>
        <tr>
            <th>ID</th>
            <th>名前</th>
            <th>価格</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>1</td>
            <td>フォーク</td>
            <td>3,00</td>
        </tr>
        <tr>
            <td>2</td>
            <td>グラス</td>
            <td>4,00</td>
        </tr>
        <tr>
            <td>3</td>
            <td>ナイフ</td>
            <td>2,00</td>
        </tr>
    </tbody>
</table>

このように、ある製品のデータを使用するときは、必ずこのテーブルから取得する必要があります。

つまり、**製品**の情報を保存するスプレッドシートがあるようなものです。

各行にはID、つまり一意の識別子（たとえば連番）が含まれます。
