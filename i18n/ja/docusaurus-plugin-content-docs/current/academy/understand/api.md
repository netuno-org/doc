Netunoには、JWT（JSON Web Token）とOpenAPI 3.0をサポートし、ローコードでREST APIを作成するための独自フレームワークがあります。

NetunoのWebサービス開発フレームワークは非常に柔軟で、あらゆる種類の開発を実行できます。

このフレームワークには、メール送信、他のREST APIの利用、他のデータベースとの統合、PDFやExcelファイルの生成、SMS送信、データベースデータの操作など、一般的なニーズを満たすための多くのコード行を節約するローコード開発向け機能がすでに多数含まれています。

また、Netunoのフレームワークに解決策がない場合でも、既存のJava、Kotlin、さらにはJavaScriptのライブラリを簡単に統合して、カスタムのリソースを開発し、Netunoのフレームワークと統合できます。

## JWT - JSON Web Token

[JWT.io](https://jwt.io/)は、セッションコンテキストのデータをJSONオブジェクト経由でクライアントに渡すための標準仕様です。

これにより、サーバーはログイン済みユーザーの機密データをセッションに保存する必要がなくなり、代わりにクライアントへ渡されるトークンとなり、その後は各リクエストでこのトークンを返す必要があります。

このトークンには、有効期限や、再認証を要求せずに新しいトークンを作成できるプロセスなど、いくつかのセキュリティ制御が適用されます。

NetunoはJWTサポートを統合しており、シンプルで簡単に使用でき、Netunoネイティブのユーザーと認証とも統合して動作します。

## OpenAPI 3.0

Webサービスの定義開発とクライアントコード生成の標準となって久しいSwagger v1およびv2の成功を受け、

Swaggerはその定義をオープンにし、[OpenAPI 3](https://www.openapis.org/)となりました。

これは、APIの文書化方法や、APIを利用するクライアントの生成方法の標準を定義する基盤であり続けています。

NetunoはOpenAPI 3.0との統合をすでに備えており、OpenAPI定義と[JSON Schema](https://json-schema.org/)の検証を併用します。

つまりNetunoでは、取得および返却されるJSONのスキーマ検証を利用して、Webサービスの入力と出力も検証できます。

- `Input`: Webサービスへの呼び出しが構造と検証に適合しない場合、拒否されます
- `Output`: 定義された構造と検証に適合しないデータが返された場合、Webサービスが準拠していないという警告が生成されます。

このようにNetunoは、受信データの検証のためのコード内の多くの`if`の作成を省くだけでなく、単体テストを実行する形で、Webサービスが生成している結果の検証も保証します。

また、Netunoが生成するOpenAPI構造は、[Swaggerエディター](https://editor.swagger.io/)で使用して、テストインターフェース、ドキュメント、および他の技術でのAPIクライアント向けコードを生成できます。

## 基本

NetunoはWebサービスと認証の作成を手間なくサポートします。つまり、JWTやOpenAPIの使用は必須ではありませんが、標準の推奨事項です。

API作成を迅速化するため、あるいはサーバー間通信を伴う状況では、最大限に簡素化して時間を節約することがよくあります。

> Netunoでは[HTTP認証](https://developer.mozilla.org/pt-BR/docs/Web/HTTP/Authentication)を実行できます。
