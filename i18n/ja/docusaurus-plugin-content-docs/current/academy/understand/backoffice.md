Webアプリケーションやモバイルアプリケーションの開発において、バックオフィス、つまりデータ管理層という概念は一般的です。

すなわち、通常はWeb上にある層であり、ビジネス管理を行うユーザーがインターフェースにアクセスしてデータの操作を行うことができます。

以下の要件は非常に一般的です。

- ユーザー管理
- ユーザーグループ管理
- ビジネスルールに合わせたデータベースレコードの操作
- ユーザーが何をいつ行ったかを記録するログ
- アクセスの制限。グループやユーザーによっては特定のデータを変更できない、あるいは閲覧すらできない
- ブラウザおよびモバイル端末からのアクセスを許可
- 管理レポートの生成
- ビジネスに合わせたダッシュボード。グラフやテーブルで表示できる関連情報を含む

これらの理由などから、バックオフィスの開発は最終的なアプリケーションの開発と同じかそれ以上の手間がかかることがよくあります。

さらに、バックオフィスがREST APIを提供し、Webサービスを通じてビジネスデータを最終的なアプリケーション、すなわちフロントエンドと通信できるようにするのも一般的です。

![バックオフィス。](/docs/assets/business/business-backoffice.svg "バックオフィス。")

Netunoは強力なバックオフィスエンジンを提供しており、コードを書かずにデータ構造を作成し、データベースと統合されたフォームを生成することで、作成、検索、編集、削除といった最も一般的な操作を行うことができます。

また、ユーザーとグループの管理、ログ記録を伴うアクセス制御も提供します。

ローコードでダッシュボード、レポート、そしてJWT (JSON Web Token) と統合されたREST API (Webサービス) を作成することができます。

> Netunoは最も一般的な機能をすべてビジネスモデルに合わせて調整できる状態で提供するため、オーダーメイドのバックオフィスを開発する労力は劇的に削減されます。

## 新しいプロジェクト向けのバックオフィス

新しいプロジェクト、特に外部クライアント向けのアプリケーションを開発する場合、バックオフィスの予算は軽視されがちです。つまり、その開発やインターフェースの構想に費やす時間が軽く見られます。

これは対象となるクライアントには見えないため、後回しにできるからです。

さらに、意思決定者の目的は最終的な成果を達成することにあり、内部の管理層にはあまり関心が向きません。特に関連するコストが発生する場合はなおさらです。

しかし、開発中、そして特にテストの段階では、バックオフィスのインターフェースがあればデータの整合性をより適切に検証できます。

Netunoは**データモデルの構築を容易にし、データ管理のためのレスポンシブなフォームを自動的にWebインターフェースで提供する**ため、データ構造のモデリング段階でNetunoを使うだけで、自動的にバックオフィスのインターフェースが得られます。とてもシンプルです!

その後は、ダッシュボード、レポート、WebサービスをすべてNetunoで開発するレベルまで発展させることもできます。

あるいは、何らかの制約や義務により、WebサービスやAPI REST全体を他の任意の技術で開発することもできます。その場合はNetunoが生成したデータベースを利用するだけで済みます。

いずれにせよ、バックオフィスのニーズを満たすための選択肢としてNetunoが利用できます。

## 既存アプリケーション向けのバックオフィス

すでに存在するアプリケーションで、バックオフィスが開発されていない場合、あるいは存在していても制限がある場合。

Netunoは、既存のバックオフィスを拡張するためにも、不足しているバックオフィスを補うためにも使用できます。

Netunoでバックオフィスを作成する労力は非常に小さいため、バックオフィス全体をNetunoで作ることも、一部のモジュールだけを作ることもできます。

どの技術オプションを採用するかは、その人の判断と想像力に委ねられます。確かなことは、あまり複雑にする必要はなく、時間をかけて成長させていくモジュール式のバックオフィスを考えればよいということです。

通常、モジュール方式での開発は非常に複雑ですが、Netunoはこのプロセスも簡素化し、同じデータベース上で複数のアプリケーションを開発できるようにするため、既存のバックオフィスに影響を与えずに、それを拡張する独立した補助モジュールを開発するための優れたソリューションでもあります。

Netunoは同じアプリケーション内で複数のデータベースを簡単に統合して管理できるため、別のデータベースへの情報のインポートやエクスポートも容易になります。

こうして、バックオフィスの複雑さを、既存のバックオフィスへの追加の「モジュール」のようなNetunoアプリケーションからより適切に分離することができます。

## まとめ

間違いなく、Netunoの主な目的の一つは、バックオフィスの開発を可能な限り簡素化し、既存のプロジェクトにも新しいプロジェクトにも統合できるようにすることであり、新しいプロジェクトでは他の技術ともうまく統合できます。

Netunoは、すべての開発をNetunoで行わなければならないような閉鎖的なプラットフォームではありません。むしろ逆で、Netunoは以下の制約を克服するために、その場のニーズを満たすだけに使用することもできます。

- コスト
- 時間

あらゆる他の技術と統合することが可能です。

したがって、資金不足や納期が非常に厳しいといった問題があり、さらには複雑さが大きく複数の技術が統合されている場合、Netunoはコストと時間の問題を解決し、作業を楽にするためのもう一つの技術として捉えるべきです。
