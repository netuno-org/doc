Netuno では、複数のコマンドやプロセスのデータ出力（ログ）を単一のターミナルウィンドウに統合できます。これはメインサーバーが実行されているのと同じウィンドウです。

複数の技術を同時に扱うことが一般的な現代の開発フローでは、Netuno はログオーケストレーターとして機能し、ReactJS、Angular、Vue などのフロントエンドプロセスをはじめ任意のプロセスなど、並列で自動起動するよう設定された複数のコマンドを管理できます。

> 任意のプロセスを開始できます。そのコマンドを定義するだけでよく、たとえば別の技術で開発された補助 REST API のサーバーを統合することもできます。


## 設定

外部プロセスを統合するには、アプリケーションの環境設定ファイルを編集する必要があります。このガイドでは、開発環境を例に使用します。

### ファイルの場所

アプリケーションのフォルダに移動し、次のファイルを探します:

- 📂 `config/_development.json`

### 設定構造


設定は `commands` キーで行い、オブジェクトの配列で構成します。これにより、複数のサービスを並列で実行できます。

ファイルを開き、`"commands"` キーが既に存在するか確認します。存在しない場合は、以下の設定に従ってファイルの末尾に追加します（JSON 形式を守ってください）:

```json
{
    ...
    "commands": [
        {
            "path": "ui",
            "command": "bun run watch",
            "enabled": true
        },
        {
            "env": [ "PORT=21030", "WDS_SOCKET_PORT=21030" ],
            "path": "webサイト",
            "install": "bun install",
            "command": "bun run dev",
            "enabled": true
        }
    ],
    ...
}
```

> **注記:** 上記の例では、`ui` フォルダ用と `webサイト` フォルダ用のコマンドを設定しており、どちらも bun パッケージマネージャーを使用しています。

### パラメータリファレンス

**ユーザーインターフェース（UI）:** アプリケーションの `ui` ディレクトリ内で `bun run watch` を実行します。

**Webサイト:** `webサイト` フォルダ内で `bun run dev` を実行します。

### env

プロセスの実行に必要な環境変数を定義します。複数の変数を同時に定義できます。

### path

コマンドを実行するフォルダパスを、アプリケーションのルートからの相対パスで定義します。

### install

Netuno には、パッケージ依存関係を管理するためのインテリジェントな機能が組み込まれています:

- **自動検出:** コマンドが `npm`、`bun`、`pnpm`、または `yarn` で始まる場合、Netuno は `node_modules` フォルダが存在するか確認します。

- **インテリジェント実行:** フォルダが見つからない場合、メインプロセスを開始する前に対応するインストールコマンド（例: `bun install`）が自動的に実行されます。

- **カスタマイズ:** `install` パラメータを手動で定義すると、デフォルトの検出はカスタム設定に置き換えられます。

### command

実行するメインコマンドです。すべてのデータ出力（`output`）は Netuno に統合されます。

### enabled

コマンドをアプリケーションとともに自動起動するか（true）、しないか（false）を定義します。

## まとめ

Netuno でのコマンドの一元化は、ワークフローを大幅に簡素化します。
統合された可視性により、並列プロセスのすべての情報を単一のターミナルに集約できるため、リアルタイムの監視が容易になります。

安全な終了機能により、Netuno サーバーの実行を停止すると、設定されたすべての補助プロセスも自動的に終了するため、バックグラウンドプロセスやポートの競合を防げます。
