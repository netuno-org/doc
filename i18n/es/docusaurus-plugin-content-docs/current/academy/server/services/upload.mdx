Enviar archivos a la API y guardarlos en una carpeta o en la base de datos.

## Introducción

Cuando necesitamos enviar archivos a los servicios de la API REST tenemos varias formas
de realizar este desarrollo en Netuno.

Normalmente los archivos se envían en el cuerpo de la petición HTTP estructurados en formato
multipart, es el procedimiento más común en el frontend, por ejemplo cuando rellenamos un
formulario y hay un campo para elegir un archivo.

Como alternativa podemos enviar los bytes de los archivos codificados en Base64 como valor
en un objeto JSON, cuando queremos una API REST 100 % JSON.

## Archivos

A través de `_req.file` podemos pasar el nombre del campo y así obtener el objeto del archivo
que se ha enviado, veamos cómo:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const miArchivo = _req.file("archivo");
            `
        },
    ]}
/>

Es decir, `_req` tiene todos los datos que recibimos en el cuerpo de la petición HTTP.

Y a través del método `file` permite obtener el objeto que representa el archivo que se
ha enviado.

El valor obtenido podrá ser `null` en caso de que no haya ningún archivo.

## Como Base64 en el JSON

Para realizar la subida de un archivo en el JSON enviado al servicio, podemos definir una propiedad con el valor:

`data:image/png;base64,...`

Donde en los `...` sigue la secuencia de bytes del archivo codificados en Base64.

Siendo que el tipo de archivo va a continuación de `data`, por ejemplo:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Objeto

Si el archivo está en una estructura interna del JSON dentro del subobjeto:

```json
{
  "persona": {
    "archivo": "data:image/png;base64,..."
  }
}
```

Se puede obtener de la siguiente forma:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const miArchivo = _req.getValues("persona").getFile("avatar");
            `
        },
    ]}
/>

### Array

Si el archivo está en una estructura interna del JSON dentro del array:

```json
{
  "archivos": [
    "data:image/png;base64,..."
  ]
}
```

Se puede obtener de la siguiente forma:

<PolyglotCode

## OpenAPI

Netuno soporta la integración con OpenAPI y utiliza la definición de OpenAPI para validar la petición HTTP.

> Más sobre la [OpenAPI en Netuno](/docs/academy/server/services/openapi).

Con el tipo `file`, Netuno valida si el valor comienza con el formato de archivo en el JSON, por ejemplo:

- `data:image/png;base64,...`

Para validar si se está recibiendo un archivo en una propiedad del objeto JSON:

```json title="post.in.json"
{
  "summary": "Subida de archivo",
  "description": "Servicio que recibe un archivo en el objeto JSON.",
  "type": "object",
  "properties": {
    "archivo": {
      "type": "file"
    }
  },
  "required": [
    "archivo"
  ]
}
```

Para validar si se está recibiendo una lista de archivos en array en el JSON:

```json title="post.in.json"
{
  "summary": "Subida de archivos",
  "description": "Servicio que recibe una lista de archivos en array en el JSON.",
  "properties": {
    "archivos": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "archivos"
  ]
}
```

## Guardar el archivo

Normalmente cuando recibimos un archivo en el servicio necesitamos guardarlo, como por ejemplo:

- **Base de datos**: Archivo relacionado con un registro, como el de un usuario.
- **Storage**: Carpeta interna de la aplicación que sirve para gestionar archivos en general.
- **Carpeta**: Colocar el archivo en una carpeta cualquiera del sistema.

### Base de datos

En la gestión de los campos de los formularios, Netuno soporta el tipo `image` y `file`, siendo:

- **Image**: Archivos de imagen en general, JPG y PNG.
- **File**: Cualquier tipo de archivo.

Imagine que tiene un campo de Imagen en el formulario Producto, podemos guardar el archivo enviado mediante subida de la
siguiente forma:

#### Descarga del archivo de la base de datos

Para mostrar el archivo almacenado debemos crear un servicio que proporcione los bytes del archivo.

Siendo que los archivos guardados en base de datos, como en el ejemplo anterior, el archivo en sí se coloca en el storage de la
aplicación y en la base de datos se almacena solo el nombre final del archivo.

> El storage de la aplicación es una carpeta destinada a almacenar y organizar estructuras de archivos genéricos.

Por lo tanto, en el ejemplo anterior los archivos de base de datos del formulario `Producto` y del campo `Imagen` quedan
almacenados en:

- `storage/database/producto/imagen/*`

> Netuno gestiona automáticamente el nombre del archivo almacenado para evitar nombres de archivos repetidos.

Para obtener el archivo, se puede crear un servicio que muestre el archivo de imagen del producto, por ejemplo:

            storageProductoImagenArchivo = _storage.database(
                "producto",
                "imagen",
                dbProductoImagenNombre
            )

            if storageProductoImagenArchivo.extension() == "jpg" || storageProductoImagenArchivo.extension() == "jpeg"
                _header.contentTypeJPG()
            else
                _header.contentTypePNG()
            end

            _header.noCache()

            _out.copy(storageProductoImagenArchivo.inputStream())
        `
    },
]}
/>

Fíjese en que el recurso `_storage` ([Storage](/docs/library/resources/storage)) se utiliza para obtener el archivo:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.database(
                    "producto", // Nombre del formulario/tabla.
                    "imagen", // Nombre del campo/columna.
                    dbProductoImagenNombre // Nombre del archivo.
                );
            `
        },
    ]}
/>

En la base de datos se almacena solo el nombre del archivo, siendo que a través de `_storage.database` podemos
obtener el archivo en sí.

### Storage

Podemos guardar un archivo directamente en el `storage` de la aplicación.

Para no mezclar con los archivos de base de datos, debemos utilizar la carpeta de `filesystem`, que tiene la
finalidad de almacenar archivos genéricos que no están asociados en la base de datos.

Para recibir el archivo, en este ejemplo se muestra cómo un archivo enviado en el servicio
 `POST` se almacena directamente en el storage:

<PolyglotCode
    file="services/archivo/post"
    codes={[
        {
            lang: 'javascript',
            code: `
                const archivo = _req.getFile("archivo");
                _storage.filesystem("servidor", "subida").ensurePath();
                archivo.save(_storage.filesystem("servidor", "subida", archivo.name()));
            `
        },
    ]}
/>

El archivo queda almacenado en la carpeta `storage` de la aplicación, en:

- `storage/filesystem/servidor/subida/*`

> El recurso [Storage](/docs/library/resources/storage) se utiliza para obtener la ruta de carpeta y de archivo:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                _storage.filesystem(
                    "servidor", // Nombre de la subcarpeta en el filesystem.
                    "subida", // Nombre o ruta de la subcarpeta interna.
                    archivo.name() // Nombre final del archivo.
                );
            `
        },
    ]}
/>

> Vea más sobre la documentación de [Storage](/docs/library/resources/storage).

Para hacer la descarga del archivo, en este ejemplo se muestra cómo se pueden obtener los bytes del archivo

### Carpeta

Podemos guardar un archivo directamente en cualquier carpeta del ordenador.

Hay dos recursos que son muy útiles en estos casos:

- `_app` - Podemos obtener cualquier carpeta o archivo en la aplicación.
- `_os` - Podemos obtener cualquier carpeta o archivo en el ordenador.

> Vea la documentación de los respectivos recursos [App](/docs/library/resources/app) y [OS](/docs/library/resources/os),
> ambos recursos tienen los métodos `folder` y `file`, que permiten indicar cuál es la ruta de la carpeta o del archivo
> respectivamente.

Para recibir el archivo, en este ejemplo se muestra cómo un archivo enviado en el servicio
`POST` se almacena directamente en una carpeta de la aplicación:

## Conclusión

Como puede verse, podemos integrar la subida de archivos en los servicios de la API REST, incluso integrado con
OpenAPI.

Podemos guardar el archivo en la base de datos, dentro de la carpeta `storage` de la aplicación o en cualquier carpeta del
ordenador.

Vea la documentación de los recursos utilizados en este tutorial que permiten manipular los archivos:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

En base de datos podemos guardar imágenes en campos del tipo `image`, y podemos guardar cualquier tipo de archivo en
campos del tipo `file`, cómo guardamos u obtenemos archivos son de la misma forma en cualquier caso, ya sea imagen o
archivo genérico.
