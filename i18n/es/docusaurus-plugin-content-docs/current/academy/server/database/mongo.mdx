## Introducción

<a href="https://www.mongodb.com/" target="_blank">MongoDB</a> es una base de datos NoSQL orientada a documentos. En lugar de tablas y filas, los datos se guardan en documentos con un formato similar a JSON, lo que permite una gran flexibilidad en el modelo de datos.

El recurso [_mongo](/docs/library/resources/mongo) de Netuno ofrece la integración con MongoDB, con una abstracción low-code sobre el cliente oficial de MongoDB para Java, disponible para los diversos lenguajes de programación soportados por Netuno: **JavaScript, Python, Ruby, Kotlin y Groovy**.

> Antes de continuar, se recomienda saber cómo crear servicios en Netuno; consulte el tutorial [REST - Servicios Web](/docs/academy/server/services/rest).

Un ejemplo de implementación de las operaciones presentadas aquí está disponible en el servicio de ejemplo `mongo.js`, que se encuentra en:

## Instalación de MongoDB

### Con Docker

Asumiendo que tiene Docker instalado, basta con descargar la imagen de MongoDB e iniciar un nuevo contenedor:

```shell
docker pull mongo
docker run -d --name mongo -p 27017:27017 mongo
```

De esta forma, MongoDB queda accesible en `localhost:27017` sin autenticación.

Para crear el usuario de la base de datos según la configuración de la aplicación, ejecute:

```shell
docker exec -it mongo mongosh productos_db --eval 'db.createUser({ user: "productos_user", pwd: "12345678", roles: [{ role: "readWrite", db: "productos_db" }] })'
```

### Con Ubuntu

MongoDB no está incluido en los repositorios oficiales de Ubuntu, por lo que es necesario añadir el repositorio oficial antes de la instalación:

```shell
sudo apt-get install gnupg curl
curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg -o /usr/share/keyrings/mongodb-server-7.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] http://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
sudo apt-get update
sudo apt-get install -y mongodb-org
```

Una vez instalado, puede iniciar el servicio con:

```shell
sudo systemctl start mongod
```

### Con Windows

- <a href="https://www.mongodb.com/try/download/community" target="_blank">Descargar MongoDB Community Server</a>.

Ejecute el instalador descargado y, en el paso **Service Configuration**, active **Install MongoD as a Service** para que MongoDB se inicie automáticamente. MongoDB queda accesible en `localhost:27017` sin autenticación.

> Consulte la [documentación oficial de MongoDB](https://www.mongodb.com/docs/manual/installation/) para otras distribuciones y versiones.

## Configuración de la Aplicación

La configuración de las conexiones de MongoDB se realiza en el fichero de configuración de la aplicación, según el entorno:

- `config/_development.json`

> Vea más sobre los [ficheros de configuración](/docs/academy/explore/configuration) de la aplicación.

Dentro del fichero de configuración, añada el bloque `mongo`, donde cada clave identifica una conexión:

```javascript
{
    ...
    "mongo": {
        "tienda": "mongodb://tienda_user:12345678@localhost/tienda_db",
        "productos": {
            "username": "productos_user",
            "password": "12345678",
            "host": "127.0.0.1",
            "port": "27017",
            "database": "productos_db"
        }
    },
    ...
}
```

Una conexión se puede definir de dos formas:

- **Como URL de conexión** — el valor es simplemente una cadena, por ejemplo `"mongodb://tienda_user:12345678@localhost/tienda_db"`.
- **Como objeto de configuración** — con los campos:
  - `url` — si se define, se utiliza directamente como URL de conexión, ignorando los demás campos.
  - `protocol` — el protocolo de la conexión, por defecto `mongodb`.
  - `username` y `password` — las credenciales de acceso.
  - `host` — la dirección del servidor, por defecto `localhost`.
  - `port` — el puerto de la conexión, por defecto `27017`.
  - `database` — el nombre de la base de datos, por defecto el nombre de la clave de la conexión.
  - `params` — parámetros adicionales de la conexión añadidos a la URL, por ejemplo `{ "authSource": "admin" }`. Solo se aplican cuando la URL se construye a partir de los campos del objeto.

> La conexión no tiene por qué ser la base de datos principal de la aplicación. A diferencia de la configuración `db`, el bloque `mongo` es independiente y permite varias conexiones simultáneas.

### Filtros

La factoría `_mongo.filters()` ofrece los principales operadores de consulta de MongoDB:

| Operador | Descripción |
|---|---|
| `eq("campo", valor)` | Igual al valor. |
| `ne("campo", valor)` | Distinto del valor. |
| `gt("campo", valor)` | Mayor que el valor. |
| `gte("campo", valor)` | Mayor o igual que el valor. |
| `lt("campo", valor)` | Menor que el valor. |
| `lte("campo", valor)` | Menor o igual que el valor. |
| `in("campo", valor1, valor2, ...)` | Igual a cualquiera de los valores. |
| `nin("campo", valor1, valor2, ...)` | Distinto de todos los valores. |
| `and(filtro1, filtro2, ...)` | Coincide con todos los filtros. |
| `or(filtro1, filtro2, ...)` | Coincide con al menos uno de los filtros. |
| `not(filtro)` | No coincide con el filtro. |
| `regex("campo", "patrón")` | Coincide con la expresión regular. |
| `exists("campo")` | El campo existe en el documento. |
| `text("búsqueda")` | Búsqueda de texto. |
| `type("campo", "tipo")` | El campo es del tipo especificado. |
| `mod("campo", divisor, resto)` | El resto de la división del campo por el divisor es igual al valor. |
| `where("expresión")` | Coincide con los documentos que satisfacen una expresión JavaScript, por ejemplo `"this.precio > 100"`. |
| `size("campo", n)` | El campo de matriz tiene exactamente `n` elementos. |

Las etapas de agregación disponibles son las siguientes:

| Etapa | Descripción |
|---|---|
| `match(filtro)` | Selecciona solo los documentos que coinciden con el filtro. |
| `group("$campo", acumuladores)` | Agrupa los documentos por el campo y aplica los acumuladores. |
| `project(proyección)` | Añade, elimina o modifica campos en los documentos. |
| `sort(ordenación)` | Ordena los documentos. |
| `limit(n)` | Limita a los primeros `n` documentos. |
| `skip(n)` | Salta los primeros `n` documentos. |
| `count()` | Cuenta el número de documentos. |
| `lookup("colección", "campoLocal", "campoExtranjero", "como")` | Ejecuta un join con otra colección. |

Y los acumuladores más utilizados:

| Acumulador | Descripción |
|---|---|
| `sum("campo", "$expresión")` | Suma de los valores. |
| `avg("campo", "$expresión")` | Media de los valores. |
| `min("campo", "$expresión")` | Valor mínimo. |
| `max("campo", "$expresión")` | Valor máximo. |
| `first("campo", "$expresión")` | Valor del primer documento. |
| `last("campo", "$expresión")` | Valor del último documento. |
| `top("campo", ordenación, "$expresión")` | Valor superior según la ordenación. |
| `bottom("campo", ordenación, "$expresión")` | Valor inferior según la ordenación. |

> En los acumuladores, la expresión con prefijo `$` se refiere al campo de un documento de entrada, por ejemplo `"$precio"`.

## Operaciones con Opciones

Las factorías `*Options()` del recurso `_mongo` devuelven los objetos de opciones estándar del driver de MongoDB, y puede encadenar sus métodos directamente. Por ejemplo, `upsert(true)` inserta el documento cuando el filtro no coincide con ningún documento existente:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const antiguo = coleccion.findOneAndUpdate(
                    _mongo.filters().eq("nombre", "Monitor"),
                    _mongo.updates().set("cantidad", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'python',
            code: `
                antiguo = coleccion.findOneAndUpdate(
                    _mongo.filters().eq("nombre", "Monitor"),
                    _mongo.updates().set("cantidad", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'ruby',
            code: `
                antiguo = coleccion.findOneAndUpdate(
                    _mongo.filters().eq("nombre", "Monitor"),
                    _mongo.updates().set("cantidad", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'kotlin',
            code: `
                val antiguo = coleccion.findOneAndUpdate(
                    _mongo.filters().eq("nombre", "Monitor"),
                    _mongo.updates().set("cantidad", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        },
        {
            lang: 'groovy',
            code: `
                def antiguo = coleccion.findOneAndUpdate(
                    _mongo.filters().eq("nombre", "Monitor"),
                    _mongo.updates().set("cantidad", 8),
                    _mongo.findOneAndUpdateOptions().upsert(true)
                )
            `
        }
    ]}
/>

Cuando el documento se inserta, `findOneAndUpdate()` devuelve `null`.

Las factorías de opciones disponibles son: `insertOneOptions()`, `insertManyOptions()`, `updateOptions()`, `findOneAndUpdateOptions()`, `replaceOptions()`, `findOneAndReplaceOptions()`, `deleteOptions()`, `findOneAndDeleteOptions()`, `countOptions()`, `estimatedDocumentCountOptions()`, `dropCollectionOptions()` y `textSearchOptions()`.

## Conclusión

Con el recurso `_mongo`, Netuno ofrece una abstracción low-code y políglota sobre el cliente oficial de MongoDB para Java, permitiendo trabajar con documentos, filtros, ordenaciones, proyecciones, actualizaciones, índices y agregaciones en JavaScript, Python, Ruby, Kotlin y Groovy.

Para más detalles sobre todos los métodos disponibles, consulte la documentación del recurso [_mongo](/docs/library/resources/mongo) y de la clase [MongoCollection](/docs/library/objects/MongoCollection).
