Trimiteți fișiere către API și salvați-le într-un dosar sau în baza de date.

## Introducere

Când trebuie să trimitem fișiere către serviciile API REST, avem mai multe modalități
de a realiza această dezvoltare în Netuno.

De obicei, fișierele sunt trimise în corpul cererii HTTP structurate în format
multipart, este procedura cea mai comună în frontend, de exemplu când completăm un
formular și există acel câmp pentru a alege un fișier.

Alternativ, putem trimite octeții fișierelor codificați în Base64 ca valoare
într-un obiect JSON, când dorim o API REST 100% JSON.

## Fișiere

Prin `_req.file` putem transmite numele câmpului și astfel obținem obiectul fișierului
care a fost trimis, vedeți cum:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const fisierulMeu = _req.file("fisier");
            `
        },
    ]}
/>

Adică, `_req` conține toate datele pe care le primim în corpul cererii HTTP.

Iar prin metoda `file` se poate obține obiectul care reprezintă fișierul care a fost
trimis.

Valoarea obținută poate fi `null` în cazul în care nu există niciun fișier.

## Ca Base64 în JSON

Pentru a realiza upload-ul unui fișier în JSON-ul trimis către serviciu, putem defini o proprietate cu valoarea:

`data:image/png;base64,...`

Unde în `...` urmează secvența octeților fișierului codificați în Base64.

Iar tipul fișierului urmează după `data`, de exemplu:

- PNG: `image/png`.
- JPG: `image/jpeg`
- TXT: `text/plain`
- PDF: `application/pdf`
- XLSX: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`

### Obiect

Dacă fișierul se află într-o structură internă a JSON-ului în subobiect:

```json
{
  "persoana": {
    "fisier": "data:image/png;base64,..."
  }
}
```

Poate fi obținut în modul următor:

<PolyglotCode
    codes={[
        {
            lang: 'javascript',
            code: `
                const fisierulMeu = _req.getValues("persoana").getFile("avatar");
            `
        },
    ]}
/>

### Array

Dacă fișierul se află într-o structură internă a JSON-ului în array:

```json

  "fisiere": [
```

Poate fi obținut în modul următor:

## OpenAPI

Netuno suportă integrarea cu OpenAPI și utilizează definiția OpenAPI pentru a valida cererea HTTP.

> Mai multe despre [OpenAPI în Netuno](/docs/academy/server/services/openapi).

Cu tipul `file`, Netuno validează dacă valoarea începe cu formatul de fișier în JSON, de exemplu:

- `data:image/png;base64,...`

Pentru a valida dacă se primește un fișier într-o proprietate a obiectului JSON:

```json title="post.in.json"
{
  "summary": "Încărcare fișier",
  "description": "Serviciu care primește un fișier în obiectul JSON.",
  "type": "object",
  "properties": {
    "fisier": {
      "type": "file"
    }
  },
  "required": [
    "fisier"
  ]
}
```

Pentru a valida dacă se primește o listă de fișiere în array în JSON:

```json title="post.in.json"
{
  "summary": "Încărcare fișiere",
  "description": "Serviciu care primește o listă de fișiere în array în JSON.",
  "properties": {
    "fisiere": {
      "type": "array",
      "items": {
        "type": "file"
      }
    }
  },
  "required": [
    "fisiere"
  ]
}
```

## Salvarea fișierului

De obicei, când primim un fișier în serviciu, trebuie să îl salvăm, de exemplu:

- **Baza de date**: Fișier asociat unei înregistrări, cum ar fi a unui utilizator.
- **Storage**: Dosar intern al aplicației care servește la gestionarea fișierelor în general.
- **Dosar**: Plasarea fișierului într-un dosar oarecare al sistemului.

### Baza de date

În gestionarea câmpurilor formularelor, Netuno suportă tipul `image` și `file`, și anume:

- **Image**: Fișiere de imagine în general, JPG și PNG.
- **File**: Orice tip de fișier.

#### Descărcarea fișierului din baza de date

Pentru a prezenta fișierul stocat, trebuie să creăm un serviciu care furnizează octeții fișierului.

Deoarece fișierele salvate în baza de date, ca în exemplul de mai sus, fișierul în sine este plasat în storage-ul
aplicației, iar în baza de date este stocat doar numele final al fișierului.

> Storage-ul aplicației este un dosar destinat stocării și organizării structurilor de fișiere generice.

Prin urmare, în exemplul de mai sus, fișierele din baza de date ale formularului `Produs` și ale câmpului `Imagine` sunt stocate în:

- `storage/database/produs/imagine/*`

> Netuno gestionează automat numele fișierului stocat pentru a evita nume de fișiere repetate.

Pentru a obține fișierul, se poate crea un serviciu care prezintă fișierul de imagine al produsului, de exemplu:

### Storage

Putem salva un fișier direct în `storage`-ul aplicației.

Pentru a nu le amesteca cu fișierele din baza de date, trebuie să folosim dosarul de `filesystem`, care are
scopul de a stoca fișiere generice ce nu sunt asociate în baza de date.

Pentru a primi fișierul, în acest exemplu se demonstrează cum un fișier trimis în serviciul
 `POST` este stocat direct în storage:

<PolyglotCode
    file="services/fisier/post"
    codes={[
        {
            lang: 'javascript',
            code: `

                _storage.filesystem("server", "incarcari").ensurePath();
                fisier.save(_storage.filesystem("server", "incarcari", fisier.name()));
            `
        },
    ]}
/>

Fișierul este stocat în dosarul `storage` al aplicației, la:

- `storage/filesystem/server/incarcari/*`

> Resursa [Storage](/docs/library/resources/storage) este utilizată pentru a obține calea dosarului și a fișierului:

<PolyglotCode

> Vedeți mai multe în documentația [Storage](/docs/library/resources/storage).

### Dosar

Putem salva un fișier direct în orice dosar al calculatorului.

Există două resurse care sunt foarte utile în aceste cazuri:

- `_app` - Putem obține orice dosar sau fișier din aplicație.
- `_os` - Putem obține orice dosar sau fișier din calculator.

> Vedeți documentația resurselor respective [App](/docs/library/resources/app) și [OS](/docs/library/resources/os);
> ambele resurse au metodele `folder` și `file`, care permit indicarea căii dosarului sau fișierului,

## Concluzie

După cum se poate observa, putem integra upload-ul de fișiere în serviciile API REST, inclusiv integrat cu
OpenAPI.

Putem salva fișierul în baza de date, în dosarul `storage` al aplicației sau în orice dosar al
calculatorului.

Vedeți documentația resurselor utilizate în acest tutorial care permit manipularea fișierelor:

- [Storage](/docs/library/resources/storage)
- [App](/docs/library/resources/app)
- [OS](/docs/library/resources/os)

În baza de date putem salva imagini în câmpuri de tip `image` și putem salva orice tip de fișier în
câmpuri de tip `file`; modul în care salvăm sau obținem fișiere este același în orice caz, fie imagine, fie
fișier generic.
