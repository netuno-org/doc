Configurare și utilizare a autentificării cu token.

## Introducere

JWT (JSON Web Token) este un standard pentru asigurarea securității și contextului autentificării în aplicațiile web, unde 
frontend-ul este decuplat de backend.

Este utilizat frecvent când frontend-ul unei aplicații web este dezvoltat în ReactJS, AngularJS, VueJS etc., iar 
backend-ul furnizează un API REST pentru a furniza și primi date dinamice ale aplicației.

> Token-ul (JWT) este un cod securizat care identifică utilizatorul.

Cu JWT (JSON Web Token), API-ul REST al backend-ului permite serviciilor private să obțină contextul de autentificare, 
pentru a ști cine este utilizatorul autentificat, adică pe baza token-ului putem afla care este utilizatorul, 
token-ul în acest caz fiind JWT (JSON Web Token).

## CORS

API-ul REST poate fi într-un subdomeniu diferit de website, ceea ce implică configurații de 
[CORS (Cross-Origin Resource Sharing)](/docs/academy/server/services/cors) pentru ca serviciile să poată fi accesate.

Prin urmare, dacă API-ul REST este într-un domeniu/subdomeniu diferit de frontend, chiar și folosind JWT, este necesar
ca CORS să fie configurat corect.

> CORS este o politică de securitate pentru consumul de resurse în domenii, subdomenii sau porturi diferite.
> Pentru a garanta că o adresă poate integra cu adevărat cu altă adresă.

Acest lucru se întâmplă deoarece browserele blochează utilizarea serviciilor, sau a altor tipuri de resurse, la adrese 
externe, pentru a evita atacurile de obținere a datelor confidențiale.

## Activare și Configurare

Pentru a activa și configura JWT în aplicația dvs. din Netuno, este necesar să editați fișierul de configurare al 
aplicației corespunzător mediului pe care îl utilizați, cum ar fi:

- `config/_development.json`
- `config/_production.json`

> Depinde de mediul configurat în Netuno, în fișierul `netuno/config.js` vedeți parametrizarea `config.env`.

Introduceți și ajustați următorii parametri:

```json
    ...
    "auth": {
        "jwt": {
            "enabled": true,
            "secret": "SecretTrebuieSaAiba32Caractere!!!",
            "expires": {
                "access": 1440,
                "refresh": 1440
            }
        }
    },
    ...
```

În parametrul `secret` puneți o secvență de caractere complexă și aleatorie, este cheia care va asigura 
securitatea criptării JWT.

Parametrii `expires` sunt definiți în minute, de exemplu: `60` care echivalează cu 1 oră și `1440` cu o zi.

### Acces Restricționat la Grupuri

Suplimentar, poate fi transmis parametrul `groups`, care definește codul Grupurilor utilizatorilor care se pot 
autentifica cu JWT, de exemplu:

```json
    ...
    "auth": {
        "jwt": {
            ...
            "groups": ["client", "furnizor"],
            ...
        }
    },
    ...
```

În exemplul de mai sus, doar utilizatorii care aparțin grupurilor:

- Clienți, codul grupului fiind `client`.
- Furnizori, codul grupului fiind `furnizor`.

Doar utilizatorii din aceste grupuri se pot autentifica cu JWT.

## Fetch - JavaScript Pur

JavaScript-ul din browsere furnizează `fetch` pentru a integra cu serviciile API-ului REST al backend-ului.

Urmează câteva exemple despre cum să realizați autentificarea cu JWT și reînnoirea token-ului.

### Autentificare

Exemplu de obținere a _Access Token_-ului cu [fetch](https://developer.mozilla.org/pt-BR/docs/Web/API/Fetch_API):

```javascript
fetch("http://localhost:9000/services/_auth", {
    method: 'post',
    headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json'
    },
    body: JSON.stringify({
        username: payload.username,
        password: payload.password,
        jwt: true
    })
}).then((response) => {
	if (response.status != 200) {
        if (response.status != 403) {
            console.log('Autentificarea a eșuat cu status neașteptat:', response.status);
        }
        alert('Login invalid.');
        return null;
    }
    return response.json();
}).then((res) => {
    if (res && res.result === true) {
        console.log(`Token-ul meu de acces: ${res.access_token}`);
        console.log(`Token-ul meu de reîmprospătare: ${res.refresh_token}`);
        console.log(`Expiră în: ${res.expires_in} minute`);
        sessionStorage.setItem('token', JSON.stringify(res));
    }
}).catch((error)=> {
    console.log(error);
    alert('A apărut o problemă tehnică, încercați din nou mai târziu.');
});
```

Observați că `token` ar trebui păstrat ca sesiune, prin urmare este preferabil să utilizați [sessionStorage](https://developer.mozilla.org/pt-BR/docs/Web/API/Storage) 
în loc de [localStorage](https://developer.mozilla.org/pt-BR/docs/Web/API/Storage) pentru mai multă siguranță.

Cu `refresh_token` este posibil să generați un nou `token` înainte de timpul de expirare (`expires_in` în minute).

### Utilizarea _Access Token_-ului în alte Servicii

Pentru a executa servicii personalizate care necesită autentificare prealabilă în aplicațiile Netuno, trebuie să transmiteți 
_Access Token_-ul în Header-ul protocolului HTTP, ca valoare a cheii _Authorization_, de exemplu:

`Authorization: Bearer eyJhbGciOiJIUzU...`

Exemplu de executare a unui serviciu personalizat prin frontend folosind [fetch](https://developer.mozilla.org/pt-BR/docs/Web/API/Fetch_API), unde 
`Authorization` este transmis în `headers`:

```javascript
const token = JSON.parse(sessionStorage.getItem("token"));

fetch("http://localhost:9000/services/serviciul-meu", {
    method: 'post',
    credentials: 'include',
    headers: {
        'Authorization': `${token.token_type} ${token.access_token}`,
        'Content-Type': 'application/json'
    },
    body: JSON.stringify({
        parametrulMeu1: '...',
        parametrulMeu2: '...'
    })
}).then((response) => {
    if (response.status != 200) {
    	console.log(`Serviciul a eșuat cu statusul ${response.status}.`);
        if (response.status == 403) {
            alert('Neautentificat.');
        } else {
            alert('A apărut o eroare la serviciu.');
        }
        return null;
    }
    return response.json();
}).then((res) => {
    if (res) {
        console.log(`Datele de răspuns ale serviciului meu:`, res);
        alert('Serviciul a fost executat cu succes.');
    }
}).catch((error)=> {
    console.log(error);
    alert('A apărut o problemă tehnică, încercați din nou mai târziu.');
});
```

Observați că, în Headers-ul HTTP, în parametrul `Authorization` sunt utilizați `token_type` și `access_token` 
obținuți din obiectul JWT salvat anterior la autentificare în 
[sessionStorage](https://developer.mozilla.org/pt-BR/docs/Web/API/Storage).

### Actualizare cu _Refresh Token_

Pentru a actualiza token-ul și a prelungi autentificarea, trebuie să apelați din nou serviciul `_auth`, dar pe lângă parametrul
`jwt: true` este necesar să transmiteți și parametrul `refresh_token` cu valoarea primită în autentificarea reușită 
anterior.

Actualizarea token-ului trebuie făcută înainte de timpul de expirare (`expires_in` în minute).

Deci, pentru a prelungi autentificarea și a reînnoi token-ul, vedeți exemplul:

```javascript
const token = JSON.parse(sessionStorage.getItem("token"));

fetch("http://localhost:9000/services/_auth", {
    method: 'post',
    headers: {
        'Content-Type': 'application/json',
        'Accept': 'application/json'
    },
    body: JSON.stringify({
        refresh_token: token.refresh_token,
        jwt: true
    })
}).then((response) => {
    if (response.status != 200) {
        if (response.status != 403) {
            console.log('Reînnoirea token-ului a eșuat cu status neașteptat:', response.status);
        }
        alert('Reînnoirea accesului cu token invalid.');
        return null;
    }
    return response.json();
}).then((res) => {
    if (res && res.result === true) {
        console.log(`Noul meu Token de Acces: ${res.access_token}`);
        console.log(`Noul meu Refresh Token: ${res.refresh_token}`);
        console.log(`Expiră în: ${res.expires_in} minute`);
        sessionStorage.setItem("token", JSON.stringify(res));
    }
}).catch((error)=> {
    console.log(error);
    alert('A apărut o problemă tehnică, încercați din nou mai târziu.');
});
```

La obținerea unui token nou, trebuie să începeți să îl utilizați, în locul celui anterior (vechi) în următoarele apeluri către servicii.

În acest mod, autentificarea este prelungită prin reînnoiri succesive ale token-ului, este o modalitate de a garanta că utilizatorul
rămâne autentificat.

## Auth Client - NPM

Pentru a realiza cu ușurință integrarea cu frontend-ul, este disponibil modulul NPM:

- [@netuno/auth-client](https://www.npmjs.com/package/@netuno/auth-client)

În frontend puteți realiza instalarea cu [Bun](https://bun.sh):

- `bun install @netuno/auth-client`

> Poate fi utilizat un alt manager de dependențe de frontend precum PNPM, NPM, YARN sau altul.

### Configurare

Acest modul depinde de [@netuno/service-client](https://www.npmjs.com/package/@netuno/service-client), la definirea 
adresei serviciilor, de exemplu:

```javascript
import _service from '@netuno/service-client';
...
_service.config({
    prefix: 'http://localhost:9000/services/'
});
```

`auth-client` utilizează prefixul din `service-client` pentru a construi intern adresa serviciului `_auth`, 
în acest caz, urmând exemplul va fi:

- `http://localhost:9000/services/_auth`

Deci această adresă este construită automat utilizând prefixul de adresă al serviciilor API-ului REST 
al aplicației Netuno.

Vedeți cum să personalizați configurațiile `auth-client`:

În versiunea ES module, `config()` este asincron. Așteptați finalizarea sa înainte de a utiliza clientul configurat:

```javascript
import _auth from '@netuno/auth-client';

await _auth.config({
    storage: 'local', // session este valoarea implicită.
    onLogin: () => { alert("Autentificat!"); },
    onLogout: () => { alert("Deconectat!"); }
});
```

Dacă doriți ca token-ul să fie salvat în `localStorage`, atunci este necesar să definiți în configurare 
`storage: 'local'`, deoarece implicit este `storage: 'session'` utilizând `sessionStorage`.

### Autentificare

Pentru a efectua login-ul utilizând `_auth`:

```javascript
import _auth from '@netuno/auth-client';
...
_auth.login({
    username: "admin",
    password: "secret",
    success: ()=> {
        alert("Succes.");
    },
    fail: ()=> {
        alert("Eșec.");
    }
});
```

Token-ul este salvat automat, în `session` (`sessionStorage`) sau `local` (`localStorage`), în funcție de 
configurare, implicit este `session`.

### Actualizarea Token-ului

Exemplu de actualizare a token-ului:

```javascript
import _auth from '@netuno/auth-client';
...
_auth.refreshToken({
    success: ()=> {
        alert("Succes.");
    },
    fail: ()=> {
        alert("Eșec.");
    }
});
```

Token-ul este salvat automat, în `session` (`sessionStorage`) sau `local` (`localStorage`), în funcție de
configurare, implicit este `session`.

### Eliminarea Token-ului

Exemplu de încheiere a sesiunii, adică procesul de deconectare și eliminare a token-ului:

```javascript
import _auth from '@netuno/auth-client';
...
_auth.logout();
```

Token-ul este eliminat din `sessionStorage` sau `localStorage` în funcție de configurare, implicit este 
`sessionStorage`.

## Backend - Servicii ale API-ului REST

Dacă header-ul `Authorization` este transmis în integrarea cu serviciile cu un token valid, atunci este posibil 
să identificați care este utilizatorul și grupul.

În backend putem utiliza resursa `_user` și `_group`, care identifică care este utilizatorul și grupul 
respectiv.

Pentru a vedea datele utilizatorului autentificat, utilizăm resursa [User](/docs/library/resources/user), de exemplu:

            `
        },
    ]}
/>

### Securitate

Dacă token-ul este invalid sau dacă nu este transmis `Authorization`, atunci Netuno garantează că serviciul nu
este executat, cu excepția cazului în care serviciul este configurat ca acces public, implicit serviciile sunt private.

> Pentru a gestiona dacă serviciul este public sau privat, configurați în aplicația dvs. în: `server/core/_service_config.js`

Întrucât în dezvoltare Netuno permite executarea serviciilor private direct, fără autentificare, din
motive de practicitate, deoarece majoritatea serviciilor programate nu au nevoie în mod normal de contextul de 
autentificare, astfel devine mai simplu în general dezvoltarea și testarea.

Dacă nu este în dezvoltare, de exemplu în producție, atunci serviciile pot fi executate doar cu
autentificare, cum este evident.

### Resursa de Autentificare

În mod normal, resursa `_user` și `_group` sunt suficiente, dar există situații în care dorim să realizăm operații mai 
avansate și în acest caz avem resursa `_auth`.

Resursa `_auth` este resursa principală de autentificare, gestionează configurațiile și are toate operațiile 
legate de procesul de autentificare.

> Pentru a afla mai multe, vedeți documentația resursei [Auth](/docs/library/resources/auth).

## Concluzie

Într-un mod simplu, este posibil să configurați și să activați autentificarea cu JWT (JSON Web Token) în aplicații.

> Utilizați autentificarea cu JWT pentru a dezvolta servicii sigure în API-ul REST.

Integrarea JWT în frontend poate fi realizată direct cu `fetch`.

Pentru a agiliza și standardiza implementarea, este disponibil modulul NPM [@netuno/auth-client](https://www.npmjs.com/package/@netuno/auth-client), care poate fi
utilizat cu orice tehnologie de frontend.

Întotdeauna când este necesar să identificați utilizatorul în execuția serviciilor API-ului REST, utilizați autentificarea cu JWT.

În backend, configurarea și obținerea utilizatorului autentificat sunt foarte simple.
