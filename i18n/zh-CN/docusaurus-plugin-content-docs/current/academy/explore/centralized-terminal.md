Netuno 可以将多个命令和进程的数据输出（日志）统一汇集到同一个终端窗口中——也就是主服务器正在运行的那个窗口。

在现代开发流程中，同时处理多种技术是常见的情况，Netuno 在此充当日志编排器，可以配置多个命令并行自动启动，例如 ReactJS、Angular、Vue 以及任何其他前端进程。

> 任何进程都可以启动，只需定义它的命令即可，例如甚至可以集成由任何其他技术开发的辅助 REST API 服务器。

## 配置

要集成外部进程，你需要编辑应用程序的环境配置文件。在本指南中，我们将以开发环境为例。

### 文件位置

进入你的应用程序文件夹并找到该文件：

- 📂 `config/_development.json`

### 配置结构

配置通过 `"commands"` 键完成，它是一个对象数组。这样你就可以并行运行多个服务。

打开文件并检查 `"commands"` 键是否已存在。如果不存在，请按照以下配置将其添加到文件末尾（遵守 JSON 格式）：

```json
{
    ...
    "commands": [
        {
            "path": "ui",
            "command": "bun run watch",
            "enabled": true
        },
        {
            "env": [ "PORT=21030", "WDS_SOCKET_PORT=21030" ],
            "path": "website",
            "install": "bun install",
            "command": "bun run dev",
            "enabled": true
        }
    ],
    ...
}
```

> **注意：** 在上面的示例中，我们为 "ui" 文件夹配置了一个命令，为 "website" 文件夹配置了另一个命令，二者都使用 bun 包管理器。

### 参数参考

**用户界面（UI）：** 在应用程序的 `ui` 目录中执行 `bun run watch`。

**网站：** 在 `website` 文件夹中执行 `bun run dev`。

### env

定义进程运行所需的环境变量。你可以同时定义多个变量。

### path

定义命令执行所在的文件夹路径，相对于应用程序根目录。

### install

Netuno 内置了管理包依赖的智能机制：

- **自动检测：** 如果你的命令以 `npm`、`bun`、`pnpm` 或 `yarn` 开头，Netuno 会检查 `node_modules` 文件夹是否存在。

- **智能执行：** 如果未找到该文件夹，则会在启动主进程之前自动执行相应的安装命令（例如 `bun install`）。

- **自定义：** 手动定义 `install` 参数后，默认检测将被你的自定义配置所替代。

### command

要执行的主命令。所有数据输出（`output`）都将集成到 Netuno 中。

### enabled

定义该命令是否（true）随应用程序自动启动，或者不启动（false）。

## 结论

在 Netuno 中集中管理命令可以极大地简化工作流程。
统一的可见性使所有并行进程的信息汇聚到一个终端中，便于实时监控。

安全关闭意味着，当停止 Netuno 服务器的运行时，所有已配置的辅助进程也会自动终止，从而避免出现"后台"进程或端口被占用的问题。
