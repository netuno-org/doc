在 Web 和/或移动应用开发中，后台管理（backoffice）这一概念很常见，它是数据管理层。

也就是说，这通常是一个 Web 层，业务管理人员会进入一个界面，在其中对数据进行操作。

以下需求非常常见：

- 用户管理；
- 用户组管理；
- 按照业务规则操作数据库记录；
- 记录用户做了什么以及何时做的日志；
- 限制访问权限，根据用户组或用户的不同，可能无法修改甚至查看某些数据；
- 允许通过浏览器和移动设备访问；
- 生成管理报表；
- 根据业务定制的仪表盘，展示相关信息，并可呈现图表和表格；

由于这些以及其他原因，开发后台管理往往和开发最终应用一样费时，甚至更费时。

此外，后台管理通常还提供带 Web 服务的 REST API，用于实现业务数据与最终应用（即前端）之间的通信。

![后台管理。](/docs/assets/business/business-backoffice.svg "后台管理。")

Netuno 提供了强大的后台管理引擎，无需编写代码即可创建数据结构，并生成与数据库集成的表单，用于最常见的操作，如创建、搜索、编辑和删除。

它还提供用户和用户组管理，以及带日志记录的访问控制。

它允许以低代码方式创建仪表盘、报表，以及集成了 JWT（JSON Web Token）的 REST API（Web 服务）。

> 由于 Netuno 已提供所有最常见功能，并可按业务模型进行调整，因此定制开发后台管理所需的工作量会大幅降低。

## 新项目的后台管理

在开发新项目时，尤其是面向外部客户的应用，通常会压低后台管理的预算，也就是说，会减少投入在其开发和界面构思上的时间。

这是因为目标客户看不到它，所以可以将其放到次要位置。

此外，决策者的目标更多在于达成最终结果，而不是内部管理层面，尤其是在涉及较高成本时。

但在开发过程中，尤其是在测试阶段，拥有后台管理界面可以更好地验证数据的一致性。

由于 Netuno 简化了**数据模型的构建，并自动在 Web 界面中提供用于数据管理的响应式表单**，只需在数据建模阶段使用 Netuno，就能自动获得后台管理界面。非常简单！

之后，你可以选择进一步发展到用 Netuno 开发仪表盘、报表和 Web 服务。

或者，由于某些限制或强制要求，你可以使用任何其他技术开发 Web 服务和整个 REST API，只需消费 Netuno 生成的数据库即可。

无论如何，你都可以将 Netuno 作为满足后台管理需求的选项。

## 现有应用的后台管理

对于已经存在、但尚未开发后台管理，或者即使已有后台管理却存在限制的应用。

Netuno 既可用于扩展现有后台管理，也可用于补齐缺失的后台管理。

由于使用 Netuno 创建后台管理的工作量非常小，因此既可以完全用 Netuno 做一个完整的后台管理，也可以只做其中几个模块。

采用哪些技术方案由个人决定，也取决于其想象力；有一点可以肯定，不必把事情搞得太复杂，可以把后台管理设想为模块化，并随着时间推移按需逐步开发和扩展。

通常以模块方式开发非常复杂，但 Netuno 也简化了这一过程，允许在同一数据库上开发多个应用，因此它也是一个出色的解决方案：可以开发独立的辅助模块来扩展现有后台管理，而不会对现有后台管理造成影响。

由于 Netuno 可以轻松集成并管理同一应用中的多个数据库，因此可以方便地在另一个数据库中导入和导出信息。

这样一来，就可以更好地将后台管理的复杂度与 Netuno 应用（它们相当于现有后台管理的附加“模块”）的复杂度分离开来。

## 结论

毫无疑问，Netuno 的主要目标之一就是尽可能简化后台管理的开发，并实现与现有项目和新项目的集成，在新项目中还能与其他技术良好集成。

Netuno 并不是一个封闭的平台，并不要求所有开发都必须转到 Netuno 上进行；恰恰相反，Netuno 可以仅用于满足特定需求，以突破以下方面的限制：

- 成本
- 时间

它允许与任何其他技术集成。

因此，如果问题在于资金不足或交付日期过于紧张，并且还存在大量复杂性和多种集成技术，那么应将 Netuno 视为又一种能够解决成本和时间问题、让工作更轻松的技术。
