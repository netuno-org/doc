在任何类型的业务中，通常都会存在那些 Excel 文件，或 Google Spreadsheets、LibreOffice、OpenOffice 等任何其他类型的电子表格……它们因能以简单的方式满足信息组织、分析乃至与其他电子表格集成的需求而被广泛使用。

因此，当信息结构相对较小且复杂度不高时，Excel 及其同类工具能够很好地解决问题。

随着时间推移，趋势往往是不断增长，产生越来越多信息分散的文件。

![Excel 文件图片](/docs/assets/business/excel-danger.jpg "Excel 文件。")

问题在于，当那个 Excel 文件连同另外一些文件变成一头怪物时，管理就会变得困难，更糟的是当涉及多人时，就会开始产生各种问题，使信息变得越来越脆弱，直至完全难以维持。

这时就需要创建一个更健壮的应用程序，能够管理用户配置文件、用户组，通过验证并以更好的结构管理数据，将数据导出为带有图表和表格的复杂报告，执行更复杂的搜索，与其他系统集成，以及更多功能。

> 主要困境在于 Excel 相对便宜，而开发一个管理应用程序又太贵。

借助 Netuno，我们可以**以较低的投入**快速创建一个应用程序来管理所有信息，从而彻底取代那些分散且难以管理的 Excel 文件。

## 电子表格与数据库表

不要以为数据库非常复杂，您会发现并非如此，甚至它与 Excel 电子表格非常相似。

> 数据库表就相当于一张电子表格。

例如，分析您在 Excel 中的电子表格：

|   	|    A    	|      B     	|       C       	|      D      	|
|:-:	|:-------:	|:----------:	|:-------------:	|:-----------:	|
| **1** 	| 产品 	| 数量 	| 单价 	| 总价 	|
| **2** 	|  叉子  	|     10     	|      3.00     	|    30.00    	|
| **3** 	|   杯子  	|      5     	|      4.00     	|    20.00    	|
| **4** 	|   刀  	|      8     	|      2.00     	|    16.00    	|
| **5** 	|         	|            	|  **总价**  	|    **66.00**    	|

要将这些信息存储到数据库中，需要创建一张表来存储**产品**信息。

该表将按如下示例进行结构化，并包含以下数据：

因此，每当使用某个产品的数据时，这些数据都必须来自这张表。

也就是说，就好像您有一张保存产品信息的电子表格。

每一行包含一个 ID，即唯一标识符，例如一个顺序编号。
